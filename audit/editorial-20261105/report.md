- 原理页更明确地给出设计动机、适用假设、概率/资源账本与反例；不把参数比例、复杂度阶数或论文速度套成部署收益。

- 沿用确认的 Atlas 深色入口与浅色阅读体系：46rem 长文宽度、正文 1rem/1.95、清晰标题与元信息、原生折叠自测、局部表格/代码/数学滚动。没有增加付费图片、字体或后端依赖。

## 两轮交叉审查的修正

| 发现的问题 | 本轮修正 |
| --- | --- |
| 用户开口确认会使自己的审批失效 | 媒体 epoch 与动作审批版本分离，预期确认不等于取消 |
| MoE 所有专家必须常驻 GPU | 说明存储与卸载路线，计入传输/调度代价 |
| 低代码高危链路一律迁代码 | 以恢复、核权、审批和幂等能力决定迁移，迁移不自动安全 |
| 最大已观察 fence 等于即时撤权 | 补 18/19 传播缺口、写入端事务或激活屏障及在途效果限制 |
| 先查副作用再撤销旧写权 | 先关闭写准入、记录在途未知，再对账与回收 |
| 只拒绝任务回执就回收工作目录 | 对全部活跃文件写者隔离/终止确认，新 attempt 不复用旧目录 |
| JSON 前缀可解析就执行工具 | 等待供应商完整调用边界、冻结完整参数摘要再审批/执行 |

审查是静态协议反例检查，不是已部署系统的恢复/安全证明；并未因此把文章改为人工 reviewed。
