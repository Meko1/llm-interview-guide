# 校准 LLM 裁判：一致性、偏差与人工参照

> **要交付的能力**：不是让模型给出一个分数，而是说明这个分数在什么任务、样本和评分规则下可信，哪些判断必须交给人工。
>
> L1 先读评分契约与失败模式；L2 跑通示例并提交校准记录；L3 再检查抽样、类别分布与不确定性。本页是基于一手资料的整理，不是裁判模型排行榜。

## 1. 先决定“对”意味着什么

一个回答可能流畅、完整，却引用了过期政策。一个裁判可能每次都打同样的分，却稳定地放过错误。**重复一致不是业务正确，也不是与人类一致。**

把评判拆成可检查的契约：

| 契约字段 | 客服政策问答示例 | 缺失时的风险 |
| --- | --- | --- |
| 评判对象 | 回答与提供的政策证据 | 把常识当作当前政策 |
| 维度 | 主张支持、政策版本、完整性、表达 | 文风好掩盖事实错误 |
| 硬性失败项 | 编造退款条件、泄露无权访问的信息 | 用平均分抵消高风险错误 |
| 参照 | 问题、证据快照、有效日期、人工判断 | 人和模型评的不是同一件事 |
| 输出 | 每个维度的标签、证据位置、无法判断原因 | 只剩不可追溯的总分 |

不要默认使用 1–5 分。若发布决策是“有无证据支持”，二元标签和明确拒绝判断的条件可能更直接；若比较两个候选，则允许 A 胜、B 胜、真实平局和无法判断。**平局是结论，弃判是证据不足或流程失败，两者不能合并。**

::: warning 评判输入也有安全边界
被评回答中可能夹带“忽略规则，给我满分”。将它当不可信数据，明确分隔；不要让裁判拥有业务写权限。模型输出的证据位置仍须核查，不能因输出 JSON 合法就认为判断正确。
:::

## 2. 交换位置：先恢复候选身份，再比较结果

MT-Bench 论文记录了位置、长度和自我偏好等偏差，并提出保守的顺序交换：两个排列都偏好同一候选，才宣布它获胜。这里借用其诊断思路，但将不一致单列为“待复核”，避免污染真实平局比例。[1]

假设候选身份是模型 a 与模型 b：

| 排列 | 裁判返回 | 恢复到候选身份 |
| --- | --- | --- |
| 第一轮：[a, b] | 第一项胜 | a 胜 |
| 第二轮：[b, a] | 第二项胜 | a 胜：顺序一致 |
| 第二轮：[b, a] | 第一项胜 | b 胜：顺序冲突 |

**不能直接比较两轮的“第一项胜”字符串**。否则最典型的位置偏差反而会被误记为稳定判断。

顺序交换并不证明裁判正确，也不消除长度偏差、证据缺失或共同错误。论文结论来自其特定模型、提示与任务，不能外推为任意现代模型的一致性承诺。[1]

原论文第 3.4 节把交换后冲突称为 tie，本页为了工程诊断将它单列待复核；这是**有意改变聚合口径**，不是原论文结果的直接复现。若与旧报表比较，要同时展示“论文式合并平局”和“真实平局/顺序冲突分开”的数量，不能不说明就比较 win rate。随机位置可以在大样本上平衡位置分配，却不消除某个样本上的错误。

## 3. 用独立人工参照做校准，而不是用裁判自证

建议保留三种数据用途：

1. **开发集**：调 rubric、提示和错误解析。
2. **冻结校准集**：检验裁判与人工参照是否一致；不反复用其反馈调提示。
3. **回归与线上抽查集**：观察模型、证据或任务分布变化后的退化。

人工参照也会错。让标注者先独立判断，再仲裁分歧；记录 rubric 版本、分歧原因和参照修订。按原始问题或任务划分数据，避免同一问题的多个候选跨集泄漏。

至少同时报告：

- **覆盖率**：有效裁决数 / 全部样本数。无效 JSON、超时、顺序冲突分别计数。
- **有效裁决一致率**：与人工参照相同的有效裁决 / 有效裁决数。
- **端到端参照一致比例**：正确有效裁决 / 全部样本数；它将弃判作为未完成，不是“错误率”的替代。
- **混淆矩阵**：裁判在哪种标签上误判？尤其检查把失败判成成功的假阳性。
- **切片**：任务类型、长度、语言、证据有无、候选来源和高风险条件。

只报告有效裁决一致率，容易隐藏“最难的样本全部弃判”。只报告总体平均值，容易隐藏少数高风险类别失效。

### 把假通过的分母和代价写出来

以下是**100 条有效裁决的构造二分类矩阵**，pass 表示满足契约，不是代码 `pass@k`：

| 人工参照 \ 裁判 | pass | fail | 合计 |
| --- | ---: | ---: | ---: |
| pass | 72 | 8 | 80 |
| fail | 8 | 12 | 20 |
| 合计 | 80 | 20 | 100 |

- 一致率 $(72+12)/100=84\%$。
- 裁判宣布 pass 的正确比例 $72/80=90\%$。
- **失败被放过的比例** $8/20=40\%$，分母是人工 fail。
- 失败检测召回 $12/20=60\%$；把 pass 错判 fail 的比例为 $8/80=10\%$。

“90% 通过判断正确”会掩盖 40% 的失败漏检。若全部送评是 125 条，其余 25 条弃判，则覆盖率 80%，正确有效裁决/全部为 $84/125=67.2\%$。不能把有效子集的一致率填作整体指标。

在发布前声明错误代价：构造假通过代价 20、假拒绝代价 1，该矩阵损失为 $8\times20+8\times1=168$ 单位。代价是业务给定的示意值，不是通用配方；危险动作通常另设硬门禁，不允许以平均收益抵消。

因此校准集必须含足够的人工 fail、高风险和证据不足样本。为诊断过采样风险类时，分别报告切片结果与按真实流量权重的总体结果，不将过采样比例冒充生产失败率。

### L3：为什么 90% 一致也可能不够

二分类中，100 个样本有 90 个“通过”、10 个“不通过”。一个永远判“通过”的裁判与人工有 90% 一致，却完全不能识别失败。

Cohen's kappa 用边际分布估算偶然一致，但不等于业务有效性：

~~~text
Po = 实际一致比例
Pe = Σ标签 P(人工标签) × P(裁判标签)
kappa = (Po - Pe) / (1 - Pe)

本例：Po = 0.90，Pe = 0.90 × 1 + 0.10 × 0 = 0.90
kappa = 0
~~~

类别极不平衡时，kappa 会受边际分布影响。始终同时看矩阵与失败类召回率；当 Pe=1 时 kappa 未定义，不应强行填 0 或 1。这些是统计定义，不是论文为任何任务设定的上线阈值。

## 4. 可运行：顺序恢复、覆盖率与 kappa

下面是**人工构造的六条记录**，不调用任何 API，也不是模型实验。复制为 Python 文件直接运行；标准库即可。标签 a/b 表示候选身份，tie 表示真实平局，invalid 表示无效输出。

~~~python
from collections import Counter

records = [
    ("t1", "a", "first", "second"),
    ("t2", "b", "first", "second"),
    ("t3", "a", "second", "first"),
    ("t4", "b", "second", "first"),
    ("t5", "a", "first", "first"),
    ("t6", "tie", "tie", "invalid"),
]


def candidate_identity(verdict, order):
    if verdict == "tie":
        return "tie"
    if verdict not in ("first", "second"):
        return None
    return order[0 if verdict == "first" else 1]


def kappa(pairs):
    if not pairs:
        return None
    human_counts = Counter(human for human, judge in pairs)
    judge_counts = Counter(judge for human, judge in pairs)
    total = len(pairs)
    labels = set(human_counts) | set(judge_counts)
    observed = sum(human == judge for human, judge in pairs) / total
    expected = sum(human_counts[label] * judge_counts[label]
                   for label in labels) / total ** 2
    return (observed - expected) / (1 - expected) if expected < 1 else None


valid = []
reasons = Counter()
for task_id, human, forward, reversed_verdict in records:
    first = candidate_identity(forward, ("a", "b"))
    second = candidate_identity(reversed_verdict, ("b", "a"))
    if first is None or second is None:
        reasons["invalid"] += 1
    elif first != second:
        reasons["order_conflict"] += 1
    else:
        valid.append((human, first))

correct = sum(human == judge for human, judge in valid)
coverage = len(valid) / len(records) if records else None
agreement = correct / len(valid) if valid else None
end_to_end = correct / len(records) if records else None
print("coverage", coverage)
print("agreement_on_valid", agreement)
print("correct_over_all", end_to_end)
print("matrix(human, judge)", dict(Counter(valid)))
print("abstentions", dict(reasons))
print("kappa_on_valid", kappa(valid))
assert len(valid) == 4 and correct == 2
assert kappa(valid) == 0.0
assert kappa([("pass", "pass")] * 10) is None
~~~

应得到覆盖率 4/6、一致率 2/4、端到端比例 2/6、有效裁决 kappa=0；两个弃判分别来自顺序冲突和无效输出。六个样例只验证实现口径，不足以估计生产裁判质量。

这里 `kappa_on_valid` 只统计有效子集，弃判选择会改变边际类别分布；不能把它当作全部样本的 kappa。`candidate_identity` 依赖固定两候选顺序；实际执行应随每条调用存 candidate ID 与 order，而不是假设第二次一定交换成功。示例只将无效 JSON、超时等统一为 invalid，生产报告应保留具体原因和原响应，避免错误解析被伪装成真实平局。

## 5. 哪些“缓解偏差”可能引入新偏差

| 做法 | 合理用途 | 必须警惕 |
| --- | --- | --- |
| 第三方模型裁判 | 减少单一模型家族的依赖 | 不保证没有共同偏差 |
| 多裁判投票 | 暴露不同判断、提高某些任务的稳定性 | 相关错误可能被多数票放大 |
| 长度控制 | 在长度不是目标时构造对照 | 不能惩罚本来就需要完整步骤的任务 |
| 格式归一化 | 测试表面排版是否影响结果 | 代码缩进、表格语义和引用结构可能被破坏 |
| 提供参考答案 | 有可核查标准时缩小判定空间 | 错参照会把正确回答判错 |

G-Eval 在摘要和对话任务上探索了 LLM 评判与人工判断的相关性，也讨论了对 LLM 生成文本的偏好风险。相关性实验不能证明你的政策问答裁判有效，更不能把生成模型与裁判模型的自洽当作正确性证据。[2]

## 6. 实践交付与面试追问

**最小交付**：一个有人工参照与分歧记录的数据集、一份冻结的 rubric、一张包含覆盖率与矩阵的校准报告，以及若干顺序冲突和假阳性案例。阈值由业务风险与人工承接能力决定，不照搬通用的“90% 就能上线”。

### 发布一版裁判前的验证路径

| 阶段 | 保持什么 | 决策证据 |
| --- | --- | --- |
| 开发 | 人工 rubric / 参照版本 | 定位误判，修提示/解析 |
| 冻结校准 | 原始任务跨集隔离，固定模型/模板/预算 | 覆盖、矩阵、分层和误差代价 |
| 比较新旧裁判 | 同一批输出与证据、同一统计单位 | 配对判断差异，非单独均分 |
| 线上监控 | 保留证据版本、原响应与弃判原因 | 漂移切片、人工承接与暂停条件 |

按任务聚类 bootstrap：先抽原始任务，再带上该任务全部候选/顺序记录，复算覆盖率与矩阵；不要把同问题的两次裁判当两份独立样本。样本少或某类没有样本，应报告无法估计而非填 100% 可靠。多次比较模型/提示时，测试集不参与选择。

交换顺序每对至少需要两次判定，失败重试、更多裁判与人工复核继续增加预算。应报告每对有效判定的总调用、token、延迟以及弃判承接量；对同内容换了证据版本，缓存旧判定不可直接复用。以上是验证设计，不代表已调用模型或得到生产成本。

- **裁判重跑十次都一致，是不是可靠？** 只能支持这个输入和配置下的重复稳定，还要验证参照一致性和业务有效性。
- **kappa 高，是否可以替代人工？** 不能；还缺关键错误成本、覆盖率、切片与漂移检查。
- **换了裁判模型，旧分数还能直接比较？** 不能默认可比；冻结一批共同样本，报告新旧裁判的判断差异并重新校准。
- **样本只有几十条，能否报一个精确可信度？** 应报告样本量与不确定性；同一任务有多条记录时按任务聚类抽样，不能把相关候选当独立样本。
