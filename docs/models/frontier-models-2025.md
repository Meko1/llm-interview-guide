# 2025-2026 前沿模型盘点

这里保留原标题和 URL，但内容是**2024–2025 若干公开报告与发布的学习快照**，不是截至 2026 年 11 月 5 日的最新型号、排名或购买建议。面试回答“前沿是什么”时，更有价值的是说清版本、贡献、成本和证据缺口。

阅读约定：技术报告支持其披露的训练与架构；发布公告支持当时的产品声明；未成功读取的材料只作入口，不用于补参数或训练细节。相关基础见 [经典模型](/models/classic-models)、[LLaMA/Qwen](/models/llama-qwen)、[DeepSeek](/models/deepseek)。

## 一、OpenAI：GPT-5 系列

[GPT-5 官方发布页](https://openai.com/index/introducing-gpt-5/) 本轮读取返回 HTTP 403，故仅链接待核。原文中的“所有模态一起预训练”“单个模型自行路由快慢思考”“Codex 必然基于某个底座”等说法不在这里作为已确认架构事实保留。

准备此系列时应分开核查：

- ChatGPT 产品是否由多个组件组成，与 API 模型 ID 是否相同。
- 哪些接口支持图像/音频输入、哪些支持相应输出。
- 推理预算、工具调用与路由是接口控制、产品编排还是已披露的内部机制。
- Codex 产品、编程专用 checkpoint 与基础模型之间是什么已公开关系。

**不要从“能使用工具”反推训练数据、隐藏思维链或内部模型结构。** 未读取原文时，可以讲核查问题，不应猜出答案。

## 二、Anthropic：Claude 4 系列

依据 [Introducing Claude 4（2025 发布公告）](https://www.anthropic.com/news/claude-4)，Opus 4 与 Sonnet 4 发布时支持扩展思考，并提供扩展思考与工具使用交替进行的 beta 能力。这是该次公告的产品描述，不是“所有 Claude 都有同一模式”。

工具调用、并行工具、文件访问和外部持久化记忆都需要开发者提供环境与权限。Claude Code 的多文件修改或运行测试，是模型与工具编排共同产生的系统行为；不能把一次成功演示当作长程 Agent 的可靠性证明。本文不保留无条件“最强编码”或统一上下文数字。

MCP 解决工具连接协议，不会自动处理授权、幂等、事务、提示注入或危险操作确认。

## 三、Google：Gemini 2.5 系列

[2025 年 3 月 Gemini 2.5 发布公告](https://blog.google/technology/google-deepmind/gemini-model-thinking-updates-march-2025/) 介绍的是 **2.5 Pro Experimental**：思考模型、当时公布的一百万 token 窗口，以及文本、音频、图像、视频理解能力。

这些属于公告时点，不自动覆盖后续 Pro/Flash、Deep Think 或实时/生成 API。尤其要区分**理解音视频输入**与**生成图像/语音输出**；原文把系列能力合并成“全模态输出”的表述已移除。

长窗口能容纳信息，不代表每个位置都能可靠取回证据。需要在实际代码库或文档上测中间位置、跨文件依赖、引用准确性和输入成本，见 [长上下文](/basics/long-context)。

## 四、Meta：Llama 4 系列

[Llama 4 官方发布入口](https://ai.meta.com/blog/llama-4-multimodal-intelligence/) 与 [Scout 官方模型卡](https://huggingface.co/meta-llama/Llama-4-Scout-17B-16E-Instruct) 本轮未成功读取，保留为待核导航。Scout、Maverick、Behemoth 的具体发布状态、参数、窗口、视觉能力和许可应逐项查看；原文的数值与“最长”“单卡运行”结论已删除。

可以先明确一条不依赖型号的成本原则：**MoE 的激活参数不是全部权重显存，也不是端到端延迟预测器。** 必须核对总权重、量化、共享层、专家分布、KV Cache 和通信。即使某个量化 checkpoint 能装入单卡，也不表示长上下文和目标并发可用。

## 五、阿里：Qwen3 系列

[Qwen3 报告 v1（2025）](https://arxiv.org/html/2505.09388v1) 介绍初版稠密与 MoE 模型、36T token 的预训练数据，以及包含 119 种语言和方言的语料覆盖。语料覆盖不等于每种语言同等能力。

初版代表包括 Qwen3-235B-A22B、Qwen3-30B-A3B；名称中 A 指示激活参数量级，不能作为显存需求。初版后训练支持思考/非思考模式，开关要看 chat template 和服务封装。

**版本差异很重要**：[官方仓库](https://github.com/QwenLM/Qwen3) 区分初版与 2507 的 Instruct/Thinking 版本；其示例明确 Instruct-2507 仅非思考，不能机械沿用“所有 Qwen3 都通过 `enable_thinking` 切换”的说法。当前仓库是可变文档，部署时仍须锁定 checkpoint revision 与对应模板。

## 六、DeepSeek：R1 与 V3

依据 [V3 v1](https://arxiv.org/html/2412.19437v1) 和 [R1 v1](https://arxiv.org/html/2501.12948v1)：

| 版本 | 公开机制 | 不应混淆 |
| --- | --- | --- |
| V3 / V3-Base | MLA、MoE、FP8、MTP；基础与后训练模型需区分 | 正式训练成本不是全部研发成本 |
| R1-Zero | 从已预训练底座开始，无前置 SFT 的 RL 实验 | 不是从随机权重只用 RL |
| R1 | 冷启动 SFT、推理 RL、拒绝采样 SFT、多场景 RL | 正式 R1 不是纯 RL 流程 |
| R1-0528 | 作为后续版本入口 | 不用 v1 论文代替升级版技术核验 |

R1 报告中的推理成绩支持相应评测协议，不证明通用业务已追平所有闭源模型。具体公式、成本账本和失败边界见 [DeepSeek 专题](/models/deepseek)。

## 八、2025-2026 模型趋势总结

| 讨论方向 | 本文可用证据 | 应当落地的取舍 |
| --- | --- | --- |
| 推理预算与模式 | Qwen3 初版、Claude 4 公告 | 更长输出的质量增益 vs 延迟、token 成本 |
| 开放 MoE | V3、Qwen3 报告 | 激活计算 vs 常驻权重、路由通信 |
| 长上下文 | Gemini 2.5 当时公告 | 名义容量 vs 检索准确性、prefill 与 KV 成本 |
| 多模态 | 产品输入声明与公开 VLM 报告 | 模态、分辨率、证据定位与接口边界 |
| Agent 系统 | 工具使用公告 | 成功率、权限、状态管理与不可逆动作 |

这些是有证据的设计方向，不是“所有模型全面转向某路线”或“开源领先/落后半年”的市场结论。
