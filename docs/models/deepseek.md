# DeepSeek 专题（MLA / GRPO / R1）

读 DeepSeek 的价值在于理解**算法、训练系统与推理系统怎样协同**，而不是记住“便宜又强”。本文限定 [DeepSeek-V3 报告 v1（2024）](https://arxiv.org/html/2412.19437v1) 与 [DeepSeek-R1 报告 v1（2025）](https://arxiv.org/html/2501.12948v1)；不把结论自动迁移到 R1-0528 或后续 API。

## 为什么 DeepSeek 值得单独讲？

| 学习主线 | 报告中的机制 | 需要追问的边界 |
| --- | --- | --- |
| KV 显存 | MLA 缓存压缩表示与位置分支 | 当前服务栈是否支持对应算子 |
| 容量与训练 | MoE、FP8、DualPipe、MTP | 权重显存、路由通信、精度与调度 |
| 推理后训练 | GRPO、R1-Zero、R1、蒸馏 | 奖励可靠性、采样开销与任务分布 |

V3 报告给出总参数 671B、每 token 激活约 37B。前者关系到权重存储，后者主要刻画部分计算量；37B 激活不等于单卡只需容纳 37B 权重。

## MLA：多头潜在注意力

MHA 缓存每层历史 token 的 K/V。固定精度与 batch 时，缓存随序列长度、KV 头数和头维度线性增长。GQA 通过多个查询头共享 KV 头缩减缓存；MLA 则联合压缩内容 K/V，并保留独立位置分支。

简化内容分支：

$$
c_t^{KV}=W^{DKV}h_t,\qquad
k_t^C=W^{UK}c_t^{KV},\qquad
v_t^C=W^{UV}c_t^{KV}.
$$

部署时不必每步显式重建全部内容 K/V：可把 $W^{UK}$ 吸收到查询侧计算，把 $W^{UV}$ 与输出映射合并。RoPE 依赖位置，其旋转不能随意跨过投影矩阵；报告因此采用解耦的 RoPE key 分支。

按 V3 报告配置，缓存包含 512 维 KV latent 与 64 维位置 key。**仅算单层、单 token、BF16 缓存有效元素**，大小为 $(512+64)\times2=1152$ 字节；不含 batch、层数、分页、对齐和运行时开销。与 GQA 的比较要给出它的 KV 头数和头维度，不能直接说“小一个量级”。

MLA 和 GQA 都是经过训练的参数化设计，不是任意已训练 MHA 的无损压缩。报告消融中的质量结果只支持对应模型与任务，不能宣称 MLA “近乎无损且必然更好”。基础见 [Attention 与变体](/basics/attention)。

## DeepSeekMoE：细粒度 + 共享专家

V3 的 MoE 层配置包含 256 个路由专家、每 token 选择 8 个，以及 1 个共享专家；不是所有网络层都必须是 MoE。共享专家恒定参与，路由专家按 token 选择。把它们解释为通用与专门能力是一种设计动机，不能据此认定每个专家已学到可命名的知识领域。

**负载均衡必须说完整**：V3 在选择专家时给 affinity score 加偏置，依据负载上调/下调；偏置不通过普通反向传播学习。选中的专家组合权重仍使用原 affinity score。与此同时，报告保留了较弱的 **sequence-wise balance loss** 以防单序列极端失衡，因此“无辅助损失策略”不等于“整套训练完全没有均衡辅助损失”。

节点受限路由控制通信范围，但不会让通信免费。容量、负载、all-to-all、跨节点带宽与尾部专家拥塞一起决定实际吞吐，见 [MoE](/basics/moe)。

## V3 的训练工程创新

**FP8 混合精度。** 报告中激活采用 $1\times128$ tile、权重采用 $128\times128$ block 缩放，并让累加和敏感模块保留更高精度。它不是“所有张量改 FP8”，也不能脱离硬件、算子和稳定性验证复用。

**MTP。** 多 token 预测增加训练信号；推理可作为投机解码的预测来源。V3 报告在其评估中给出约 1.8 倍 TPS，不是任意硬件/并发/任务的保证。要测接受率、验证开销、batch 和端到端延迟，见 [投机解码](/inference/speculative-decoding)。

**DualPipe。** 调度计算与通信重叠，减少流水线气泡。可隐藏多少通信取决于计算/通信比例和网络，不是无条件“零 all-to-all 成本”，见 [分布式训练](/pretraining/distributed-training)。

### 成本账本：GPU 小时不等于美元

V3 v1 表 1 的口径是正式训练计算，不包括此前研究与消融：

| 阶段 | H800 GPU 小时 |
| --- | ---: |
| 预训练 | 2,664,000 |
| 上下文扩展 | 119,000 |
| 后训练 | 5,000 |
| 合计 | 2,788,000 |

报告假设每 H800 GPU 小时 2 美元，得到 $2{,}788{,}000\times2=5{,}576{,}000$ 美元。**558 万是近似美元额，不是 GPU 小时**。这不是公司总研发成本、R1 总训练成本，也不包含数据采购、人力、失败探索或生产服务成本；不能据此算出比所有闭源同行便宜多少倍。

## GRPO 与 R1：用强化学习激发推理

### GRPO（Group Relative Policy Optimization）

对一个问题采样 $G$ 个回答，以组内奖励统计量构造优势，不额外训练价值模型。简化写法为：

$$
A_i=\frac{r_i-\bar r}{\operatorname{std}(r_1,\ldots,r_G)+\epsilon}.
$$

这里 $\epsilon$ 表示实现需处理零方差的数值保护，并非声称报告公式原样包含它。完整目标还有概率比、裁剪和 KL 约束，不能只用标准化奖励替代整个算法。组内奖励全相同时，这个奖励优势无法区分回答；采样、验算、KL 与训练批次仍会产生成本。

省去 critic 不等于成本减半或训练一定更稳定。PPO 的 critic 也不必与策略同规模。GRPO 可用于可靠打分的任务，不只限定规则奖励；可验证奖励尤其利于减少主观奖励模型偏差。详见 [强化学习基础](/advanced/rl-basics)。

### R1-Zero：纯 RL 的概念验证

报告从**已预训练的 V3-Base** 开始，不进行前置 SFT，使用规则奖励做 RL。训练观察到更长推理、反思等行为，同时有可读性与语言混杂问题。

“纯 RL”描述后训练步骤，不是从随机参数训练、不依赖已有知识，也不证明任何小模型或开放任务都能靠同样方法成功。长链输出与一次“aha”样例也不是可靠理解能力的独立证明。

### R1 正式版：四阶段训练流水线

```text
冷启动 SFT
  → 推理 RL（正确性等奖励，并考虑语言一致性）
  → 拒绝采样与新 SFT（约 60 万推理 + 20 万非推理样本）
  → 面向多场景的 RL（规则奖励与偏好奖励按任务使用）
```

这些样本数量与流程来自 R1 v1。正式 R1 **不是无 SFT 的 R1-Zero**。报告中拒绝采样后对 V3-Base 做 SFT，也不能简单理解为所有阶段始终只在同一个 checkpoint 上接着训练。

### 蒸馏：让小模型继承推理能力

报告用约 80 万条数据微调 Qwen/Llama 稠密底座，形成蒸馏模型；其比较支持特定设置下蒸馏优于所比较的小模型 RL 方案。它不证明小模型无法探索推理，也不保证所有领域都能继承老师能力。

教师错误、冗长轨迹和分布偏移都可能被学生学到。验证需比较同底座、同任务、预算可比的基线，并记录训练数据授权和底座许可。

## 面试速答卡

| 考点 | 可用回答 |
| --- | --- |
| MLA | latent 内容缓存 + 解耦位置 key，矩阵吸收依赖具体实现 |
| MoE 均衡 | 路由偏置按负载调整，并仍保留序列级辅助均衡项 |
| FP8 | 分组缩放与高精度关键路径，不是全模型无条件低精度 |
| MTP | 训练目标与推理加速来源；1.8 倍是报告设置下结果 |
| GRPO | 组内相对奖励替代价值估计，采样和奖励仍有成本 |
| R1-Zero / R1 | 无前置 SFT 的后训练实验 / 含冷启动与多阶段 SFT 的正式流程 |

## 高频追问

<details>
<summary>老板问“V3 只花 560 万，能否用同样预算复现 R1？”</summary>

不能直接推断。V3 数字是正式训练 GPU 小时按假设租金换算，不是全部研发开支，更不是 R1 账本。先拆出已有底座、数据/奖励、消融、集群利用率和后训练资源，再谈可复现预算；本文没有实际复现实验。

</details>

<details>
<summary>MLA 权重能加载，为什么延迟仍可能比 GQA 模型高？</summary>

权重兼容不代表高效算子兼容。要查 latent 缓存是否被展开、矩阵吸收是否生效、精度与 batch、专家通信和框架版本。KV 元素数更少只是一个成本分项。

</details>
