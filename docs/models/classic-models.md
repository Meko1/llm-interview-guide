# 经典模型盘点与架构谱系

“盘点你了解的模型”可以用三个问题组织：**输入怎样互相看见，训练预测什么，部署怎样产生输出？** 这比背年份更能解释模型为什么适合某项任务。本文是历史架构地图，不是当前性能排名。

## 三条架构路线的分化

```text
Transformer
├─ Encoder-only：BERT / RoBERTa → 表示、判别
├─ Decoder-only：GPT / LLaMA / Qwen → 因果序列生成
└─ Encoder-Decoder：T5 / BART / Whisper → 条件序列生成
```

| 路线 | 可见信息与目标 | 推理形态 | 取舍 |
| --- | --- | --- | --- |
| Encoder-only | BERT 双向编码，掩码语言建模 | 输出向量或任务头结果 | 输入可整体编码，不直接提供标准自回归生成接口 |
| Decoder-only | 因果注意力，下一 token 预测 | 逐 token 生成，可复用 KV Cache | 生成接口统一，但长输入和长输出都有成本 |
| Encoder-Decoder | 编码器看输入，解码器因果生成并交叉读取编码结果 | 输入编码一次，再生成目标 | 适合输入输出分离；多一组交叉注意力状态 |

训练目标并非由结构唯一决定：不是所有编码器都用 MLM，也不是所有序列到序列模型都用 span corruption。Embedding/Rerank 同样可由不同骨干构建，不能说“几乎全是 BERT”。

**为什么 Decoder-only 成为大规模文本生成的常见选择？** 因果目标容易从连续文本构造监督；提示、示例和输出可放进同一序列；已有服务栈大量优化增量生成。这是工程解释，不是 Encoder-Decoder 在能力或复杂度上必然落败的定理。Encoder-Decoder 也能使用 KV Cache。

## BERT：理解路线的巅峰与转身

[BERT（2018）](https://arxiv.org/abs/1810.04805) 用双向 Transformer 做语言表示预训练，再增加任务输出头微调。它的核心价值是把大量未标注文本学到的表示迁移给下游任务，而非“能看左右上下文，所以理解一定更强”。

BERT 原版的 MLM 与下一句预测是具体训练配方；后续编码器可以更换目标。BERT 没有标准 GPT 式自回归解码器，不等于双向结构在任何改造下都不能生成。检索与分类是否选择编码器，要比较任务质量、吞吐、输入长度与模型容量，见 [Embedding 与向量数据库](/rag/embedding-vectordb)。

**失败例**：取任意语言模型的隐藏向量做检索，再把相似度当相关性。没有合适的表示训练、池化和负样本协议，架构名称不能保证检索效果。

## GPT 系列：一条路线的完整进化史

| 历史阶段 | 可引用的材料 | 应当讲清的变化 |
| --- | --- | --- |
| GPT-1 / GPT-2 | 生成式预训练路线的历史入口 | 从任务微调到提示式任务表达，不在此补未核验数值 |
| GPT-3（2020） | [Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165) | 175B 自回归模型，实验采用无梯度更新的 zero/few-shot 设置 |
| InstructGPT（2022） | [Training language models to follow instructions](https://arxiv.org/abs/2203.02155) | SFT、偏好排序与 RLHF 改善作者提示分布上的人类偏好 |
| ChatGPT | 对话产品的历史节点 | 产品名称不是固定 checkpoint 或完整架构说明 |
| GPT-4（2023） | [技术报告](https://arxiv.org/abs/2303.08774) | 报告支持图文输入、文本输出；不公开完整内部架构 |
| GPT-4o、o 系列与后续版本 | [版本化发布入口](/models/frontier-models-2025) | 输入输出模态、推理预算和工具接口要分别核对 |

InstructGPT 的“1.3B 优于 175B”具体指作者提示分布上，人评偏好小型对齐模型的输出；不是所有任务都超过大模型，也不能算出“对齐总比扩规模划算”。GPT-3 的 few-shot 结果说明上下文示例可以改善部分任务，不能推断模型临时学习必然可靠或 ICL 是这一代才突然出现。

**GPT-4 是否 MoE？** 本文不采用传闻回答。公开报告没有提供足以确认专家数、总参数等细节，面试中应直接说明未知。

## T5 与 Encoder-Decoder 路线

[T5（2019）](https://arxiv.org/abs/1910.10683) 用 text-to-text 接口统一任务，并系统比较预训练目标、结构、数据与迁移方法。输入输出都写成文本，不意味着必须 Decoder-only。

Encoder-Decoder 的输入表示可以反复被解码器交叉读取；这在翻译、摘要和语音识别中仍有价值。代价包括交叉注意力计算与缓存、两部分参数的部署管理。谁更省要按输入/输出长度与模型尺寸比较，不能只数“有几套模块”。

## 开源主线：LLaMA、Qwen 与 Mistral

[LLaMA（2023）](https://arxiv.org/abs/2302.13971) 展示了公开可获得语料训练稠密语言模型的路线；[Llama 3 报告 v1（2024）](https://arxiv.org/html/2407.21783v1) 描述了数据规模、GQA、后训练与上下文扩展。[Qwen3 报告 v1（2025）](https://arxiv.org/html/2505.09388v1) 则可用来学习稠密/MoE 与思考/非思考后训练。逐代变化见 [LLaMA 与 Qwen](/models/llama-qwen)。

Mistral 7B、Mixtral 是滑动窗口、GQA 和开放 MoE 的学习入口；本文不保留未经本轮读取原报告核对的参数表、胜率及“首个”结论。MoE 的知识容量、单 token 激活量、常驻权重与通信开销要分开谈，详见 [MoE](/basics/moe)。

DeepSeek 的 MLA、MoE、FP8、MTP 与推理后训练是另一组协同设计，见 [DeepSeek 专题](/models/deepseek)。公开权重不自动意味着公开完整训练数据或无条件商用。

## 国内模型生态速览

Qwen、DeepSeek、GLM、Kimi、Doubao、MiniMax、Baichuan、Yi 等名字可帮助定位报告或模型卡，但品牌不是架构类别。问“国产模型有哪些”时，可选择自己读过或用过的两三个版本展开，剩余明确为候选入口，见 [中文生态](/models/chinese-llm-landscape)。

## 闭源三巨头一句话定位

这里沿用旧标题作为导航，不据此给出市场份额结论。OpenAI、Anthropic、Google 的发布材料可以说明模型或系统对外提供什么；**闭源 API 的可观测行为不能反推出参数量、路由或模态融合结构**。比较应限定模型 ID、接口、时间快照和任务。

## 架构演进趋势小结

| 设计轴 | 常见选择 | 不能省略的代价 |
| --- | --- | --- |
| 归一化与激活 | Pre-Norm、RMSNorm、SwiGLU、QK-Norm | 参数/数值配置不同，不能视为通用最优配方 |
| 位置与长度 | RoPE、长上下文训练/扩展 | 名义窗口不等于可靠检索范围 |
| KV 缓存 | MHA、GQA、MLA | 质量、缓存体积和算子支持一起衡量 |
| 容量 | Dense、MoE | 总参数常驻显存、路由与通信 |
| 后训练与推理预算 | SFT、偏好优化、RL、额外生成预算 | 数据/奖励质量、输出长度、失败与成本 |

这是若干报告中的设计方向，不是从旧到新必然单向替代。推理时计算也不能替代预训练、证据检索或测试验证，见 [推理模型](/advanced/reasoning-models)。

## 面试怎么答「盘点模型」类问题

先给三条路线；选一个历史实验讲清任务与协议；再选一个开放权重版本讲工程变化。最后落到自己的约束：哪些能力有原材料依据，哪些只有发布描述，哪些是业务实测。没有实测时讲验证计划，不把计划说成结果。

## 高频追问

<details>
<summary>Encoder-Decoder 没有成为常见聊天底座，是否说明它不能增量推理？</summary>

不能。解码器同样可缓存历史 K/V，也可缓存编码器交叉注意力的 K/V。路线流行度受训练与服务生态影响，不能直接推出能力或算法复杂度上的绝对优劣。

</details>

<details>
<summary>小型 InstructGPT 获得更高偏好，能得出什么、不能得出什么？</summary>

能得出：作者设置中后训练改善了提示分布上的人评偏好。不能得出：小模型在所有知识、推理或安全任务胜过大模型，也不能得出对齐训练的总投入一定更低。

</details>
