# 小语言模型与端侧部署（SLM）

小模型不是“云端大模型的廉价替代品”，而是**在特定任务和资源预算下的候选方案**。它可能更适合离线抽取，也可能因重试、长推理或算子不支持反而更慢、更贵。阅读顺序：先估资源，再看能力来源，最后决定是否端云组合。

## 什么是 SLM？

SLM 没有统一参数阈值。这里指相对较小、面向有限资源或窄任务的语言模型；“小”不保证能在任意手机运行，也不代表知识、推理或多模态需求相同。

| 历史学习案例 | 可讨论的证据 | 不可直接推断 |
| --- | --- | --- |
| [Phi-3 报告（2024）](https://arxiv.org/abs/2404.14219) | phi-3-mini 3.8B，过滤网页与合成数据；报告有手机部署案例 | 任意手机、任意温度与上下文都能达到同样体验 |
| [Qwen3 初版报告 v1（2025）](https://arxiv.org/html/2505.09388v1) | 多尺寸与强到弱蒸馏 | 小型号自动与旗舰同等可靠 |
| [R1 报告 v1（2025）](https://arxiv.org/html/2501.12948v1) | Qwen/Llama 稠密底座上的推理蒸馏 | 在未见领域或业务上必然超过同尺寸模型 |
| MiniCPM、SmolLM、Gemma、Llama 小尺寸 | 查具体模型卡的候选入口 | 同系列尺寸、模态、许可和运行条件都一致 |

## 为什么需要 SLM？

适合考虑小模型的约束包括离线、敏感数据不出端、窄任务高频执行或设备预算受限。可本地部署也不等于行为容易审计：日志、权重来源、更新渠道与失败检测仍需系统设计。

对分类或格式转换，先问是否需要语言模型。规则、传统分类器、schema 校验可能更便宜、更确定；把 Agent 拆成子任务也不意味着每步都应调用 SLM。

## 小模型为什么也能很强？

- **数据筛选与合成**：Phi-3 报告提供具体例子，但合成数据也会放大老师错误或覆盖缺口。
- **蒸馏**：学习老师产生的输出或轨迹，可减少独立探索需求；不能越过底座容量与数据分布限制。
- **较长训练**：生命周期请求量大时，训练更多换较低推理成本可能合理；不保证任何任务都值得。
- **窄域适配**：固定分布上减少能力要求，但分布外输入、注入攻击和新术语仍需挑战集。

这些是机制与报告案例，不是“小模型经微调常能追平所有大模型”的通用结论。相关方法见 [数据工程](/pretraining/data-engineering)、[DeepSeek](/models/deepseek)、[缩放定律](/pretraining/scaling-law)。

## 端侧部署技术栈

```text
模型层：具体 checkpoint + tokenizer/template + 量化版本
运行层：llama.cpp / MLX / MNN / MLC-LLM / ExecuTorch / ONNX Runtime 等候选
后端层：CPU / GPU / NPU 的实际算子与分配策略
设备层：内存上限、可用带宽、持续功耗与系统限制
```

这是选型导航，不是兼容性声明。GGUF 是文件/模型表示格式；AWQ 是权重量化方法；INT4/INT8 是位宽，三者不能当作同一层级替代项。模型可加载也不证明所有计算都已 offload 到 NPU。

### 先做内存账本

构造例：3B 参数模型，单纯 4-bit 权重有效载荷为 $3\times10^9\times4/8=1.5$ GB（十进制）。真实需求还含量化 scale、未量化层、KV Cache、激活、临时 workspace 与运行时。因此不能说“3B INT4 固定约 2GB、轻松进手机”。

GQA 的缓存有效载荷可估为：

$$M_{KV}=2BLTn_{KV}d_hs,$$

其中 $B$ 为并发序列数、$L$ 为层数、$T$ 为缓存长度、$n_{KV}$ 为 KV 头数、$d_h$ 为头维度、$s$ 为每元素字节数。构造 $B=1,L=32,T=4096,n_{KV}=8,d_h=128,s=2$ 时，结果为 512 MiB。此式不含分页、对齐或缓存量化元数据，也不适用于直接估 MLA 的缓存布局。

**速度账本**还要分 prefill 与 decode：长输入可能使首 token 延迟成为瓶颈；小 batch 的 decode 常受访存影响，但量化反量化、算子效率、并发与 offload 会改变瓶颈。持续运行的热降频不能用短时峰值代替。

## 端云协同架构（面试加分项）

| 模式 | 适用条件 | 风险与代价 |
| --- | --- | --- |
| 分级路由 | 本地简单任务，复杂任务升级 | 难度预测错；云端超时和重复计费 |
| 端侧预处理 | 本地筛选/脱敏后上云 | 脱敏可能漏敏感信息，也可能损坏关键语义 |
| 本地缓存/离线兜底 | 有可校验的有效期和适用范围 | 过期答案与缓存权限隔离 |
| 端侧草稿、云端验证 | 模型/分词协议相容且网络预算可接受 | 往返、低接受率、验证成本可能抵消收益 |

投机协同不是“草稿可靠所以直接相信”；正确性还依赖验证算法。分级路由不能只依赖小模型自报置信度，可结合确定性校验、输入分布、证据缺失和风险级别。相关设计见 [系统设计](/engineering/system-design)。

## SLM vs LLM 选型

不要只比较 token 单价。构造例：小模型每次尝试成本 0.002 元，成功率 80%；大模型每次 0.006 元，成功率 98%。假设失败都可识别、尝试独立且无限重试，单位成功成本分别约为 $0.002/0.8=0.0025$ 元和 $0.006/0.98\approx0.00612$ 元。真实系统不满足无限重试假设，还要加入升级、网络和人工成本；高风险失败也不能只折成钱。

端侧验收至少覆盖：冷启动和热启动、典型/长 prompt、持续负载、后台内存压力、离线、任务质量、安全与云端升级路径。固定模型、量化、运行时、设备型号、系统版本和温度条件，报告 p50/p95 延迟、峰值内存、能耗与成功率。本文没有运行这些真机实验。

## 高频追问

<details>
<summary>量化后的大模型就是 SLM 吗？</summary>

不是。参数规模、量化位宽和部署位置是不同维度。量化降低权重存储，不一定降低所有激活/缓存开销，也可能改变质量与算子性能。

</details>

<details>
<summary>本地抽取准确率高，是否可以直接承担云端路由？</summary>

还需验证错路由的代价与识别机制。测试单位、否定、长尾实体、分布外输入和注入；危险动作保持确定性权限/校验，失败可升级或拒绝，不靠模型自信程度放行。

</details>
