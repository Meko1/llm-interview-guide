# 中文大模型生态全景

认识生态不是给厂商排座次，而是能回答：**哪个具体 checkpoint 适合什么任务，依据在哪里，部署后怎么证明它够用？** 本文保留模型、垂直领域、数据与工具的导航，但不维护实时市场份额或性能榜。

[Awesome-Chinese-LLM](https://github.com/HqWu-HITCS/Awesome-Chinese-LLM) 可用作发现项目的社区索引，不能替代技术报告、模型卡与许可文件。架构细节见 [LLaMA 与 Qwen](/models/llama-qwen)、[DeepSeek](/models/deepseek)；历史发布快照见 [前沿模型盘点](/models/frontier-models-2025)。

## 面试先背这几句话

- 先说模型全名、版本和任务，再说能力；“某厂商中文强”不是可复现的选型依据。
- 开放权重、开放训练代码、开放训练数据、允许商用是不同属性；许可要逐 checkpoint 查。
- 中文知识选择题、指令遵循、术语抽取、工具调用和长文引用应分开评测。
- 领域适配不必从训练开始：提示、检索、工具与微调解决的问题不同。
- 数据规模不是质量证明，尤其要核对来源授权、重复、个人信息和评测污染。

## 一、国内厂商模型矩阵

### 1.1 代表系列：用报告版本代替梯队 {#_1-1-第一梯队-2025-2026-视角}

下面是用于学习的**历史版本快照**，不是截至 2026 年 11 月的在售型号清单。

| 系列与材料 | 可以据此讨论 | 不能据此断言 |
| --- | --- | --- |
| DeepSeek-V3（2024 报告）、R1（2025 报告） | MLA、MoE、推理后训练和蒸馏 | 今天 API 的价格或某业务的胜率 |
| Qwen2.5（2024 报告）、Qwen3（2025 初版报告） | 数据扩展、稠密/MoE、思考模式 | 全系列共享相同上下文与许可 |
| GLM、Kimi、Doubao/Seed、Hunyuan、ERNIE | 作为候选系列查模型卡和产品文档 | 厂商路线等于每款模型架构 |
| MiniMax、Step、InternLM | 按具体版本查注意力、多模态与部署支持 | 未读取报告的参数量或性能优势 |

前两行依据 [V3 报告 v1](https://arxiv.org/html/2412.19437v1)、[R1 报告 v1](https://arxiv.org/html/2501.12948v1)、[Qwen2.5 报告](https://arxiv.org/abs/2412.15115)、[Qwen3 报告 v1](https://arxiv.org/html/2505.09388v1)。其余行仅是候选导航，本文没有对这些系列作逐版本技术核验。

### 1.2 其他重要玩家

Baichuan、Yi、MiniCPM、Spark、Skywork、PanGu 等名字仍有检索价值，但不在这里推断公司归属、市场排名或产品转向。面试准备应为用过的候选建立一张记录卡：

```text
模型 ID / checkpoint revision / Base 或 Instruct
模型卡与权重许可 / 代码许可 / 数据使用条件
服务方式 / 精度 / 推理框架版本 / 硬件
业务样本集版本 / 提示与解码设置 / 失败案例
```

端侧候选的重点不是厂商体量，而是目标设备的内存、持续功耗和任务质量，见 [SLM](/models/slm)。

## 二、开源系谱：为什么 Qwen 成了「中文 LLaMA」

这个比喻表达的是“可复用底座与衍生模型生态”，不是架构相同或所有中文项目都采用 Qwen。Qwen2 报告发布了不同尺寸的基础与指令模型，Qwen3 初版报告进一步包含稠密和 MoE 模型；这些让开发者可以按算力和任务筛选候选，见 [Qwen2 报告](https://arxiv.org/abs/2407.10671)。

选底座还要看 tokenizer 对你的中文、代码、表格混合文本的实际压缩率。大词表可能缩短序列，也增加嵌入层和输出头成本；不能只凭词表大小推断推理便宜。系列内的 Coder、VL、Audio 等变体也不是同一个模型切换输入格式，必须分别核对架构、接口与许可。

**失败例**：用一个通用中文问答榜的分数选择财报抽取底座，上线后把“万元”识别成“元”。这里缺的不是厂商名单，而是单位、否定、表格关系和证据定位测试。

## 三、垂直领域模型盘点

社区索引中的 HuatuoGPT、BenTsao、LaWGPT、DISC-FinLLM、FinGLM 等可作为学习入口，项目名称不等于领域资质，也不说明当前维护状态。

| 领域 | 必须单独验收的能力 | 典型失败 |
| --- | --- | --- |
| 医疗 | 证据出处、适用人群、拒答与升级人工 | 把一般知识改写成个体诊断 |
| 法律 | 法域、条文版本、事实与意见分离 | 引用失效条文或虚构案例 |
| 金融 | 数值、单位、日期、计算工具与引用 | 混淆合并报表与母公司口径 |
| 教育 | 解题步骤、反例和错误定位 | 答案正确但中间步骤不成立 |

可选适配流程保留如下，不意味着每一步都要做：

```text
业务失败样本与基线
  → 提示 / 结构化输出 / 工具 / RAG
  → （必要时）领域继续预训练
  → 领域 SFT 与安全偏好适配
  → 留出集与生产约束验收
```

继续预训练用于改变语料分布，SFT 用于任务行为；事实可由 RAG、数据库或权威 API 提供。训练权重也会记住事实，RAG 也会检索错；关键是更新、引用与纠错机制，而非“事实绝不进权重”。相关取舍见 [RAG vs 长上下文 vs 微调](/rag/rag-vs-long-context)。

## 四、中文数据集

### 4.1 预训练语料

WuDao、SkyPile、WanJuan、MNBVC、CCI 是历史语料项目的检索入口。这里不保留未逐项核对的规模与“高质量”评级。下载前检查发布版本、子集构成、采集与去重规则、语言配比和许可；网页公开可见不等于可自由训练。

### 4.2 SFT 指令数据集

BELLE、COIG/COIG-CQIA、Firefly、Alpaca-zh、ShareGPT-zh、Magpie-zh 可帮助比较数据构造方法，但同名派生数据未必共享质量与授权。[COIG-CQIA（2024）](https://arxiv.org/abs/2403.18058) 报告描述了真实来源与人工核验；这是该数据集的制作证据，不是“中文 SFT 数据都可靠”。

评估样本时应查：问题是否自然、回答能否追溯、是否泄露评测题、翻译是否扭曲意图，以及训练/验证是否按来源或实体拆分。奖励模型评分只能辅助筛选，不能替代事实核对。

### 4.3 偏好数据集

中文偏好数据要记录比较的是有用性、事实性、安全还是文风，及标注指南、分歧处理与授权。不能把英文偏好对翻译为中文后视为已完成本地价值对齐。训练方法见 [RLHF / DPO](/finetuning/rlhf)。

## 五、中文评测基准 ★

| 基准类别 | 学习入口 | 能支持的结论 |
| --- | --- | --- |
| 中文知识选择题 | [C-Eval（2023）](https://arxiv.org/abs/2305.08322)、[CMMLU（2023）](https://arxiv.org/abs/2306.09212) | 在固定题集、提示和计分方式下的答题表现 |
| 考试与开放题 | AGIEval、GAOKAO-Bench | 需查子集、题型与开放题评分协议 |
| 幻觉、安全、领域任务 | HalluQA、Safety-Prompts、CValues、PromptCBLUE | 只覆盖其定义的风险和任务 |
| 主观偏好或综合评测 | SuperCLUE、Arena 类评测 | 依赖采样人群、配对与评判协议 |

C-Eval 原论文明确包含 52 个学科、不同教育与职业难度；这不代表能替代中文业务验收。公开题集还可能被训练数据包含。比较结果至少固定 checkpoint、模板、few-shot、思考预算和评分器，并报告样本数与错误类型，见 [评测基准深入](/evaluation/benchmarks)。

## 六、训练/推理工具链的国产开源力量

LLaMA-Factory、XTuner、Swift、vLLM、LMDeploy、SGLang、OpenCompass、FlagEval、ModelScope 等是工具入口，不是流行度或无障碍下载保证。框架名只说明能力类别；运行前要验证模型支持、量化格式、许可证与版本兼容。

工具路线见 [微调训练工具链](/finetuning/training-frameworks)、[推理框架对比](/inference/serving-frameworks) 和 [学习资源](/interview/resources)。选工具时优先考虑已有运维能力、可观测性与回滚，而不是换成榜单上的“标准配置”。

## 高频追问

<details>
<summary>你如何回答“国产模型和闭源模型差距多大”？</summary>

先询问任务与部署条件，再给同一业务集的比较方法：质量、安全、延迟、吞吐、单次成功成本、许可与可维护性。没有同版本同协议结果时，不给“领先半年”或“已追平”的全局结论。

</details>

<details>
<summary>中文知识榜第一，为什么仍不能直接作为领域底座？</summary>

榜单测的是特定问题分布。领域系统还涉及证据引用、权限、单位、格式、时效和拒答。建立领域留出集与挑战集，比较提示/RAG 基线和微调增益；将版本及错误样本写入选型记录。

</details>
