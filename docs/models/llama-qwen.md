# LLaMA 与 Qwen 架构演进

这一页不是“哪个系列更强”，而是回答**为什么改这个组件，收益如何验证，代价记在哪本账里**。范围限定 LLaMA 1/2、2024 年 Llama 3 报告，以及 Qwen 1/2/2.5、2025 年 Qwen3 初版报告；系列名称不能替代 checkpoint 版本。

## 现代开源 LLM 的"标准配方"

在本文讨论的稠密模型中，Decoder-only、Pre-RMSNorm、SwiGLU、RoPE、GQA 是常见组合，不是所有开放模型的标准或最优架构。

| 组件 | 设计动机 | 必须保留的边界 |
| --- | --- | --- |
| Pre-Norm / RMSNorm | 深层训练与归一化开销 | 稳定性还依赖初始化、学习率和精度 |
| SwiGLU | 门控前馈表达 | 中间维度决定参数与 FLOPs，不能只比激活函数名字 |
| RoPE | 在注意力中表达位置关系 | 位置形式不保证未经训练的任意长度外推 |
| GQA | 多个 Q 头共享 KV，降低缓存 | KV 头数影响质量、并行划分与显存 |
| QKV bias / QK-Norm | 模型版本中的注意力设计差异 | 删除 bias 与增加归一化不是数学上的等价替换 |

第一代 LLaMA 使用 MHA；不能把后续 GQA 追溯成所有 LLaMA 的固有配置。GQA 与 MLA 的不同路线见 [Attention](/basics/attention) 和 [DeepSeek](/models/deepseek)。

## LLaMA 系列演进

### 演进总览

| 报告版本 | 公开范围 | 学习重点 |
| --- | --- | --- |
| [LLaMA（2023）](https://arxiv.org/abs/2302.13971) | 7B–65B 基础模型 | 数据预算与长期推理成本的平衡 |
| [Llama 2（2023）](https://arxiv.org/abs/2307.09288) | 7B–70B 基础与 Chat 模型 | 对话后训练、安全与有用性 |
| [The Llama 3 Herd of Models v1（2024）](https://arxiv.org/html/2407.21783v1) | 包括 405B 稠密模型、最长 128K 窗口 | 数据规模、GQA、词表、后训练与长度扩展 |

Llama 3 报告覆盖的发布阶段与最初 Llama 3 发布不是同一配置快照。不能把 405B、128K 写成最初所有型号都拥有的参数，也不能据后续产品名推断完整网络结构。

### 每一代解决了什么问题

**LLaMA 1：考虑长期推理预算。** 较小模型训练更久，可能用更多一次性训练成本换较低部署成本。原报告中 13B 在多数所测基准超过 GPT-3 175B，这是其任务与协议下结果，不是任何业务的普遍比较。训练算力最优与生命周期成本最优也不是同一个目标，见 [缩放定律](/pretraining/scaling-law)。

**Llama 2：把基础模型变成对话候选。** 报告明确区分 pretrained 与 Chat 模型，描述对话和安全后训练。比较时要对齐 Base/Instruct 属性、提示和评测方式，不能把聊天偏好变化都归因于注意力架构。

**Llama 3：一起改变数据、词表和训练配方。** 2024 报告中旗舰训练使用 15.6T 文本 token，采用 8 个 KV 头的 GQA，后训练包含 SFT、拒绝采样和 DPO。多个因素同时变化，不能直接宣称“提升大部分来自数据”而没有控制变量或消融证据。

报告在架构选择中已设置 RoPE base 为 500,000；不能说这是 3.1 扩到 128K 时才首次修改。长度扩展还包括逐步增加长序列训练与验证，不是改一个频率就完成。

Llama 4 的入口见 [前沿模型快照](/models/frontier-models-2025)；本轮未读到其模型卡，不保留据此推断“稠密路线已被放弃”的结论。

## Qwen 系列演进

### 演进总览

| 报告版本 | 报告给出的变化 | 不应跨版本合并的属性 |
| --- | --- | --- |
| [Qwen（2023）](https://arxiv.org/abs/2309.16609) | Base/Chat 与多语言、工具应用路线 | 早期型号的长度和许可 |
| [Qwen2（2024）](https://arxiv.org/abs/2407.10671) | 多尺寸基础/指令模型，包含 Dense 与 MoE | 每个尺寸的上下文和注意力配置 |
| [Qwen2.5（2024）](https://arxiv.org/abs/2412.15115) | 报告语料从 7T 扩至 18T，并更新后训练 | 语言模型与 Coder/Math/VL 不共用全部配置 |
| [Qwen3 v1（2025）](https://arxiv.org/html/2505.09388v1) | 36T 语料，119 语言/方言覆盖，思考/非思考后训练 | 初版混合模式不代表后续所有 checkpoint |

数据量是报告口径，不是有效非重复知识量，也不能推出语言覆盖内每种语言都达到同等水平。

### 每一代的关键设计

**Qwen 1。** 大词表是其多语言路线的学习点，但是否更省中文 token 要用具体 tokenizer 编码业务语料验证。早期 QKV bias 的配置与动机应查对应报告和源码；本文不保留没有逐项核验的“bias 必然改善外推”。

**Qwen2 / Qwen2.5。** 既有数据扩展，也有后训练与不同尺寸/专项分支。一个型号标注 128K，不意味着所有分支原生支持同等长度；长上下文扩展选项与默认推理设置也须分开。

**Qwen3 初版。** 报告架构段明确沿用 GQA、SwiGLU、RoPE、Pre-RMSNorm，去掉 QKV bias 并引入 QK-Norm 以支持稳定训练。QK 归一化改变注意力数值行为，但还涉及缩放和可学习参数，不能说从数学上保证无 loss spike。

后训练将长推理与非思考数据结合；这不是仅靠一个模板就“赋予推理能力”。[官方仓库](https://github.com/QwenLM/Qwen3) 还区分 2507 Instruct 与 Thinking 版本，Instruct-2507 示例已不要求 `enable_thinking=False`，不能把初版开关视为整个系列永久接口。

## LLaMA vs Qwen：面试对比要点

| 维度 | 该怎样比较 |
| --- | --- |
| Tokenizer | 同一中文/代码/表格语料的 token 数、特殊 token 与模板开销 |
| 注意力 | Q/KV 头数、头维度、bias、QK-Norm、位置与缓存布局 |
| 后训练 | Base/Instruct、任务数据、偏好优化与思考模式版本 |
| 上下文 | 训练长度、扩展方式、服务默认限制与长文本质量 |
| 开放性 | 逐 checkpoint 的模型、代码、数据许可与使用限制 |

不要回答“国内都用 Qwen，因为许可一律宽松”；模型、数据和衍生权重的授权要分别检查。候选选型见 [中文生态](/models/chinese-llm-landscape)。

### 词表账本：缩短序列也会增大输出层

构造例：隐藏维度为 4096，词表从 32,000 增到 128,000。若输入嵌入与输出头**不共享权重**，新增参数为：

$$2(128{,}000-32{,}000)\times4096=786{,}432{,}000.$$

只算 BF16 权重约增加 1.57 GB（十进制），不含梯度、优化器与运行时。若权重共享，参数增量减半。这是教学计算，不是 Llama 3 某个 checkpoint 的完整内存账单。

## 与闭源 GPT 系列的架构差异

[GPT-4 报告（2023）](https://arxiv.org/abs/2303.08774) 不公开完整内部架构，因此不以 MoE 传闻当对照行。公开报告允许检查配置与实验，闭源产品通常只能比较接口与行为；这是证据透明度差异，不直接证明能力或可靠性差异。

如果要解释“架构相似但质量不同”，应列数据、参数、优化、后训练、评测模板等候选原因；没有消融时不量化各自贡献。

## 高频追问

<details>
<summary>为什么不能把“8 个 KV 头”背成 GQA 的最优答案？</summary>

它是 Llama 3 报告中的配置，不是通用最优。缓存体积取决于 KV 头数与头维度，缩减比例应相对该模型的 Q 头数计算；并行切分还可能复制 KV 头。质量要在训练和任务设置中验证。

</details>

<details>
<summary>领域适配选 Base 还是 Instruct？</summary>

继续预训练常优先考虑 Base，任务格式适配可从 Instruct 做基线，但不能直接断言 Instruct + LoRA 总最划算。比较遗忘、引用/安全能力与业务质量，并控制数据量、训练预算和部署约束。没有实测时给计划而不是胜负结论。

</details>

<details>
<summary>改 RoPE base 后模型能加载，能否宣称支持 128K？</summary>

不能。加载、生成不报错、窗口容量和长程质量是不同验收项。需按目标长度训练或采用适当扩展，并测不同位置、跨段依赖和延迟/显存；仅改配置不是技术验证。

</details>
