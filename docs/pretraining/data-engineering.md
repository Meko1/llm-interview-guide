# 数据工程与合成数据

> 本文按数据流阅读，但决策顺序是先冻结目标任务与验证集，再确定来源、过滤和配比。不同模型同时改变训练量、架构与后训练，不能把跨代效果差异唯一归因于数据。读完应能交付带血缘的 token 账本，而非一串清洗工具名。

## 一、全景：预训练数据流水线

```
原始数据源 (Common Crawl / 代码 / 书籍 / 论文 / 对话)
   │
   ▼
文本抽取 ──► 语言识别 ──► 规则过滤 ──► 质量打分 ──► 去重 ──► 去毒/隐私 ──► 去污染 ──► 配比混合 ──► 训练
 (HTML→文本)  (fastText)   (启发式)    (模型打分)  (3 个层级)  (PII/毒性)  (评测集泄漏)  (领域权重)
```

留存率取决于分母是抓取字节、文档数还是 tokenizer 处理后的 token，也取决于语言与过滤规则。没有同口径快照，不报告通用留存百分比。

## 二、清洗流水线逐层拆解

### 1. 文本抽取与语言识别

- HTML → 正文：用 trafilatura 等工具去掉导航/广告/模板（boilerplate）；抽取质量直接决定后面所有环节的上限。
- 语言识别：fastText 语言分类器按语种分流，决定每种语言进入各自的清洗管道。

### 2. 规则过滤（启发式）

可作为实验起点的启发式规则（不是跨语言统一标准）：

| 规则类型 | 示例 |
| --- | --- |
| 长度 | 过滤过短文档、平均词长异常的文档 |
| 符号比例 | 标点/字母比、数字占比、特殊符号占比超阈值 |
| 重复结构 | 重复行占比、重复 n-gram 占比过高（模板页/垃圾站） |
| 完整性 | 以项目符号开头的行占比、不以标点结尾的行占比 |
| 黑名单 | 色情/赌博站点域名、关键词 |

### 3. 模型质量打分

规则只能去掉"明显的垃圾"，区分"普通文本 vs 高质量文本"需要模型：

- **分类器打分**：训练 fastText/BERT 小分类器，正样本用维基、书籍、被高赞引用的页面，给每篇文档打质量分，按分数采样。
- **困惑度过滤**：用 KenLM 等小语言模型算 PPL，过高（不通顺）或过低（高度模板化）都可疑。
- **LLM 打分**：FineWeb-Edu 使用教育价值评分训练分类器，再筛选网页。评分学习的是指定标注目标，不是通用真伪判别器；高教育分不保证数学答案正确或适合所有任务。

### 4. 去重（三个层级）

| 层级 | 方法 | 说明 |
| --- | --- | --- |
| 精确去重 | 文档哈希（MD5/SHA） | 去掉完全相同的文档 |
| **模糊去重** | **MinHash + LSH** | 工业主力：估计文档间 Jaccard 相似度，去掉近重复（转载/小改动） |
| 子串去重 | 后缀数组找长公共子串 | 去掉文档内/跨文档的长重复片段 |

重复会改变样本权重，可能增加记忆和原文复现风险，也可能浪费预算；但去重强度过大可能丢失合法模板与低资源领域。以独立验证损失、长尾任务与复现风险共同选择阈值，不把记忆和泛化视为互斥结果。

**MinHash 一句话原理**：对每篇文档的 n-gram 集合做多个随机哈希、各取最小值组成签名；两篇文档签名相同位置的比例 ≈ Jaccard 相似度。LSH 把签名分桶，只对同桶文档精算，避免两两比较的 $O(N^2)$。

### 5. 去毒、隐私与去污染

- **毒性过滤**：分类器去除仇恨/暴力内容（注意过度过滤会误伤方言、少数群体相关文本——这本身是个研究课题）。
- **PII 处理**：识别并删除/替换邮箱、电话、身份证号等个人信息。
- **基准去污染（decontamination）**：对实际训练快照与冻结评测集进行交叉审计，分别检查题干、答案、解释和同源变体。n-gram 只用于发现候选，重叠不自动证明实际训练使用或分数影响；未命中也不代表无泄漏。实践见 [数据污染审计](/pretraining/contamination-audit)。

## 三、数据配比与训练课程

### 配比（Data Mixture）

各领域数据按什么比例混合，直接影响模型能力分布：

- 网页、代码、数学的配比由目标任务和可用来源决定。代码数据对特定推理任务的增益需要控制总 token、训练计算与其他数据配比的消融，不从占比相关性推出因果。
- 多语言配比决定各语言能力；中文模型必须保证足够中文语料与配套词表（见 [LLaMA 与 Qwen](/models/llama-qwen)）。
- **DoReMi** 用小代理模型的域重加权产生配比，再用于较大模型；论文实验支持该设置中的改善，不保证跨 tokenizer、领域和规模迁移后仍最优。

### 课程（Curriculum）：数据顺序也有讲究

现代预训练普遍分阶段：

```
阶段一：主预训练 —— 海量混合数据（数 T 至数十 T tokens）
阶段二：退火/中期训练 —— 提高高质量数据（教科书、数学、代码）占比，
        学习率衰减收尾，常配合上采样精品数据
阶段三：长上下文扩展 —— 长文档继续预训练，扩 RoPE base
```

以上是可能的阶段安排，不是所有模型的必选三阶段。数据分布与学习率同时改变时，要用对照区分各自贡献；长上下文适配也不只是修改 RoPE base，还需检查长度分布、位置策略与短上下文退化。

## 四、合成数据：从补充到主力

当许可、质量或领域覆盖限制可用真实数据时，可以用合成数据补缺口；“数据耗尽”必须限定来源与任务，不能据此证明合成数据已普遍成为主力。

### 主要技术路线

| 方法 | 思路 | 代表 |
| --- | --- | --- |
| Self-Instruct | 用 LLM 从种子任务扩写指令数据 | 早期 Alpaca |
| Evol-Instruct | 让 LLM 把指令改写得更复杂/更深 | WizardLM |
| 蒸馏 | 强模型生成回答训练弱模型 | 大量开源 Instruct 模型 |
| 教科书合成 | 让 LLM 按主题撰写教学级语料用于**预训练** | Phi 系列 |
| 拒绝采样 | 采样多个回答，用 RM/规则筛出最优入库 | LLaMA 3 后训练 |
| 自我提升 | 模型自己生成-筛选-训练循环迭代 | R1 蒸馏数据、RFT |

### 合成数据的风险

- **模型坍缩（model collapse）**：递归训练可能丢失尾部分布；风险受真实数据保留、采样与训练设置影响。混入真实数据和验证器过滤是风险控制，不是免疫保证；过滤器本身也可能偏向简单题。
- **偏差继承**：教师模型的错误与风格偏好被放大固化。
- **同质化**：不同团队用同一个强模型蒸馏，模型间风格趋同。

> 关键认知：合成数据的价值核心在**验证器**——数学可判对错、代码可跑测试，所以数学/代码合成数据最成功；无法验证的开放域合成数据质量保障要难得多。这与 RLVR 火爆的原因同源（见 [强化学习基础](/advanced/rl-basics)）。

## 五、SFT 阶段的数据工程

预训练看"量+质"，SFT 看"质+多样性"，逻辑完全不同：

- **质量与覆盖先于盲目扩量**：LIMA 在 65B LLaMA 上使用 1000 条精选样本，支持其设置下有限指令数据有效的结论；不能证明任何领域都只需千条，也不能证明 SFT 无法学习新知识。
- **多样性**：任务类型、难度、长度、语言风格的覆盖比条数重要；大量近似重复的指令会让模型过拟合到固定句式。
- **难度分级**：从模型答错的样本里挑训练数据（错题本思路）比随机采样有效。
- **数据筛选自动化**：IFD、指令跟随难度评分等方法自动从大池子里挑高价值样本。
- **格式即数据**：loss mask（只算回答部分损失）、多轮对话的拼接方式、系统提示的多样化，都是 SFT 数据工程的一部分，详见 [微调范式](/finetuning/finetuning)。

## 高频追问

**Q：去重为什么用 MinHash 而不是两两比较或 embedding 聚类？**
全量两两比较是 $O(N^2)$；MinHash+LSH 用概率候选筛选减少比较。桶倾斜仍可能产生大量候选，漏检/误删必须在标注样本上测量；隐私文本不能把“少量漏检”默认当作可接受。

**Q：怎么判断预训练数据是否污染了评测集？**
可结合精确匹配、n-gram、近重复和语义候选，再回查原文、血缘与实际训练使用记录。规则阈值不是通用标准；改写、翻译或私有新题对照也有难度和分布变化等混杂因素。详见 [污染审计的三层证据](/pretraining/contamination-audit)。

**Q：代码数据为什么能提升通用推理能力？**
代码提供状态、依赖和形式化结构，是可能的机制解释；要证明提升来自代码，需等 token/等计算消融并检查基准污染。对特定任务有效不等于对所有通用推理都有效。

**Q：数据快用完了怎么办（数据墙问题）？**
四条路：① 合成数据（配验证器保质量）；② 多模态数据（图像/视频/语音的信息远未挖尽）；③ 提高数据利用效率（多 epoch 训练的边际收益研究、课程学习）；④ 把算力从预训练转向后训练/推理时计算（test-time scaling，见 [推理模型与慢思考](/advanced/reasoning-models)）。

**Q：SFT 数据 1 万条和 100 万条怎么选？**
先问基座能力、任务覆盖与新增知识，再用逐步扩量实验画学习曲线。LIMA 不能给出通用“万条足够”的门槛；领域知识还可比较继续预训练、SFT 与检索，并同时检查遗忘和回答质量。

## 数据上线账本：不是只有保留条数

每个 shard 记录来源/许可、时间与哈希、抽取版本、过滤原因、去重簇、tokenizer 与 token 数。配比按实际进入 loss 的 token 统计，不把长短差异很大的文档条数当权重。重复 epoch 分开记录独特数据量和处理量；冻结评测集后做交叉污染审计。

合成样本保留生成模型/提示/采样配置、来源与验证轨迹。代码测试通过仅覆盖测试到的行为，奖励模型分高也不等于事实正确。最终留出不经过同一生成器与筛选器挑选的验证集，避免“生成—过滤—评测”共享偏差。

复跑必须能恢复采样器 RNG、域权重与数据游标；换 world size 后检查重复/跳过范围，而不是只确认训练进程启动。来源：[FineWeb-Edu 数据卡](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu)、[DoReMi](https://arxiv.org/abs/2305.10429)、[LIMA](https://arxiv.org/abs/2305.11206)。数据卡和默认分支可能变化，实际复现须锁定 revision。

**Q：如果让你从零搭建一条中文预训练数据管线，你会怎么设计？**
按漏斗作答：CC + 中文网页源 → trafilatura 抽取 → fastText 语种过滤 → Gopher 式规则过滤（针对中文调阈值，如字符比、长度按字数）→ 质量分类器（正样本用百科/出版物训练）→ MinHash 去重（中文按字或词 n-gram）→ PII/毒性过滤 → 评测集去污染 → 配比实验（小模型代理实验定配比）→ 退火阶段预留精品数据。能完整说出漏斗 + 中文特殊处理（分词、繁简、全半角）即是高分答案。
