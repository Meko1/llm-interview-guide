# Agent 持续进化专题扩展设计

## 背景

本轮内容扩展以李博杰《深入理解 AI Agent：设计原理与工程实践》v1.3 的第 8 章“Agent 的持续进化”为主要启发，并结合仓库现有 Agent、记忆、评估、工作流和生产治理专题重新组织。PDF 提供概念框架，正文必须使用本站自己的面试场景、架构表达和工程案例，不照搬原文段落、表格或示意图。

当前 `docs/agent/agent-basics.md` 已覆盖 Agent Loop、工具、记忆、安全、预算、可观测和发布等基础知识，且篇幅很长；现有文档也分别覆盖上下文工程、工具安全、Agent 评估与耐久工作流。项目尚未系统回答另一个重要问题：Agent 如何把运行经验转化为可验证、可发布、可回滚的长期能力，而不是只会保存聊天记忆或不断追加 Prompt。

## 目标

新增 `docs/agent/agent-continuous-evolution.md`，面向 Agent 工程、LLM 应用开发和系统设计面试，建立一条完整主线：

- 区分记忆、反馈回流、在线学习与持续进化。
- 说明如何从运行轨迹中提取可信学习信号。
- 根据问题性质选择知识、指令或 Skill、程序或 Harness、模型参数四类更新载体。
- 用“在线稳定执行 + 离线候选进化”双循环隔离生产流量与能力更新。
- 给出验证、灰度、回滚、审计和不可自改可信根的工程边界。
- 提供系统设计题、指标、失败模式、高频追问和项目讲法。

## 页面定位与边界

页面定位是“持续进化控制面与能力生命周期”，不是 Agent 基础概念的再次汇总。

本页负责：

- 经验如何成为候选更新。
- 候选更新写到哪里。
- 如何证明新能力真正有效且没有破坏旧能力。
- 如何安全地发布、回滚、整理和淘汰能力。

本页不重复展开：

- 记忆分类与检索细节，链接到 `/agent/agent-memory`。
- 单次任务的轨迹评估方法，链接到 `/agent/agent-evaluation`。
- 上下文压缩与隔离算法，链接到 `/agent/context-engineering`。
- 长任务检查点、重试与业务补偿，链接到 `/agent/durable-agent-workflows`。
- Prompt、Skill、工具的企业治理细节，链接到已有 interview 专题。
- 模型后训练算法推导，链接到微调与强化学习栏目。

## 内容结构

### 1. 先建立边界：记住不等于学会

用对比表区分会话上下文、用户记忆、经验资产和模型参数更新，强调“保存一次反馈”“无限追加规则”和“可迁移、可淘汰、可回滚的能力更新”不是同一件事。

### 2. 从轨迹中提取学习信号

将证据分为三层：

- 结果证据：业务状态、测试、规则校验和用户确认。
- 过程证据：工具调用、决策路径、重试、人工修改和停止原因。
- 质量证据：成本、延迟、安全、可维护性和长期价值。

原始网页、邮件、工具输出和模型自评均视为不可信候选证据，不能直接写入正式能力。

### 3. 四类更新载体的选型

给出统一决策矩阵：

- 知识：事实、案例、可检索经验。
- 指令或 Skill：可用自然语言描述、需要模型判断何时应用的策略。
- 程序或 Harness：规则稳定、需要确定性执行和验证的流程。
- 模型参数：跨任务、隐式、规模化且有足够数据支撑的行为能力。

默认选择最小、最容易归因和回滚的修改，不把所有 bad case 都升级成微调或全局 Prompt 规则。

### 4. 在线执行与离线进化双循环

使用本站原创 ASCII 架构图表达：生产 Agent 只执行稳定版本并记录不可变证据；离线进化控制面负责聚合、诊断、生成候选、验证、审批和发布。两条循环通过版本化轨迹库、能力仓库和评测集连接。

### 5. 候选能力生命周期

定义 `proposed -> validated -> canary -> active -> deprecated/rolled_back` 状态，说明每一步的责任、输入和门禁。候选知识、Prompt、Skill、代码和参数均不得直接覆盖生产版本。

### 6. 验证与指标

同时验证“更新器提出了好修改”和“任务 Agent 能正确激活并遵循修改”，避免只看一个端到端总分。核心指标包括：

- 候选修改有效率。
- 产物激活率与规则遵循率。
- 留出任务增益和旧能力回归率。
- 安全退化、负迁移、成本与延迟变化。
- 人工接管率、回滚率和长期维护复杂度。

### 7. 安全边界与失败模式

重点覆盖提示注入固化、奖励投机、幸存者偏差、自评自批、Prompt 或 Skill 膨胀、灾难性遗忘和验证器污染。验证器、测试门槛、权限策略、审计日志和稳定版本备份构成可信根，普通进化流程不可修改。

### 8. 离线整理与能力保鲜

说明按时间、轨迹数量、错误率或容量触发的离线整理：合并重复经验、处理冲突、重建索引、标记过期能力、重新验证长期未使用工具并保留来源与回滚版本。“睡眠学习”只作为离线整合的类比，不承诺无监督自我升级。

### 9. 系统设计题与面试表达

设计一个“企业客服 Agent 持续改进平台”，要求能够从线上失败和人工纠正中生成候选 Skill/Harness 修改，但不能让单次用户输入直接改变生产策略。页面给出参考架构、数据流、发布门禁、指标和事故处置，并收尾于项目讲法模板与高频追问。

### 10. 与已有专题分工及参考资料

列出站内交叉链接，注明本页只负责能力更新生命周期。参考资料优先引用原始论文或官方资料；PDF 作为本轮主题启发来源列入延伸阅读，但不复制其特色表达或案例数据。

## 写作与质量标准

- 正文约 220 至 300 行，保持近期专题的密度。
- H1 后用引用块给出页面定位和核心结论。
- 使用中文编号 H2、对比表、ASCII 架构图、状态流转和一段结构化数据示例。
- 每个抽象原则至少配一个企业场景或失败案例。
- 不虚构产品能力、论文结论或具体提升数字；无法回溯原始来源的数据不写入。
- 内部链接使用 VitePress 无扩展名绝对路径，并人工核对目标文件存在。
- 不修改或提交 `outputs/` 与无关未跟踪文件。

## 验收标准

- 新页面清楚回答“学什么、改哪里、如何验证、怎样发布、何时回滚”。
- 与 Agent 记忆、评估、上下文、耐久执行页面有明确分工，无大段重复。
- 顶部 Agent 菜单与 `/agent/` 侧栏都能访问新页面。
- 页面包含双循环、更新载体选型、候选生命周期、可信根、指标、失败模式、系统设计题与高频追问。
- `git diff --check` 通过。
- `npx vitepress build docs --outDir ../.vitepress-build-check` 通过，随后删除 `.vitepress-build-check`。
- 提交只包含设计说明、目标文档和导航配置；`outputs/` 不进入任何提交。
