# 知识蒸馏与模型压缩

## 总览

模型压缩是将大型神经网络模型压缩到更小尺寸的技术集合，目标是在尽可能保持精度的前提下减少显存占用、加快推理速度、降低部署成本。

```
模型压缩四大方向
├── 量化（Quantization）—— 降低参数位宽
├── 剪枝（Pruning）—— 移除冗余参数/结构
├── 知识蒸馏（Knowledge Distillation）—— 大模型指导小模型
└── 低秩分解（Low-rank Decomposition）—— 矩阵近似
```

> 本文按“学习更小模型→改变结构→降低位宽”阅读，但组合顺序并非固定。先冻结质量切片、内存峰值与 SLO；没有模型、数据与 kernel 配置，不承诺掉点百分比、缩减比例或提速倍率。

## 知识蒸馏（Knowledge Distillation）

### 核心原理

知识蒸馏通过将大型复杂模型（**教师模型**）的知识迁移到小型简单模型（**学生模型**），使学生模型能够继承教师模型的性能。

```
教师模型（Teacher）
    │ 
    │ 软标签（Soft Labels）+ 温度 T
    ▼
学生模型（Student）
    │
    │ 同时学习：硬标签（真实标签）+ 软标签（教师输出）
    ▼
轻量级高性能模型
```

### 数学公式（面试高频）

**软标签生成（温度缩放）**：

```
p_i = exp(z_i / T) / Σ_j exp(z_j / T)
```

- T > 1 时分布更平滑，保留更多类间关系信息（"暗知识"）
- T = 1 退化为标准 softmax

**总损失函数**：

```
L_total = α · T² · KL(p_teacher^T || p_student^T) + (1-α) · CE(y, p_student^(T=1))
```

- α 控制软标签与硬标签的权重比
- KL 方向为教师到学生；温度作用于双方，硬标签项通常用 T=1。T² 用于补偿软目标梯度约随 1/T² 缩小的尺度，不是温度越高“知识越多”的保证。
- logits 蒸馏需要可对齐的词表和同一条件前缀；tokenizer 不同不能直接按 vocab 索引做 KL。序列蒸馏用教师生成文本作为训练目标，能用于只提供生成 API 的教师，但没有全部软分布。

公式依据 [Hinton 等原论文第 2 节](https://arxiv.org/html/1503.02531v1)。若实现未乘 T²，应报告它如何通过权重/学习率重新调节，不能和同 α 的温度实验直接比较。

### 蒸馏流程

1. **教师模型训练**：训练大型高性能教师模型
2. **学生模型设计**：选择更小的架构（层数/宽度缩减）
3. **蒸馏训练**：用教师模型的 logits 作为额外监督信号
4. **微调**：在目标任务上进一步对齐

### 蒸馏类型

| 类型 | 知识来源 | 典型方法 |
|------|----------|----------|
| Logit 蒸馏 | 输出层概率分布 | 经典 Hinton 蒸馏 |
| Feature 蒸馏 | 中间层特征表示 | FitNet / PKT |
| Attention 蒸馏 | 注意力权重分布 | TinyBERT |
| 关系蒸馏 | 样本间关系 | RKD |

### 工业界案例

**DeepSeek 蒸馏实践**：
- [DeepSeek-R1 官方说明](https://github.com/deepseek-ai/DeepSeek-R1)描述使用 R1 生成的推理数据微调 Qwen/Llama 稠密基座，包含 32B/70B 等学生；这不是直接裁剪 671B 专家权重，也不是已证明通过 logits KL 蒸馏。
- 没有同质量、同硬件、同负载对照，不引用原文未支持的成本/延迟/显存倍率。32B FP16 裸权重就约 64 GB，不能声称整个此类模型占 8 GB 而不说明低比特、卸载和模型规模。

**DistilBERT**：
- 从 BERT-base（110M）蒸馏为 DistilBERT（66M）
- [DistilBERT 论文](https://arxiv.org/abs/1910.01108)在其语言理解和运行设置下报告尺寸下降、97% 能力保留和 60% 更快；不是任意生成服务的质量或时延保证。

## 剪枝（Pruning）

### 剪枝分类

```
剪枝策略
├── 非结构化剪枝（Unstructured）
│   ├── 权重级别：直接将小权重置零
│   └── 优点：压缩率高；缺点：需要稀疏硬件支持
├── 结构化剪枝（Structured）
│   ├── Channel 级：移除整个通道/注意力头
│   ├── Layer 级：移除整层 Transformer 块
│   └── 优点：不依赖特殊硬件；缺点：压缩率相对较低
└── 半结构化剪枝（Semi-structured）
    └── N:M 稀疏（如 2:4）：NVIDIA A100+ 硬件原生支持
```

### 重要性评估准则

| 准则 | 方法 | 说明 |
|------|------|------|
| 幅度准则 | L1/L2 范数 | 权重绝对值小 → 不重要 |
| 梯度准则 | Taylor 展开 | 移除对 loss 影响最小的参数 |
| 信息准则 | Fisher 信息 | 基于参数的信息量 |
| 激活准则 | 注意力分数 | 注意力权重低 → 可剪枝 |

### KV Cache 剪枝（2025-2026 前沿）

针对推理阶段 KV Cache 显存占用过大的问题：

KV 通道裁剪与 token 驱逐是不同方法：前者改变表示维度，后者删除可访问历史。原先未注明论文/模型的 K、V 压缩百分比不作事实保留；任何方案需提供预算、掩码、kernel 对齐、训练/校准成本与长上下文任务对照，见 [KV Cache 专题](/inference/kv-cache)。

### 注意力层剪枝

- **FastV**：发现图像 Token 在 LLM 深层获取的注意力极低，可在浅层后大幅修剪
- **StreamingLLM**：仅保留 Attention Sink + 滑窗 token 的 KV

## 量化（Quantization）

### 数据类型对比

| 类型 | 位宽 | 指数位 | 尾数位 | 特点 |
|------|------|--------|--------|------|
| FP32 | 32 | 8 | 23 | 完全精度 |
| FP16 | 16 | 5 | 10 | 精度高，范围小 |
| BF16 | 16 | 8 | 7 | 范围大，精度低（深度学习首选） |
| FP8 (E4M3) | 8 | 4 | 3 | 训练推理兼用 |
| INT8 | 8 | — | — | 推理加速 |
| INT4 | 4 | — | — | 极致压缩 |

> BF16 的指数位与 FP32 相同，但尾数精度不同；常能减少 FP16 的下溢风险，不代表过参数化会自动弥补误差。仍须检查累积精度、溢出、loss 与任务回归。

### 主流量化方法

| 方法 | 类型 | 精度保持 | 速度 | 适用场景 |
|------|------|----------|------|----------|
| GPTQ | 二阶近似 PTQ | 需测 | kernel/shape 决定 | 低比特权重 |
| AWQ | 激活感知 PTQ | 需测 | kernel/shape 决定 | 低比特权重 |
| GGUF | 模型容器 | 由内部量化类型决定 | backend 决定 | 本地部署格式 |
| SmoothQuant | 等价平滑后 PTQ | 需测 | INT8 kernel 决定 | W8A8 |
| QLoRA | 冻结量化基座的 LoRA 微调 | 依训练评测 | 推理与训练分开 | 不等于更新量化基座的常规 QAT |
| FP8 训练 | 低精度训练配方 | 依累积/尺度评测 | 硬件/kernel 决定 | 不自动等同伪量化 QAT |

### 显存估算公式（面试必考）

**推理显存**：

```
模型参数显存 = 参数量(B) × 每参数字节数
FP32: 1B → 4GB
FP16/BF16: 1B → 2GB  
INT8: 1B → 1GB
INT4: 1B → 0.5GB

实际显存 = 权重 payload + 量化元数据/未量化层 + KV + 工作区/常驻/碎片
```

**KV Cache 显存**：

```
KV Cache = 2 × n_layers × n_heads × head_dim × seq_len × batch_size × 字节数
7B 模型 (32层, seq_len=4096, batch=1, FP16):
= 2 × 32 × 32 × 128 × 4096 × 1 × 2 bytes = 2 GiB ≈ 2.147 GB
```

### 混合精度训练要点

- 前向/反向：FP16/BF16（节省显存和计算）
- 参数主副本：FP32（保证梯度累积精度）
- Layer Norm：建议 FP32（需要精确的均值/方差计算）
- 优势：大 batch 下速度更快（小 batch 瓶颈在 IO，差异不大）

## 低秩分解

将大权重矩阵 W(m×n) 分解为两个小矩阵的乘积 W ≈ A(m×r) × B(r×n)，其中 r << min(m,n)。

- **SVD 分解**：经典方法，直接对权重矩阵做奇异值分解
- **LoRA 边界**：冻结完整原矩阵，只学习低秩增量 ΔW=AB；不是把 W 本身替换成低秩矩阵。合并后仍保留完整 W，不能说自动压缩基座权重。
- 若把 W 替换为两个低秩矩阵，参数从 mn 变为 r(m+n)，仅当 r<mn/(m+n) 才减少；两次 GEMM 及中间张量仍可能抵消 FLOPs 收益。构造 m=n=4096、r=512，参数约为原来的 1/4，但任务误差和实际时延另测。

## 组合压缩策略（工程最佳实践）

```
候选组合（非已验证配置）：
教师输出 → 学生训练 → 独立质量门禁
         → 结构/低比特候选 → 再做质量与 kernel 压测
         → 服务调度/可选投机 → SLO goodput 与总成本验收
```

## 高频面试追问

1. **知识蒸馏中温度 T 的作用？T 太大或太小有什么问题？**
   - T=1 是普通 softmax，仍是软概率，不是硬标签；T 太大可能抹平有用差异，T 太小接近尖锐分布，需比较带 T² 的损失与验证质量。

2. **量化为什么能加速而不只是省显存？**
   - 降低了数据传输量（memory-bound 瓶颈），INT8/INT4 运算有专用硬件加速（Tensor Core）

3. **GPTQ 和 AWQ 的核心区别？**
   - GPTQ 用二阶信息（Hessian）逐列量化；AWQ 根据激活值分布找重要通道，保护这些通道的精度

4. **QLoRA 为什么能在量化的同时进行微调？**
   - 基座以低比特存储且冻结，但反向需通过基座运算传播到 LoRA；NF4 不是普通 INT4，计算 dtype 需按实现配置，见 [QLoRA 原论文](https://arxiv.org/abs/2305.14314)。

5. **结构化剪枝和非结构化剪枝的实际部署差异？**
   - 非结构化稀疏需专用存储/kernel；随机稀疏不等于满足 2:4。结构化减少维度也可能破坏 kernel 对齐而不提速，两者均需实测。

6. **显存不够部署 70B 模型，有哪些方案？**
   - 70B INT4 裸权重约 35 GB，仍加元数据/KV；比较多卡、卸载与重新训练学生。现成稠密模型不能靠“打开 MoE 稀疏激活”直接省内存。

## 压缩实验怎样验收

冻结教师/学生与数据血缘，分离教师生成训练集和最终测试集；教师输出的错误、风格和污染会传给学生。量化与剪枝每一步记录质量变化，再测组合，收益不能简单相乘。报告压缩文件大小、加载后峰值、prefill/decode、达标 requests/s 与每完成任务成本，构造参数比不冒充真实 benchmark。
