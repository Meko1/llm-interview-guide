# GPU 与硬件基础

> 「7B 模型推理要多大显存？」「为什么大模型训练/推理都得用 GPU？」「A100 和 H100 怎么选？」——硬件是大模型工程岗的硬通货考点。本文把显存、算力、通信讲清楚。

## 为什么是 GPU？

Transformer 的主要计算包括大量矩阵乘，适合并行加速；但占比随模型、长度和 batch 改变。GPU/TPU/NPU 常用于高吞吐训练与推理，CPU 也可运行量化模型；选择依据目标延迟、成本和容量，而不是“必须 GPU”。

GPU 内部还有专门加速矩阵乘的 **Tensor Core**，对 FP16/BF16/FP8 等低精度矩阵运算有数量级加速。

## 显存：最稀缺的资源

显存（HBM）往往比算力更早成为瓶颈。两个核心场景：

### 推理显存

主要 = **模型权重 + KV Cache + 激活**。权重的粗算：

$$\text{权重显存} \approx \text{参数量} \times \text{每参数字节数}$$

| 精度 | 每参数字节 | 7B 模型权重 | 70B 模型权重 |
| --- | --- | --- | --- |
| FP32 | 4 | ~28 GB | ~280 GB |
| FP16/BF16 | 2 | ~14 GB | ~140 GB |
| INT8 | 1 | ~7 GB | ~70 GB |
| INT4 | 0.5 | ~3.5 GB | ~35 GB |

> 表中 B=10^9 参数、GB=10^9 字节，只计原始权重 payload。INT4 还需 scale、zero-point、padding 和未量化层；FP16 的 7B 权重约 14 GB / 13.04 GiB，不代表 16 GB 卡一定能部署。KV、工作区、框架常驻与碎片必须另算，不能统一预留一个百分比。

### 训练显存

远大于推理，= 参数 + 梯度 + 优化器状态 + 激活。用 Adam + 混合精度时，**「参数+梯度+优化器状态」约为参数量的 16 倍**（详见 [分布式训练](/pretraining/distributed-training)）。所以 7B 模型全参训练动辄上百 GB，需要多卡 + ZeRO/并行。

## 算力与通信

- **算力（FLOPS）**：每秒浮点运算数，看的是低精度（如 BF16/FP8）的 Tensor Core 算力。训练计算量经验公式 `C ≈ 6 × 参数量 × token 数`。
- **显存带宽**：小 batch decode 常受权重/KV 访存限制；大 batch、长上下文或多卡时也可能转为计算/通信瓶颈，详见 [推理优化](/inference/inference-optimization)。
- **卡间通信**：高频 TP 优先放高速互联域；机内/跨机边界和卡数并非绝对限制，需记录拓扑并测有效 collective 带宽。

> **大模型工程三要素：显存（装得下）、算力（算得快）、通信（同步得快）**，三者协同决定系统上限。

## 常见 GPU 选型

| GPU | 显存 | 定位 |
| --- | --- | --- |
| **B100 / B200** | 按具体 SKU 数据表核验 | Blackwell；FP4 支持不等于所有层可无损低比特计算 |
| **GB200** | 按超级芯片/整机 GPU 数分别核验 | CPU+GPU 系统，不能把整机聚合容量当单 GPU 容量 |
| **H100 / H200** | 区分 SXM、PCIe、NVL 等形态 | Hopper；带宽、功耗与互联配置不同 |
| **A100** | 按具体 40/80 GB 形态核验 | 比较任务实测成本，不从代际直接推断性价比 |
| **RTX 4090 / 5090** | 按设备与驱动信息核验 | 本地部署需核散热、互联、许可与运行环境要求 |
| **L20 / L40S** | 按 SKU 核验 | 服务吞吐需同负载、同精度对照 |
| 国产（昇腾等） | — | 国产化替代方案 |

> 官方 [Blackwell 架构页](https://www.nvidia.com/en-us/data-center/technologies/blackwell-architecture/)介绍 FP4 与 Transformer Engine；硬件格式能力不是模型质量或端到端提速保证。[H100 官方页](https://www.nvidia.com/en-us/data-center/h100/)的性能比较也附模型、网络和实验/预测口径。未对齐这些配置，不转述营销倍数为自己的 benchmark；采购须核当前数据表、供应和适用许可。

选型看：显存够不够装模型 + KV Cache、算力/带宽、是否需多卡 NVLink、预算、供货与合规。

## 高频追问

**Q：7B 模型推理需要多少显存？** FP16 权重 payload 约 14 GB；再按 KV 头数、长度、并发、精度计算 KV，并测 workspace/常驻/碎片。INT4 仅权重 payload 约 3.5 GB，不能把它当整个服务显存。

**Q：为什么大模型必须用 GPU 而不是 CPU？** 大模型计算以大规模并行矩阵乘为主，GPU 有上万核心 + 专用 Tensor Core，能同时算海量数据；CPU 核少、偏串行，跑大模型会慢几个数量级。端侧小模型量化后可用 CPU（如 llama.cpp）。

**Q：训练显存为什么比推理大那么多？** 推理只需权重 + KV Cache + 激活；训练还要存梯度和优化器状态（Adam 的一二阶矩），用混合精度时「参数+梯度+优化器状态」约为参数量的 16 倍，再加要保留的激活，所以训练显存远高于推理。

**Q：decode 一定是显存带宽瓶颈吗？** 小 batch 稠密模型常如此，但权重可跨请求摊销、MoE 每 token 只激活部分专家，缓存和融合也改变流量。用实际 kernel 与通信 trace 判断，不把理论读一遍当精确访存量。

**Q：A100 和 H100 怎么选？** 先过显存、kernel 和供货合规门禁，再在实际精度、长度和到达率下比较达标容量与每完成任务成本；更高峰值不保证更低账单。

**Q：Blackwell 相比 Hopper 怎么比较？** 区分单 GPU、超级芯片和整机，核对具体 SKU 的容量、带宽、精度、互联与功耗；FP4 的精度回归和 SLO goodput 必须实际测试，不能套统一倍率。

## 用 roofline 做第一步判断

算术强度 `I=FLOPs/搬运字节`，理想有效算力上界约为 `min(峰值 FLOP/s, 有效带宽×I)`。构造 14 GB 权重、有效读取带宽 1 TB/s，忽略 KV、启动和通信，读一遍的下界为 14 ms；这是教学下界，不是 7B 的实测 TPOT。batch 增大可摊销权重读取，但可能增加排队与逐 token 延迟。

选卡交付物应包含权重/KV/工作区峰值账本、prefill/decode 分开压测、硬件 SKU 与驱动版本、同质量量化回归和 [SLO 达标吞吐](/inference/slo-goodput)。

**Q：NVLink 和 InfiniBand 有什么用？** NVLink 是**机内卡间**高速互联，InfiniBand/RoCE 是**机间**高速网络。多卡并行（尤其张量并行）需频繁同步，通信带宽直接决定并行效率，所以通信密集的并行要放在 NVLink 机内，跨机用高速网络。
