# 投机解码（Speculative Decoding）

## 为什么需要投机解码

自回归 decode 常偏访存密集，但瓶颈与端到端占比取决于输入/输出长度、batch、硬件、缓存和并行通信。投机解码试图减少串行目标前向的等待，收益需要按负载验证，不能给出通用阶段占比。

投机解码的核心动机：**先低成本提出候选，再用目标模型批量验证，减少串行目标前向次数。** 草稿可以来自小模型、附加预测头或检索，不必总是独立的小模型。L1 先读流程，L2 重点核算显存与 SLO，L3 继续读分布保证和验证实验。

## 核心原理

深读 [投机采样的分布保证](/inference/speculative-sampling-proof)：接受概率、拒绝后残差、状态一致性与轮次成本。下面的算法家族与框架是背景线索，支持范围与倍率需要固定版本和实际负载另行验证。

### 草拟-验证机制（Draft-Verify）

```
┌─────────────────────────────────────────────┐
│  阶段一：Draft（草拟）                        │
│  草稿机制提出 K 个候选 token                  │
│  t₁, t₂, t₃, ..., tₖ                       │
├─────────────────────────────────────────────┤
│  阶段二：Verify（验证）                       │
│  大模型一次前向传播并行验证 K 个候选          │
│  按各候选前缀计算目标概率并逐位检验           │
│  首次拒绝 → 残差采样 → 撤销未提交候选状态     │
└─────────────────────────────────────────────┘
```

正确的接受与拒绝后残差采样，在论文假设和数值精度范围内恢复目标分布；不代表每次输出文本完全相同，也不代表所有投机变体都有相同保证。贪心一致、概率分布和运行时数值稳定性需要分别核查。

### 接受率与加速收益

- **接受率 α**：小模型生成的 token 被大模型接受的概率
- 在固定独立接受率 α、验证约等于一次目标前向等假设下，每轮期望输出为 1+α+…+α^K；简化速度比为该值 / (1+Kc)，c 为单步草稿/目标耗时比。α=1 时用 K+1。
- 实际收益还要计入随 K 变化的验证成本、同步、采样、回退和调度。完整公式、反例与构造计算见 [轮次成本账本](/inference/speculative-sampling-proof)。
- 接受率依赖实际草稿/目标分布、前缀与采样规则，不能仅凭低温或输出格式推断高接受率和正收益。

**构造复算**：令 K=4、α=0.8，独立同接受率近似给出每轮平均提交 `1+0.8+0.64+0.512+0.4096=3.3616` 个 token。若普通目标单步 10ms、草拟合计 2ms、验证 18ms、其他开销 2ms，则估算速度比为 `3.3616×10/22≈1.53`，不是 3.36 倍。这是教学账本，不是框架实测；真实前缀上的接受事件并不独立，应用实测轮次提交数替代近似。

## 主流算法家族

### 1. 独立草稿模型（Independent Drafting）

通常使用能生成目标 token 空间候选的小模型；“同系列”只是方便部署和对齐的候选，不是算法保证。

| 路线 | 主要成本 | 应验证什么 |
| --- | --- | --- |
| 独立小模型 | 草稿权重、KV、逐步前向与调度 | 目标分布对齐、接受率和每轮提交数 |
| [DistillSpec](https://arxiv.org/abs/2310.08461) | 蒸馏数据与训练，以及运行时草稿 | 数据分布、散度目标与解码策略的配合 |
| [REST](https://arxiv.org/abs/2311.08252) | 检索库、查询、候选构造与验证 | 任务中的重复模式、检索耗时和数据治理 |

**接口约束**：本页标准 token 级采样需要目标 token ID 空间中的候选及对应前缀上的草稿概率。共享 tokenizer 和词表简化接口；跨 tokenizer 方法需要另外的映射与概率处理，不能把“同词表”写成整个领域的绝对限制。REST 不是独立神经草稿模型，只是另一类候选来源。

### 2. Medusa（多头并行预测）

在目标模型主干上附加 K 个 Medusa 头，**并行预测**未来第 1、2、...K 位置的 token：

```
目标模型主干 ──┬── Medusa Head 1 → 预测 t+1
               ├── Medusa Head 2 → 预测 t+2
               ├── Medusa Head 3 → 预测 t+3
               └── ... → 预测 t+K
```

- **Tree Attention**：按选定树结构组织候选和可见性，并行验证多条续写；不意味着枚举无限笛卡尔积。
- **Medusa-1**：冻结主干，训练附加头。
- **Medusa-2**：联合训练主干与头，需将改变后的目标模型重新纳入质量基线。

[原论文](https://arxiv.org/abs/2401.10774) 比较了这些训练形态。树验证与某种接受规则是否保留采样分布，应逐项核对算法；不能把所有 Medusa 配方统称为与原模型任意采样完全等价，也不把论文配置中的倍率搬到生产。

### 3. EAGLE 系列（特征层投机）

EAGLE 系列利用目标模型特征辅助草稿，但不同代际不能用一句“预测隐藏特征”概括：

- 早期 EAGLE 以目标模型顶层特征为基础进行特征层自回归。
- EAGLE-2 研究动态草稿树，使候选结构适应接受倾向。
- [EAGLE-3](https://arxiv.org/abs/2503.01840) 明确改为直接 token 预测，并使用多层特征融合与 training-time test。其训练目标与早期特征预测不同。

附加训练、特征传递与树验证都有成本。先确认目标 checkpoint、草稿权重和运行时支持，再测同请求分布的收益，不直接许诺某参数量上的倍率。

### 4. PLD（Prompt Lookup Decoding / N-Gram）

对于输入输出高度重叠的任务（RAG 摘要、翻译等），直接从 prompt 中查找 N-gram 匹配作为候选：

- **无需额外草稿模型**：不等于无需查询、验证或缓存成本
- 适用场景：RAG 中引用原文、文档摘要、代码补全
- 无需独立草稿模型，但候选查询、验证、缓存与调度仍有开销；是否适合取决于输入重复模式和同负载测量。

<span id="_5-adaspec-选择性-token-蒸馏-2026"></span>

### 5. 选择性 token 蒸馏与数据配比

蒸馏是优化草稿与目标的对齐，不是只看草稿独立答题分数。选择性过滤可作为实验变量，但过滤“困难 token”也可能丢掉任务关键边界；应比较同预算下的验证成本、接受率与尾延迟。DistillSpec 原论文强调数据生成分布及散度选择与任务/解码策略的匹配，不支持“所有模型、任务都更好”的外推。

面试中先明确目标模型是否被冻结、数据来自谁、是否包含评测泄漏，再讨论草稿训练。若目标模型也改变，质量保持与推理加速必须分开验证。

## 工程实践要点

### 框架支持

| 官方入口 | 需要按所用版本核对 |
| --- | --- |
| [vLLM](https://github.com/vllm-project/vllm) | 目标/草稿架构、采样限制、并行方式与 scheduler |
| [SGLang](https://github.com/sgl-project/sglang) | 草稿权重、树配置、量化与服务负载支持 |
| [TensorRT-LLM](https://github.com/NVIDIA/TensorRT-LLM) | engine 构建、运行时特性与硬件条件 |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | 目标/草稿加载、tokenizer、设备和内存预算 |

这些是检索入口，不是本轮已逐项测试的兼容表。部署记录固定 tag/commit、命令、模型 revision 和回滚基线，不能只记框架名。

### 调优建议

1. **扫描 K 与负载**：记录验证成本和平均提交 token，不把固定 K 范围当通用最优。
2. **监控接受率**：记录 Draft/Verify 各阶段计时、接受率
3. **场景适配**：
   - 分别测试任务、温度、前缀与并发的接受率分布
   - 结构化输出不自动意味着高接受率，接受率高也不保证收益大
4. **重点监控尾延迟（P95/P99）**，排查收益失常的瓶颈

### 局限性

- **分布偏移**：草稿与目标对新任务的分布可能不再对齐，需看任务分组接受率。
- **长上下文**：验证、草拟与 KV 成本增加，收益不能从短输入外推。
- **解码规则改变**：温度、top_p、结构约束会改变概率分布，接受率不必单调变化。
- **额外显存**：权重或头之外还需草稿 KV、候选树与临时缓冲。
- **状态错误**：拒绝后未撤销候选 KV、重复提交或随机状态不一致，可能同时破坏质量与正确性。

## 高频面试追问

1. **投机解码为什么能做到无损加速？验证阶段的数学保证是什么？**
   - 接受后保留 min(p,q) 的概率质量，拒绝时从归一化的正差残差补回目标分布；多步还需前缀、缓存与采样状态一致。数值与 batch 差异仍需验证。

2. **接受率 α 受哪些因素影响？如何提升？**
   - 草稿模型质量、温度设置、领域匹配度；可通过蒸馏/微调提升草稿模型与目标模型的分布对齐

3. **Medusa 和 EAGLE 的核心区别？**
   - Medusa 用附加头提出未来 token；早期 EAGLE 预测特征，EAGLE-3 改为多层特征辅助的直接 token 预测。速度优劣取决于配置与负载。

4. **什么时候投机解码反而会变慢？**
   - 每轮新增成本超过提交 token 节约的目标计算时；低接受率、昂贵草稿或高负载资源竞争都是需要测量的原因。

5. **生产环境中如何选择投机解码方案？**
   - 先固定目标模型与质量基线，再筛掉不支持所需采样/并行特性的方案；在实际请求长度与并发下扫描 K，并比较 TTFT、TPOT、达标 goodput、显存和回滚成本。
