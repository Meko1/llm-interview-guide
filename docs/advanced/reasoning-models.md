# 推理模型与慢思考（Test-time Compute）

“慢思考”是直觉，不是人格或能力保证。这里研究的是：训练怎样改变模型的解题策略，推理阶段怎样分配计算，以及额外预算什么时候值得。服务侧方法见 [推理时算力扩展](/inference/test-time-scaling)。

## 什么是推理模型？

推理模型通常经过后训练，鼓励在回答前产生中间推导、检查或工具交互。可见 CoT、隐藏推理 token、并行采样和服务路由是不同层面的机制；界面的 Thinking 开关不证明后台由单一模型实现。

DeepSeek-R1 是本文的具体训练案例。o 系列、QwQ/Qwen、Gemini thinking、Claude extended thinking 等旧名称保留为阅读线索，不作为完整当前目录。不能从产品名字推断训练算法、隐藏链完整性或任务排名。

## 核心思想：Test-time Compute（推理时计算）

额外计算可以花在串行推导、并行候选、验证、工具执行或搜索上。[推理时计算研究](https://arxiv.org/abs/2408.03314) 比较过程验证搜索和按问题调整回答分布，强调收益取决于题目难度。它不是“想越久必然越正确”的定理。

```
训练时扩展：更大模型 + 更多数据 ──▶ 更强（贵在训练）
推理时扩展：同一模型 + 更长思考 ──▶ 更强（贵在每次推理）
```

原直觉图保留；箭头应读作“在适当数据/算法/预算下可能提升”，而非无条件因果。训练能改变能力与采样分布，推理只能在已有分布与工具能力上搜索；若正确路径极少或 verifier 错误，追加预算可能没有收益。

**构造预算账本**：四个候选各 600 token，验证每个再用 100 token，最终答案 200 token，总计 $4(600+100)+200=3000$ token。四候选可并行不意味着只付 900 token；墙钟延迟可以下降，GPU 总工作与费用未必下降。单个 3000-token 链与上述方法也不是同延迟基线。

若每次独立采样正确率 $p=0.4$，四次至少一次正确的概率 $1-(1-p)^4=0.8704$，但这是**有正确候选**而非**选出正确答案**。构造 verifier 在有正确候选时选对概率为 0.8，则最终成功率仅 $0.8704\times0.8=0.69632$；独立性、候选相关性和选择准确率必须实测。多数投票还要求答案可归一化且正确答案占优。

## 怎么训出推理能力？

### 强化学习 + 可验证奖励（RLVR）

RLVR 用可执行的判定函数给奖励，例如数学答案校验、隔离环境中的代码测试。它优化的是 verifier 认可的结果，不是所有真实正确性：有限测试可能漏 bug，答案解析器可能接受格式投机，训练测试泄漏可能产生假提升。

[R1 论文](https://arxiv.org/html/2501.12948v1) 区分：

| 路线 | 方法边界 | 不意味着什么 |
| --- | --- | --- |
| R1-Zero | 从已经预训练的 V3-Base 开始，以 GRPO 做推理 RL，不先做该阶段 SFT | 不是从随机权重、不用数据或 verifier |
| R1 | cold-start SFT、推理 RL、拒绝采样/SFT及后续对齐阶段 | 不是只用一个奖励/单轮训练 |
| 蒸馏小模型 | 使用筛选的教师样本做 SFT | 原论文蒸馏模型不包含 RL 阶段 |

GRPO 用同问题组内反馈估计基线，省去单独 critic；旧策略用于重要性比率，参考策略可用于 KL，二者不等同。组内全对/全错时相对信号可能为零。

DAPO 原论文的四项重点是 **Clip-Higher、Dynamic Sampling、Token-Level Policy Gradient Loss、Overlong Reward Shaping**；去掉 KL 是其设计讨论之一，不应替换超长奖励整形成为“四项”中的第四项。token 级分母不等于得到了真实步骤级奖励。详见 [偏好优化谱系](/finetuning/frontier-alignment)。

### 过程奖励 vs 结果奖励

| 反馈 | 优点 | 失效模式 | 验证 |
| --- | --- | --- | --- |
| ORM | 终局结果易定义 | 蒙对、测试漏洞、稀疏信号 | 独立题集、隐藏测试、解析失败审计 |
| PRM | 对中间步骤提供信号 | 步骤切分歧义、局部正确但全局无效 | 人工步骤参照、跨模板误判和搜索收益 |

PRM 可在推理时给候选打分，不必用于策略训练。Qwen-Math-PRM、ProcessBench、OpenMathReasoning 等作为后续索引保留，本文不据此声称某数据规模或 PRM 的普遍优势。

### 蒸馏（Distillation）

教师输出经过筛选再用于学生 SFT，是把昂贵探索转成训练数据。R1 原论文第 2.4 节明确其蒸馏模型只做 SFT；不能将特定基线比较外推为“小模型做 RL 永远不如蒸馏”。

数据交付应记录教师版本、prompt、采样温度、过滤器、去重、题目隔离与错误率。学生可能学到格式、冗长和教师错误；训练 loss 下降不证明推理增益，要加入答案匹配但错误解释、短链和未见模板对照。

## 推理时还能怎么「加算力」？

| 预算去向 | 适用前提 | 测什么 |
| --- | --- | --- |
| 增加串行链长 | 能持续改善而非重复 | 质量—token 曲线、截断率 |
| Self-Consistency | 可归一化的答案与有效多样性 | 正确候选占比、相关性 |
| Best-of-N | verifier 能区分质量 | 选择后的准确率，不仅 oracle pass@N |
| 搜索 + PRM | 中间状态可判断和分支 | 搜索预算、重复状态、错误剪枝 |
| 工具辅助 | 可验证外部结果且权限受控 | 调用延迟、错误传播、禁止动作 |

预算策略先在验证集定阈值，再在未参与选择的测试集验收。对简单题、证据不足题和 verifier 不可靠题，限额/直接回答/拒答可能比继续搜索更合适。

## 推理模型 × Agent：边界正在消失

保留旧标题，但**推理能力和行动权限仍有明确边界**。模型提议工具动作，运行时执行并返回观测；网络检索结果不是“内部思考真值”。多步任务需环境状态、失败恢复、幂等和授权，不能由长 CoT 自动获得。训练参见 [Agentic RL](/advanced/agentic-rl)。

比较 Agent 时把工具预算纳入总账，保存请求、工具结果和可回放状态；最终答对不能抵消未经授权的写入。这里不声称某产品“首次把工具放进思维链”。

## 高频追问

**SFT 不会产生推理能力吗？** 会，取决于数据、底座和泛化。SFT 模仿轨迹，RL 按奖励探索分布，二者不是能力有无的二分。

**长 CoT 忠实吗？** 可读理由不必对应真实决定因素。应改变证据/提示中的决定变量做反事实测试，并对照行为与解释变化；没有隐藏状态访问时须承认无法完整验证。

**怎样决定多想多久？** 使用留出集的边际质量收益、费用和 SLO 约束。最大 token 是上限而非实际消耗，也不保证达到阈值。

**DAPO 的动态采样有什么代价？** 过滤零方差组后需继续生成有效组，增加 rollout 成本且改变训练分布；要报告过滤率和总采样量，不能只报告优化步。
