# 一手资料阅读地图：从模型机制到工程验证

**不追求链接最多，而是每份资料都能回答一个具体问题。** 本批选择研究原作者论文、作者实现和框架官方工程材料；以“能解释、能核查、能做对照”为标准，不用热度、收藏量或榜单名次替代证据。

资料核对日期：2026-11-04。下文依据原始来源可检索摘要、相关原文段落或代码摘录组织，**不声称每篇论文已全文审校、所有实验已复现或所有链接已直接访问成功**。来源可靠不等于其所有结论可直接用于你的产品。

本轮增补（2026-11-05）保留原有十一条阅读路线，不把上一轮阅读记录升级为本轮全文验证。实际重新读取 DPO、污染检验、投机采样论文摘要，以及 HumanEval `estimate_pass_at_k` 函数；其余材料保留为既有索引，具体版本和章节需在自己的阅读卡中复查。

## 01 · 模型机制：Attention Is All You Need

**原始资料**：[Vaswani 等原论文](https://arxiv.org/abs/1706.03762)。

- **读它回答什么**：为什么用注意力替代循环式序列处理？原始 encoder-decoder Transformer 如何连接输入和输出？
- **证据是什么**：论文在机器翻译等实验中比较模型质量与训练效率；这是明确任务与配置下的结果。
- **没有证明什么**：原论文并不是所有现代 decoder-only 模型、位置编码、长上下文和 KV 优化的完整说明书。
- **站内实践**：[Transformer 数据流与分层自测](/basics/transformer)；给一个固定输入，标注向量形状与可见性，区分结构图和实际实现。

**追问**：当你说“Transformer 可以并行”时，指训练时处理已知序列，还是自回归生成未来 token？两者不能混用。

## 02 · 参数适配：LoRA

**原始资料**：[Hu 等原论文](https://arxiv.org/abs/2106.09685)。

- **读它回答什么**：冻结预训练权重、训练低秩增量，为什么能减少可训练参数？
- **证据是什么**：论文在指定模型与任务中比较低秩适配和全量微调，并研究适配增量的低秩特性。
- **没有证明什么**：低秩是适配假设，不是所有任务的质量保证；论文中的显存倍数也不是你部署配置的固定节省率。
- **站内实践**：[LoRA / QLoRA](/finetuning/lora)；分别列权重、增量、梯度、优化器、激活与工作区，不只统计可训练参数。

**追问**：增加 rank、改变目标层或不合并多适配器时，参数、质量和服务开销会怎样变化？不要把“可合并”说成任意部署都无额外代价。

## 03 · 偏好优化：DPO

**原始资料**：[Rafailov 等原论文](https://arxiv.org/abs/2305.18290)。

- **读它回答什么**：如何通过策略与参考模型的概率关系，将偏好学习写成可直接训练的目标？
- **证据是什么**：论文给出目标推导，并在情感控制、摘要和单轮对话等实验中比较偏好对齐。
- **没有证明什么**：不显式训练奖励模型，不代表偏好标签没有错误；训练流程更简单，也不代表任意任务都优于 PPO 或不需要调参。
- **站内实践**：[RLHF / DPO 目标与梯度](/finetuning/rlhf)；固定偏好数据、参考策略与验证集，观察偏好收益和能力退化，而不是只比较训练 loss。

**追问**：偏好数据偏向长回答、参考模型变化或 chosen/rejected 标签错误时，目标优化与业务收益是否仍一致？

## 04 · 证据生成：RAG 原论文

**原始资料**：[Lewis 等原论文](https://arxiv.org/abs/2005.11401)。

- **读它回答什么**：如何结合参数化生成模型和可检索的非参数记忆？RAG-Sequence 与 RAG-Token 的条件化有什么差别？
- **证据是什么**：论文使用神经检索与生成模型，在知识密集任务中进行训练与评估。
- **没有证明什么**：今天“向量库 + 拼接 Prompt”的应用不自动复现原论文方法；检索增强也不保证证据有效、权限正确或每个主张忠实。
- **站内实践**：[RAG 的证据链与分段评测](/rag/rag-basics)；加入旧版本政策、无证据问题和权限边界，定位证据在哪一步失效。

**追问**：答案碰巧正确但引用不支持主张，该按什么维度判定？回答正确与证据忠实需要分别检查。

## 05 · 裁判评测：MT-Bench 与 G-Eval

**原始资料**：[MT-Bench / Chatbot Arena 论文](https://arxiv.org/abs/2306.05685)、[G-Eval 论文](https://arxiv.org/abs/2303.16634)。

- **读它回答什么**：怎样检验模型裁判的偏差和与人工判断的关系，而不是直接相信分数？
- **证据是什么**：MT-Bench 分析特定裁判的位置等偏差；G-Eval 在摘要和对话任务中研究生成评判。
- **没有证明什么**：研究里的人工一致率或相关性不能原样迁移到中文政策、代码、安全或医疗任务；稳定判断也可能稳定地错误。
- **站内实践**：[裁判校准](/evaluation/judge-calibration)；恢复交换顺序后的候选身份，报告覆盖率、混淆矩阵与弃判原因。

**追问**：90% 的整体一致率，是否只是因为 90% 的样本本来就“通过”？哪些假阳性对业务最危险？

## 06 · Agent：任务结果与重复可靠性

**原始资料**：[Anthropic Agent 评测工程文章](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)、[OpenAI HumanEval 作者实现](https://github.com/openai/human-eval/blob/master/human_eval/evaluation.py)。

- **读它回答什么**：一次试验、最终状态与评判器如何区分？pass@k 为什么不能替代重复可靠性？
- **证据是什么**：前者提供工程术语与评测设计经验；后者提供每问题有限样本 pass@k 的具体估计代码。
- **没有证明什么**：HumanEval 是代码生成评测实现，不是 Agent 副作用和权限安全验证器；组合数不会自动处理相关试验与漂移。
- **站内实践**：[重复试验与 pass^k](/agent/repeated-trial-evaluation)；重置环境，按任务汇总，独立检查结果与禁止条件。

**追问**：工具写入已成功但响应超时，再执行一次是否会重复操作？评测环境是否可以安全复现这种故障？

**从公式读到统计对象**：HumanEval 的作者函数计算 $1-\binom{n-c}{k}/\binom nk$，先每题计算再聚合。构造同一题 $n=10,c=3,k=2$，得到 $1-21/45=8/15\approx0.5333$，指从这批样本中抽两份至少一份正确的比例；不能叫“两次都稳定成功”。如果另作独立同分布成功概率估计 $p=0.3$，两次都成功为 $p^2=0.09$。两种对象不同，不能用前者承诺后者。

复算时先检查 $0\le c\le n$、$1\le k\le n$，把每题的 $n,c$ 留下来；失败/超时是否算错误、是否允许人工选出正确候选，都属于评测协议。代码公式不负责保证这些前提，也不证明工具执行安全。

## 07 · 推理工程：vLLM 的指标实现

**原始资料**：[vLLM v0.19.1 服务压测实现](https://docs.vllm.ai/en/v0.19.1/api/vllm/benchmarks/serve/)。

- **读它回答什么**：TTFT、TPOT、单 token 请求和 request_goodput 在代码里究竟怎么算？
- **证据是什么**：指定版本的函数实现与统计分母，能比口头定义更直接地检查报告口径。
- **没有证明什么**：定义清晰不代表容量已经测出；某版本的统计约定也不必与别的工具或客户端一致。
- **站内实践**：[SLO 与 goodput 账本](/inference/slo-goodput)；保存失败、明确时间窗、区分请求吞吐与 token 吞吐。

**追问**：只输出一个 token 的请求没有后续 token 间隔，为什么报表里仍可能出现 TPOT=0？实现约定和数学定义怎样区别？

## 08 · 长上下文：位置诊断与 RULER

**原始资料**：[Lost in the Middle](https://arxiv.org/abs/2307.03172)、[RULER 论文](https://arxiv.org/abs/2404.06654)、[NVIDIA 作者实现](https://github.com/NVIDIA/RULER)。

- **读它回答什么**：窗口支持、证据访问和复杂任务理解为何不是同一种能力？
- **证据是什么**：前者通过位置对照分析特定任务；后者提供可配置的合成检索、多跳与聚合等任务。
- **没有证明什么**：不是所有模型都固定呈 U 形，也不能由单针检索推断全部业务理解能力；历史榜单不是当前选型结果。
- **站内实践**：[长上下文验证](/rag/long-context-validation)；固定证据，改变位置、长度和干扰，加入过期证据负例，记录实际 token 范围。

**追问**：你的“有效长度”对应什么任务、阈值和配置？平均分会不会隐藏中间位置失效？

## 09 · 数据可信度：污染检测的证据边界

**原始资料**：[Oren 等污染检验论文](https://arxiv.org/abs/2310.17623)、[tatsu-lab 作者实现](https://github.com/tatsu-lab/test_set_contamination)。

- **读它回答什么**：无法查看训练语料时，怎样在明确条件下检验原始测试顺序的模型似然偏好？
- **证据是什么**：论文讨论可交换性、零假设和顺序/分片统计比较；作者仓库提供实现与实验数据。
- **没有证明什么**：不能无条件识别所有污染，不能把未显著当作无污染；只生成文本的聊天接口也未必支持所需似然查询。
- **站内实践**：[数据污染审计](/pretraining/contamination-audit)；建立 n-gram 候选与原文归因账本，区分文本重叠、训练使用和分数影响。

**追问**：p=0.01 是不是代表 99% 概率污染？题目改写后掉分还有哪些解释？

## 10 · 投机采样：概率恢复与真实加速

**原始资料**：[Leviathan 等论文](https://arxiv.org/abs/2211.17192)、[Chen 等论文](https://arxiv.org/abs/2302.01318)、[vLLM 官方说明](https://docs.vllm.ai/en/stable/features/speculative_decoding/)。

- **读它回答什么**：拒绝后为什么需要正差残差，而不是直接从目标分布重抽？
- **证据是什么**：两篇论文给出接受/纠错算法与数值边界；官方资料说明算法、batch 与 logprobs 的区别。
- **没有证明什么**：理论分布保证不等于每次逐字相同，接受率不等于墙钟速度，也不证明目标模型回答正确。
- **站内实践**：[投机采样分布与成本](/inference/speculative-sampling-proof)；用精确有理数复算概率，再检查 K、验证与额外开销。

**追问**：如果拒绝后直接从 p 重抽，最终分布为何偏了？增加草稿长度什么时候反而更慢？

## 11 · 训练预算：计算最优与生命周期目标

**原始资料**：[Chinchilla](https://arxiv.org/abs/2203.15556)、[计入推理需求的缩放研究](https://arxiv.org/abs/2401.00448)。

- **读它回答什么**：训练预算、质量约束与长期推理需求分别怎样改变“最优”目标？
- **证据是什么**：前者研究给定训练计算的参数/token 分配；后者讨论训练加推理的计算与真实成本。
- **没有证明什么**：20:1 不是固定配方，6ND 不是租卡账单；小模型多训练也不自动同质量更优。
- **站内实践**：[训练预算与生命周期成本](/pretraining/compute-budget)；明确单位、复算构造最优点与条件性盈亏平衡，记录未验证的质量假设。

**追问**：两个配置参数不同但训练计算相同，就能认为同质量吗？服务需求变化会不会让成本结论反转？

## 用同一张卡留下阅读证据

~~~text
来源标题 / 作者 / 原始 URL：
阅读范围：摘要 / 指定章节 / 指定代码函数（不要冒充全文阅读）
版本：论文修订号 / 代码提交 / 文档版本 / 访问日期
问题：原方法在什么条件下失败？
方法增量：算法 / 数据 / 系统 / 训练配方
证据：任务、样本、指标、对照、预算与环境
代价：计算、标注、推理、工具和运行复杂度
边界：没有检验或不成立的条件
实践状态：已复算 / 已运行 / 实验设计 / 待核
下一步：最可能推翻结论的一项检查
~~~

不要把作者的结果抄成自己的复现结论。动态文档与默认分支链接会变化，实际复现时记录提交或不可变版本；搜索结果时间有时是修订或抓取时间，不直接当成论文首次发表时间。

### 把阅读卡接到一个能失败的验证

| 路线 | 最小可检验主张 | 一项能推翻草率结论的检查 |
| --- | --- | --- |
| LoRA | 指定线性层可训练增量参数减少 | 统计 `modules_to_save`、bias 和目标层，不漏激活账本 |
| DPO | chosen/rejected 的相对 log-ratio 被优化 | 标签翻转/长度匹配对照；收益是否只来自更长输出 |
| RAG | 给定证据支撑具体主张 | 保持问题不变，换成过期或不支持主张的证据 |
| 污染检验 | 原始顺序似然异常符合检验条件 | 核查可交换性、似然接口和多重检验，不把未显著当无污染 |
| 推理加速 | 指定质量与负载下端到端更快 | 加入验证、调度、失败与取消开销，检查 SLO goodput |

例如 LoRA 构造层 $W\in\mathbb R^{1024\times1024}$、rank 8：原矩阵 1,048,576 参数，增量 $8(1024+1024)=16,384$，该层比例 $1/64$。这是**参数数目**比，不是显存或服务成本节省 64 倍；优化器、激活、冻结权重和共享层仍需计入。

阅读证据可以很短，但要可定位：“第 3 节某公式 / 函数某分支 → 我确认的主张 → 没确认的部分”。摘要只足以确认研究对象与作者报告，不能填入全文实验表的具体配置；只看到链接应写 `linked_only`，不能用“官方来源”替代实际阅读。若访问遇到 403，保留失败记录和待核主张，不改凭据绕过授权。
