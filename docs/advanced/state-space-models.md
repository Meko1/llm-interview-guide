# 状态空间模型与 Mamba

SSM 的问题不是“线性复杂度必然胜出”，而是：**用有限状态压缩历史，怎样保留当前任务需要的信息，同时让训练和服务可高效执行？** 本文以 Mamba 原论文与 Mamba-1 官方缓存实现说明，不能直接套用所有后续 SSM 版本。

## 为什么要挑战 Transformer？

完整 attention 的序列混合在固定维度下通常有 $O(L^2)$ 算术量；因果 decode 每步读已有 K/V，缓存随长度增长。FlashAttention 减少中间矩阵 IO，并没有将完整 attention 的算术量改成线性。FFN、投影、词表头和服务调度还在总账中。

固定状态递推尝试将历史保存在与 $L$ 无关的张量中。这减少特定缓存增长，但不等于训练、prefill、输出缓冲或整个服务器常数显存。模型参数、batch、层数、状态维度和 dtype 仍会改变资源。

## 什么是状态空间模型（SSM）？

连续形式 $h'(t)=Ah(t)+Bx(t),y(t)=Ch(t)$ 经离散化得到：

$$h_t=\bar A h_{t-1}+\bar Bx_t,\qquad y_t=Ch_t.$$

零阶保持下 $\bar A=e^{\Delta A}$、$\bar B=\int_0^\Delta e^{uA}B\,du$。积分写法不要求 $A$ 可逆。连续参数与离散参数不同，不能拿未经离散化的 $A$ 直接解释时间步长。

当 $\bar A,\bar B,C$ 时不变且初始状态为零，展开递推有：

$$y_t=\sum_{j=1}^{t}C\bar A^{t-j}\bar Bx_j.$$

因此可用固定卷积核或递推；S4 通过结构化参数设计实现有效计算，**一般稠密状态矩阵**的每步成本仍与状态维度有关，不能仅凭线性递推就得到廉价内核。

构造标量例：$\bar A=0.5,\bar B=C=1,h_0=0,x=(2,0,4)$，则 $h=(2,1,4.5)$。展开第三步为 $0.5^2\times2+0.5\times0+4=4.5$。过去输入按动态衰减，不是在固定状态里逐字保存全部历史。

## Mamba：选择性 SSM（S6）

[Mamba 第 3.2 节](https://arxiv.org/html/2312.00752v2) 使 $B_t,C_t,\Delta_t$ 依赖输入，$A$ 仍是学习参数；离散后的 $\bar A_t$ 可因 $\Delta_t$ 改变。按内容调节状态更新的目的，是跳过无关 token、保留有关信息。参数随时间变，固定卷积核的等价关系不再成立。

但是对**已经给定的输入序列**，仿射递推仍能用结合律扫描。令一步变换 $T_t(h)=a_th+b_t$，两步复合：

$$T_2\circ T_1\leftrightarrow(a_2a_1,\ a_2b_1+b_2).$$

复合具有结合律，可分组求前缀，不需按位置串行执行全部训练计算。构造 $T_1=(0.5,2),T_2=(0.5,0)$，复合 $(0.25,1)$，对 $h_0=0$ 得 $h_2=1$，与逐步结果相同。真实模型多通道/结构化矩阵需按相应形状计算。

原论文第 3.3.2 节将 **kernel fusion、parallel scan、recomputation** 结合，避免把全部扩展状态写入 HBM。这不是“整条序列永远全放进 SRAM”，也不使未来尚未生成的 token 可并行解码。

## SSM vs Transformer

| 项目 | 完整 attention | 固定宽度选择性 SSM |
| --- | --- | --- |
| 序列混合算术量 | 随 $L$ 二次增长 | 固定通道/状态维度下随 $L$ 线性增长 |
| decode 记忆 | 保存历史 K/V | 保存递推状态与短卷积状态 |
| 历史访问 | 显式访问缓存，不保证读取正确 | 经状态压缩；重要信息可能丢失 |
| 并行计算 | 已知序列可并行 | 已知输入可 scan；生成未来仍依赖历史 |
| 实际速度 | 受硬件、batch、长度、内核影响 | 同样受这些因素影响，不承诺倍数 |

### 用形状复算缓存，而不是背“常数显存”

官方 Mamba-1 `allocate_inference_cache` 分配短卷积状态 $(B,D_{inner},d_{conv})$ 和 SSM 状态 $(B,D_{inner},N)$。构造 $B=1,D_{inner}=4096,N=16,d_{conv}=4$，两者都用 2 字节，则一层载荷：

$$(4096\times16+4096\times4)\times2=163840\ \mathrm{bytes}=160\ \mathrm{KiB}.$$

32 层为 5 MiB。比较构造的 GQA attention：每层 $2BLH_{kv}d_hs$，取 $L=8192,H_{kv}=8,d_h=128,s=2$ 字节，得 32 MiB/层、32 层为 1 GiB。**这只比较所选形状的缓存载荷，不是同质量模型或总显存实验**；实际 SSM/conv dtype 也可能不同。

## 混合架构：取长补短

混合模型在部分层使用 attention，另一些使用 SSM，以任务效果换取状态/计算折中。Jamba、Zamba、Hymba 保留为研究入口，本文未逐一核实其版本、机构和比例，不给统一最优配方。

有 attention 层，通常仍有相应长度相关 K/V；有 MoE，还需路由、专家权重/通信账本。应按每类层分别计数，而不是因名字带 Mamba 就宣布无 KV Cache。

验证方案：固定权重规模、数据和服务负载，比较短/长上下文、实体复制、多次出现同键不同值、检索干扰、跨位置依赖。分别记录质量、prefill/decode 延迟、峰值显存和状态重置后的行为；不能只跑一个长序列吞吐。

## 高频追问

**固定状态意味着不能准确复制吗？** 不是所有任务都不能，而是有限精度/宽度的压缩存在容量与干扰取舍；应在明确任务上测失效，而不是用模型族作能力排名。

**SSM 没有缓存吗？** 有缓存，只是不是增长的历史 K/V。当前官方 Mamba-1 实现还保存短卷积窗口，并在请求开始时正确初始化；请求复用时状态泄漏会造成跨请求污染。

**为什么 scan 可并行而生成仍串行？** scan 的各步参数能从已知训练输入预先计算；未来输出尚未采样，下一 token 的输入和状态仍有因果依赖。

**什么时候混合有价值？** 当质量验证表明某类任务需要显式历史访问，且 attention 层带来的成本在 SLO 内；应扫层比例/状态维度，不用复杂度阶数代替结论。
