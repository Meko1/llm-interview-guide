# Agentic RL（智能体强化学习）

> **把工具放进轨迹并不困难，正确分配奖励和控制环境代价才困难。** 本页面向 L3：先建立轨迹与观测的边界，再读目标函数、失败与实验。公开产品能调用工具，不是其具体训练算法已经公开的证据。

## 一、从 RLHF 到 Agentic RL

| 阶段 | RL 在干什么 | 奖励来自 |
| --- | --- | --- |
| **RLHF**（对齐） | 让单轮回答更符合人类偏好 | 人类偏好（奖励模型） |
| **RLVR**（推理） | 让模型学会长链推理 | 可验证结果（数学对错/代码通过） |
| **Agentic RL** | 让模型学会**多步、用工具、与环境交互**地完成任务 | 任务是否成功完成（环境反馈） |

> 三者不是互斥阶段。RLHF 可用于多轮任务，Agentic RL 可使用人类、AI 或执行奖励，RLVR 描述反馈来源。见 [RLHF](/finetuning/rlhf) 与 [推理模型](/advanced/reasoning-models)。

## 二、什么是 Agentic RL？

Agentic RL 用强化学习训练 LLM 成为更强的 **Agent**：在一个**多步、可调用工具、与环境交互**的过程中，根据「任务最终是否成功」的奖励来优化策略。

和单轮 RL 的关键不同：

- **多步轨迹（trajectory）**：一个 episode 是「思考→调工具→看结果→再思考……→完成」的整条轨迹，而非单次问答。
- **环境交互**：模型的行动会改变环境（执行代码、查数据库、操作浏览器），并获得真实反馈。
- **稀疏/延迟奖励**：奖励常只在任务结束才给（成功/失败），中间步骤没有即时反馈——这是核心难点（信用分配问题）。

### 轨迹似然：环境观测不能当模型动作

令历史 $h_t$ 包含任务、先前动作与工具返回；策略生成 $a_t\sim\pi_\theta(\cdot\mid h_t)$，环境按 $P(o_{t+1}\mid h_t,a_t)$ 返回观测。固定环境时：

$$\nabla_\theta E[R(\tau)]=E\left[(R(\tau)-b)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid h_t)\right].$$

这里是理想化、未加裁剪和 KL 的策略梯度，$b$ 是满足无偏条件的基线。工具结果是下一步动作的条件，**不是策略生成 token**。将返回的网页或代码执行结果当成动作监督，会训练模型拟合环境文本；Search-R1 明确讨论 retrieved token masking。多轮 GRPO 也应在生成动作范围上做 ratio、KL 与长度计数。

终局成功只能为整条轨迹提供信号，不能证明每一步思考都正确。若加过程奖励，需要证明奖励不是「调用工具次数越多越好」这类捷径。

## 三、典型场景

- **代码 Agent**：给一个 issue，让 Agent 自主改代码、跑测试，以「测试是否通过」为奖励（见 [Coding Agent](/engineering/coding-agent)、SWE-bench）。
- **工具使用/搜索 Agent**：训练模型学会何时搜索、如何用工具，以「答案是否正确」为奖励（如 Search-R1）。
- **GUI/电脑操作 Agent**：操作界面完成任务，以「任务是否达成」为奖励。
- **多轮对话/谈判**：以长期目标达成为奖励。

## 四、关键技术与挑战

- **算法**：PPO、GRPO 等是候选，DAPO 的数学任务配方不是所有 Agent 的默认最优。比较组内基线与 Critic 的偏差/方差、长度分母与采样成本。
- **框架**：verl、TRL、OpenRLHF 是实现入口；按所用提交确认工具循环、异步采样、mask 和权重同步，不保留未经核定的版本功能清单。
- **可验证奖励**：可重复执行不等于无噪声。隐藏测试覆盖、超时、搜索语料漂移和工具失败都可改变奖励，验证器仍会被利用。
- **信用分配**：长轨迹里哪一步该奖该罚很难界定——是 Agentic RL 的核心难题。
- **稀疏奖励**：成功率低时几乎拿不到正奖励，训练困难。对策：课程学习（由易到难）、过程奖励、拒绝采样。
- **环境与采样成本**：每条轨迹要真实跑工具/环境，慢且贵，需要高效的 rollout 基础设施。
- **稳定性**：长轨迹 + 稀疏奖励让 RL 更不稳定。

## 五、为什么重要？

它提供了针对交互任务训练策略的途径，但研究环境表现不能直接迁移到生产。必须限定可写资产、动作权限、状态重置、失败恢复与人工审批，训练出来的自主行为不构成执行授权。

## 六、推理 × Agent 合流：o3/o4-mini 的里程碑

保留 o3/o4-mini 为产品能力讨论入口，不从工具调用反推未公开优化器、奖励或隐藏 CoT。更可核对的研究证据是 Search-R1 的多轮检索训练，以及 RAGEN 对四个风格化环境的轨迹优化和 Echo Trap 分析。SAL、AgentGym、AgentBoard 保留为扩展索引，本轮未逐一复核；它们不能替代真实业务验收。

## 六、高频追问

**Q：Agentic RL 和 RLHF 有什么区别？** 前者强调交互轨迹，后者强调人类反馈来源；可交叉组合，不能以单轮/多轮作严格定义。

**Q：Agentic RL 的核心难点是什么？** ① 稀疏/延迟奖励（常只在任务结束才有信号）；② 信用分配（长轨迹里哪步该奖罚难定）；③ 环境采样成本高（每条轨迹要真实跑工具）；④ 训练稳定性差。

**Q：为什么使用可验证奖励？** 能提供可重复反馈，但正确性仅在验证器覆盖范围内；必须审计测试泄漏、超时、状态副作用与奖励捷径。

**Q：它和推理模型什么关系？** 可共享轨迹采样和奖励优化，但纯文本推理与有环境动作的任务具有不同观测、成本和权限；不能从公开输出推断内部训练机制。

**Q：稀疏奖励怎么缓解？** 课程学习（任务由易到难）、过程奖励（给中间步骤打分）、拒绝采样（保留成功轨迹做 SFT）、更好的 rollout 与探索策略，以及从能拿到正奖励的简单任务起步逐步加难。

## 复现实验：先把环境作为变量

固定初始模型、任务分层、工具/语料版本和动作预算，比较 Prompt Agent、轨迹 SFT、在线 RL；报告完成率、重复运行成功率、工具错误率、未授权动作、总生成 token 和环境耗时。失败/超时不可静默丢弃。重置环境状态并隔离 train/test 实例，避免缓存答案或历史副作用泄漏。

以「只增加搜索次数」为负对照，测试提升究竟来自训练还是额外检索预算；用隐藏测试和未见工具错误检验泛化。日志中的工具数据需脱敏且有保留策略。

- [Search-R1](https://arxiv.org/abs/2503.09516)：已读多轮搜索、retrieved token masking 和结果奖励摘要。
- [RAGEN](https://arxiv.org/abs/2504.20073)：已读风格化环境、Echo Trap 与稳定化描述；不是生产可靠性证明。
