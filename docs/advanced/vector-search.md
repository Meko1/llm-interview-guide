# 向量检索与 ANN 算法深入

向量检索先定义“近”，再决定愿意为速度/空间牺牲多少搜索精度。ANN 误差、Embedding 语义误差和业务相关性是三层问题：精确找到最近向量也可能答错问题。选型概览见 [Embedding 与向量库](/rag/embedding-vectordb)。

## 一、问题定义

给定 $N$ 个 $d$ 维向量与 query，返回按指定度量排序的 Top-$k$。Flat 暴力计算约 $O(Nd)$；矩阵计算、GPU、批量与小数据集可能使它成为合理基线，不能从“百万级”直接断言不可用。

ANN 用搜索路径剪枝或有损表示节省资源，可能漏掉最近邻。损失是否很小、提速是否明显，要在数据分布、过滤、硬件和查询负载上测量。

定义每 query 的搜索召回：

$$\mathrm{ANNRecall@k}(q)=\frac{|A_k(q)\cap E_k(q)|}{k},$$

$E_k$ 是同一向量快照、度量与过滤条件下的精确结果，$A_k$ 是 ANN 结果。距离并列时先约定 tie 规则或距离容差。与人工相关性标签的 Recall@k 不同；后者衡量业务检索，不是索引逼近程度。

## 二、相似度度量

| 度量 | 优化方向 | 适用假设 |
| --- | --- | --- |
| 内积 $q^Tx$ | 最大 | 模长可能是信号，不可随意归一化 |
| 余弦 $q^Tx/(\|q\|\|x\|)$ | 最大 | 非零向量，只比较方向 |
| L2 / 平方 L2 | 最小 | 绝对欧氏空间距离 |

两者都单位归一化时：$\|q-x\|^2=2-2q^Tx$，因此排序相同。Faiss 的 L2 距离口径需注意平方 L2 与欧氏距离的差异；阈值不能照搬。

构造 $q=(1,0),a=(2,2),b=(1,0)$：内积选 $a$（2 > 1），余弦选 $b$（1 > $1/\sqrt2$），L2 也选 $b$（0 < $\sqrt5$）。不能一概假设所有 Embedding 已归一化；检查模型输出、query/doc 两端和零向量。

## 三、主流 ANN 索引

### 3.1 HNSW（分层可导航小世界图）★

HNSW 建多层邻近图，上层帮助定位，底层更精细地探索候选。上层常用贪心移动；底层保留动态候选列表，不是单一路径贪心走到底就能保证 Top-$k$。

```
 上层(稀疏长边)   ●───────────●        ← 快速跳到大致区域
                  │           │
 中层            ●──●────●───●         ← 逐步逼近
                 │   │    │   │
 底层(稠密短边)  ●●●●●●●●●●●●●●        ← 精细定位 Top-K
```

图仅示意层次，不表示全部边长或必定找到真最近邻。[hnswlib 参数说明](https://github.com/nmslib/hnswlib/blob/master/ALGO_PARAMS.md) 区分：`M` 控制建图连接与空间，`ef_construction` 控制建图候选，查询 `ef` 控制搜索候选且不应低于 `k`。增大查询 `ef` 常提高召回但增加工作，不能弥补所有坏图或保证统一 $O(\log N)$ 延迟。

### 3.2 IVF（倒排文件索引）

先训练粗聚类，再将向量分配到倒排列表；查询选 `nprobe` 个列表搜索。若分布均匀，扫描候选数可粗估为 $N\times nprobe/nlist$，但真实簇不均、过滤和残差计算会改变成本。

构造 $N=10^6,nlist=1000,nprobe=10$，均匀近似扫描 10,000 个向量；不等于提速 100 倍，还要计粗中心搜索、列表读取、候选排序和传输。IVF-Flat **保存原向量**，不是 IVF 名称本身使向量存储大幅缩小；训练集须代表线上分布，漂移可使列表失衡。

### 3.3 PQ（乘积量化）

将向量分成 $m$ 个子空间，各训练 $2^b$ 个码字，用码字 ID 表示。每向量代码约 $mb/8$ 字节（按整字节配置）。ADC 可保留 query 全精度，借查询到子码字的距离查表近似原向量距离；IVF-PQ 还可编码相对粗中心的残差。

构造 $d=768,m=96,b=8$：FP32 原向量为 $768\times4=3072$ 字节，PQ 代码为 96 字节，**仅向量代码载荷**缩为 $1/32$。百万条代码为 96 MB，另有 ID、码本、粗中心、列表元数据；如保留原向量重排，原向量仍在总账。量化可能改变排序，增大 `nprobe` 不能消除全部量化误差。

### 索引选型

| 起点 | 先验证什么 | 再考虑 |
| --- | --- | --- |
| Flat | 精确基线是否满足负载/SLO | 满足则不必引入 ANN |
| HNSW | 图空间、构建/增量成本、召回—延迟曲线 | 查询候选与建图参数 |
| IVF-Flat | 训练代表性、簇不均和扫描量 | `nlist/nprobe` |
| IVF-PQ | 代码空间与量化召回损失 | PQ 配置、重排与原向量保留 |

没有按规模一刀切的索引答案，选择受硬件、并发、更新/删除语义和业务质量阈值约束。

## 四、工程权衡

### 过滤改变真值集合

“先检索再过滤”可能返回不足 $k$ 个。构造未过滤前 10 条中只有 2 条有权限：返回这两条并不是过滤集合的精确 Top-10，其余最近有权限文档可能在全局第 11 名以后。盲目加候选也不能保证补齐。

精确基线必须在**同一有权限集合**上算，再测 ANN 召回；记录过滤选择率和少于 $k$ 的查询比例。预过滤、图遍历中过滤、后过滤语义和连通性影响因实现而异。权限边界不可为追召回而放松。

### 可交付的测量协议

1. 固定向量模型、归一化、度量、快照和过滤条件；查询集与索引训练数据分开。
2. 保存精确邻居、ANN 结果与业务相关性标签；扫描召回、p50/p95/p99 延迟、QPS和峰值内存。
3. 分层覆盖长尾 query、重复向量、过滤稀疏与热点，分别测冷/热缓存及并发。
4. 加入插入、删除、版本漂移和故障恢复；切换索引前验证 ID/权限与快照一致。

Faiss 与 hnswlib 的删除、更新、持久化能力不能互相代替。需按具体实现核查，不把“标记删除并定期重建”说成所有 HNSW 库的统一语义。

## 五、高频追问

**维度越高越好吗？** 维度影响存储和距离计算，但语义质量取决于训练目标与任务。只有支持相应表示训练的模型才可有依据地截断，随意截断会改变度量。

**Recall@10=0.9 能证明 RAG 正确吗？** 不能，它只是逼近精确向量搜索；还需查人工相关性、版本/权限和生成忠实性。

**nprobe 变大为什么仍漏召回？** 可能 PQ 排序误差、重排候选不足、过滤/ID不一致或索引快照落后；先对照 IVF-Flat/Flat 分离粗筛与量化损失。
