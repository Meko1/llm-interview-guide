# Claude Code 扩展机制（Hooks / MCP / Skills / 命令）

> Claude Code 的强大不只在内置能力，更在**可扩展性**：用 Hooks 加确定性约束、用 MCP 接外部系统、用 Skills 封装专长、用 Slash Commands 和自定义 Agent 定制工作流。这一页讲清四大扩展机制怎么用、各自解决什么问题。功能总览见 [功能总览](/claude-code/overview)。

## 一、扩展机制全景：确定性 vs 能力

```
            确定性约束（代码强制）          能力扩展（给模型更多本事）
            ┌──────────────┐            ┌──────────────────────────┐
            │    Hooks     │            │  MCP / Skills / 命令 / Agent │
            │  生命周期拦截  │            │  外部工具/专长/工作流封装    │
            └──────────────┘            └──────────────────────────┘
```

先分清扩展的是**流程知识、工具访问还是执行检查**。2026-11-05 读取的[官方 Hooks](https://code.claude.com/docs/en/hooks)与[Skills](https://code.claude.com/docs/en/skills)是本页依据；具体可用字段仍需对照安装版本。扩展会扩大信任面，不是装得越多越安全。

## 二、Hooks：确定性生命周期钩子

Hooks 让你在 Agent 运行的**关键生命周期点**插入自定义脚本（shell 命令），框架在这些点自动触发：

| 典型 Hook 时机 | 用途举例 |
| --- | --- |
| 工具执行**前**（PreToolUse） | 拦截危险命令、强制校验参数、注入额外检查 |
| 工具执行**后**（PostToolUse） | 改完代码自动跑 lint/format、记录审计日志 |
| 用户提交前/会话事件 | 通知、合规检查、自动化触发 |

**为什么 Hooks 重要**：匹配的事件可执行检查，不依赖模型主动调用。这里的确定性是“在配置覆盖的路径上执行代码”，不是安全保证。按本轮读取的事件语义，PreToolUse 的退出码 2 可阻止尚未运行的工具；PostToolUse 已在执行之后，失败只能反馈，不能撤销写入。其他事件的阻断方式不同，不可照搬。

> Hook 本身也有权限、超时和供应链风险。上线前测试 matcher 是否覆盖 Edit、Write、shell 与 MCP 的等价入口；同步检查失败如何处理。不要让一个格式化 Hook 在并行编辑时覆盖其他 worker 的文件。

## 三、MCP：接入外部世界

MCP（Model Context Protocol）是标准协议，让 Claude Code 接入**外部工具和数据源**（见 [MCP 协议深入](/agent/mcp)）：

- **内置工具 vs MCP 工具**：Read/Edit 等核心工具与外接 MCP Server 是不同能力来源；不要把所有内置工具称为“内置 MCP”。
- **多种传输**：stdio（本地进程）、Streamable HTTP（远程）等。
- **工具发现**：客户端按协议获取能力；实际可见内容受连接状态、客户端功能和权限影响，缓存实现不属于协议保证。
- **典型用途**：连数据库查询、连内部 API、连 Jira/GitHub、连浏览器自动化、连私有知识库。

统一协议减少适配重复，但认证、授权、schema、传输与副作用仍需对接。数据库 Server 能连上，不等于租户隔离正确；应给只读凭据、参数范围和行数限制，而不是把“只读查询”写在工具描述里就结束。

## 四、Skills：「提示即能力」

Skills 把一段「做某类任务的专业提示 + 资源」打包成可复用的技能：

- **数据模型**：Markdown 文件 + Frontmatter（描述、触发条件、可用工具等元数据）。
- **按需加载**：不是一股脑全塞进上下文，而是根据任务**描述匹配**、按需激活相关技能（预算感知——描述短小，激活才加载全文）。
- **用途**：封装领域专长（如「写符合某规范的 SQL」「按公司模板生成文档」），让 Agent 在特定任务上表现稳定。

设计哲学：**能力可以是「数据（提示）」而不必是「代码」**——写一段好提示打包成 Skill，就扩展了 Agent 的专长，无需改框架。

## 五、Slash Commands 与自定义 Agent

- **Slash Commands**：官方已将自定义命令并入 Skills；`.claude/commands/deploy.md` 与 `.claude/skills/deploy/SKILL.md` 可提供 `/deploy` 入口，旧目录仍有兼容支持。不要再把它们当成两套完全独立的现行能力；内置命令与提示型 Skill 也不是同一机制。
- **自定义 Agent（Subagent 定义）**：用 Markdown 定义一个专用子 Agent（角色、可用工具、系统提示），可从多个来源加载（项目级/用户级），并**过滤工具**（限定它只能用某些工具）。用于把特定职责（如「代码审查 Agent」「测试 Agent」）固化下来。

## 六、四者怎么配合用？

```
Slash Command（入口）→ 触发一个自定义 Agent（角色专精）
   该 Agent 用 MCP 工具（接外部系统）+ Skills（领域专长）干活
   Hooks 在每步工具执行前后强制约束（格式化、安全、审计）
```

典型组合：`/security-review` 命令 → 启动「安全审查 Agent」→ 它用 MCP 连漏洞库、用 Skill 套审查清单 → PostToolUse Hook 记录审计日志。**命令是入口、Agent 是角色、MCP/Skills 是能力、Hooks 是约束。**

## 高频追问

**Q：Hooks 和提示词约束有什么区别？为什么要用 Hooks？**
提示词指导决策；代码 Hook 检查匹配事件；权限与系统隔离限制可执行范围。三者不能互相代替。应明确哪些事件可阻断、检查失败是否继续，以及是否存在未覆盖入口。

**Q：MCP 和 Claude Code 内置工具有什么关系？**
内置工具（Read/Edit/Bash 等）是 Claude Code 自带的核心能力；MCP 是**扩展通道**，让它接入外部世界的工具和数据（数据库、API、第三方系统）。模型调用 MCP 工具和调用内置工具，对它来说是一样的（都走工具调用），区别在能力来源——一个内置、一个外接。

**Q：Skills 和 MCP 都是扩展，怎么选？**
Skills 主要封装“怎么做”，但其目录也可带脚本与资源，因此不能一概称为无副作用的纯数据。MCP 主要提供工具与数据访问。两者组合时分别审查提示内容、脚本来源、Server 凭据与实际调用权限。

**Q：自定义 Agent 为什么要过滤工具？**
最小权限 + 专注。给「代码审查 Agent」只读工具（不给写/执行），既安全又让它聚焦审查不乱改；给「测试 Agent」测试相关工具。限定工具集能降低出错和越权风险，也让子 Agent 行为更可预测。

**Q：这套扩展体系对自研 Agent 的启发？**
分清「约束」和「能力」两类扩展：约束用确定性钩子（代码强制，不靠模型自觉）；能力用插件化机制（工具/提示包，灵活加载）。再用「命令/角色」组织入口和职责。这套「Hooks 管纪律、MCP/Skills 管本事、命令/Agent 管编排」的分工是可复用的 Agent 工程范式。
