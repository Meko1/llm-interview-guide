# 大模型术语速查表

> 大模型领域缩写和黑话特别多。这份速查表帮你快速扫盲，每个词配一句大白话解释。看文章遇到生词随时回来查。

## 基础概念

| 术语 | 大白话解释 |
| --- | --- |
| **LLM** | 大语言模型，海量文本训练出的超大神经网络，会「文字接龙」 |
| **Token** | 分词器产生的离散单位，可是字、词片段或字节；计数必须用模型配套分词器 |
| **Tokenizer** | 分词器，把文字切成 token 的工具，详见 [Tokenizer](/basics/tokenizer) |
| **参数（Parameter）** | 模型内部可学习的「旋钮」，7B = 70 亿个 |
| **Embedding（嵌入）** | 把离散对象映射为向量；输入 token 嵌入和用于检索的句向量不是同一种输出 |
| **向量（Vector）** | 有序数字数组；是否承载语义、能否比较相似度取决于训练目标和坐标空间 |
| **上下文窗口（Context Window）** | 模型一次能处理的最大 token 数，如 128K |
| **自回归（Autoregressive）** | 逐个生成 token，每次把已生成的内容再喂回去预测下一个 |

## 架构相关

| 术语 | 大白话解释 |
| --- | --- |
| **Transformer** | 以注意力和前馈网络组织序列计算的架构；也存在 SSM 与混合架构，详见 [Transformer](/basics/transformer) |
| **Attention（注意力）** | 让模型在理解每个词时「关注」相关的其他词 |
| **MHA / MQA / GQA / MLA** | 分别通过多头、KV 共享或潜变量压缩改变注意力计算与缓存，详见 [Attention](/basics/attention) |
| **位置编码（RoPE 等）** | 告诉模型每个词在句子里的位置 |
| **MoE（混合专家）** | 路由器为每个 token 选择部分专家；活跃计算少不等于总权重或通信小，详见 [MoE](/basics/moe) |
| **Encoder / Decoder** | 编码器（擅理解，如 BERT）/ 解码器（擅生成，如 GPT） |

## 训练与微调

| 术语 | 大白话解释 |
| --- | --- |
| **预训练（Pre-training）** | 在海量通用文本上「博览群书」，最烧钱的一步 |
| **微调（Fine-tuning）** | 在预训练模型上用少量数据「专项训练」，适配具体任务 |
| **SFT** | 监督微调，用「问-答」对教模型学会听指令 |
| **RLHF** | 基于人类反馈的强化学习，让模型说人类更喜欢的话，详见 [RLHF](/finetuning/rlhf) |
| **DPO** | 用成对偏好与参考策略直接优化的对齐目标；不是「不用反馈」 |
| **LoRA / QLoRA** | 训练低秩适配器；QLoRA 还量化冻结基座。显存仍受模型、序列和批量约束，详见 [LoRA](/finetuning/lora) |
| **对齐（Alignment）** | 让模型行为符合人类价值（有用、诚实、无害） |
| **蒸馏（Distillation）** | 用教师输出、分布或特征训练学生；能力能保留多少需要评测 |
| **Base / Chat 模型** | Base 侧重预训练分布；Chat 经后训练适配对话，通常还需要正确的聊天模板 |

## 应用开发

| 术语 | 大白话解释 |
| --- | --- |
| **Prompt（提示词）** | 你给模型的输入指令 |
| **Prompt Engineering** | 设计提示词的技巧，详见 [Prompt 工程](/prompt/prompt-engineering) |
| **CoT（思维链）** | 生成中间解题步骤的方法；可改善部分任务，但文字过程不是正确性或内部机制的证明 |
| **Few-shot** | 在提示里给几个例子引导模型 |
| **RAG（检索增强）** | 先查资料再让模型回答，减少幻觉，详见 [RAG](/rag/rag-basics) |
| **向量数据库** | 专门存 Embedding、做相似度检索的数据库 |
| **Agent（智能体）** | 通过模型决策和工具执行形成反馈循环的系统；权限、停止条件由应用控制，详见 [Agent](/agent/agent-basics) |
| **Function Calling** | 让模型「请求调用」外部函数/工具 |
| **MCP** | 一种标准化协议，统一大模型连接外部工具/数据的方式 |
| **幻觉（Hallucination）** | 模型一本正经地编造错误内容 |

## 推理与部署

| 术语 | 大白话解释 |
| --- | --- |
| **推理（Inference）** | 模型「使用阶段」，即生成回答的过程（对应训练阶段） |
| **KV Cache** | 缓存历史计算结果加速生成，但占显存 |
| **量化（Quantization）** | 以低比特表示权重或激活；质量和速度取决于校准、算子及硬件，不保证提速 |
| **vLLM** | 一种用于大模型服务的推理框架；选型看模型支持、硬件与工作负载 |
| **TTFT / TPOT** | 首 token 延迟 / 每个后续 token 的延迟 |
| **吞吐（Throughput）** | 每秒能处理多少 token / 请求 |
| **FlashAttention** | 一种又快又省显存的注意力计算方法 |

## 评估与指标

| 术语 | 大白话解释 |
| --- | --- |
| **Benchmark（基准）** | 标准化考试题集，用来给模型打分，详见 [评测基准](/evaluation/benchmarks) |
| **MMLU / C-Eval** | 知识类基准（英文 / 中文） |
| **GSM8K / HumanEval** | 数学 / 代码能力基准 |
| **困惑度（Perplexity）** | 平均 token 负对数似然的指数；只在可比数据、分词和计分协议下比较 |
| **Chatbot Arena** | 通过用户成对偏好构建的评测；排名受样本、风格偏好和统计不确定性影响 |
| **数据污染** | 测试题泄漏进训练数据，导致分数虚高 |

## 前沿热词

| 术语 | 大白话解释 |
| --- | --- |
| **推理模型 / 慢思考** | 回答前先长篇「思考」的模型，如 o1、DeepSeek-R1，详见 [推理模型](/advanced/reasoning-models) |
| **Test-time Compute** | 在推理阶段分配更多生成、搜索或验证预算；收益不保证且有延迟代价 |
| **涌现能力** | 某些评测上观察到随规模出现的非线性提升；也可能受指标阈值影响 |
| **Scaling Law（缩放定律）** | 在指定数据、架构和预算范围内拟合损失与规模的经验关系，不是无限保证 |
| **多模态** | 能同时处理文字、图片、音频等，详见 [多模态](/multimodal/multimodal) |
| **Mamba / SSM** | 一种挑战 Transformer 的新架构，详见 [状态空间模型](/advanced/state-space-models) |

**查词时先问对象。** 「推理」在部署文档里通常指运行模型，在能力评测里也可指 reasoning；「模型记忆」可能是参数中的知识、请求中的上下文，也可能是应用数据库。遇到「7B、4bit、128K」，分别问参数数量、量化对象、窗口 token 预算，不要把三者当作同一能力指标。

分词与 token 的依据：[Hugging Face 分词说明](https://huggingface.co/docs/transformers/tokenizer_summary)。这是术语入口，不是实现规范；配置细节请沿表内链接继续读。
