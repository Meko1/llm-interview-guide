# 大模型是怎么工作的（直觉版）

> 这一页用最少的术语、零公式，把「大模型为什么能聊天」讲清楚。如果你完全没接触过 AI，从这里开始；想看严谨原理，再去 [Transformer 架构详解](/basics/transformer)。目标是建立正确的直觉，避免被「AI 在思考/有意识」之类的误解带偏。

## 一句话本质：它在玩「文字接龙」

大模型（LLM）的核心机制朴素得惊人：**根据前面的文字，预测下一个最可能出现的词（token）**，然后把预测出的词接上去，再预测下一个，循环往复。

```
输入：今天天气真
预测：好（85%）／不错（8%）／热（4%）…
输出：今天天气真好
再预测：，（…）→ 今天天气真好，
再预测：适合（…）→ 今天天气真好，适合…
```

上面的概率是构造示意，不是实测。模型逐 token「续写」组成回答；对话产品还会组织历史、系统指令与工具结果，不能把整个产品等同于一个自动补全函数。

> 自回归描述的是生成顺序，不是对「有无思考」的判定。有些系统会先生成中间步骤、调用工具或比较候选，再向用户展示最终答案。逐 token 生成本身也不能完整解释幻觉；还需考虑训练资料、目标与证据缺失，见 [能力边界与误区](/beginner/llm-capabilities)。

## 二、token：模型眼里的「字」

模型不是按汉字/字母处理文本，而是按 **token**（词元）——可以理解成「常见的字、词或词片段」。比如「苹果」可能是 1 个 token，「apple」可能是 1 个，而一个生僻词可能被拆成几个 token。

- 模型的输入输出都是 token，计费、上下文长度也按 token 算。
- 不存在通用的「一个字等于几个 token」换算。语言、空格、数字、Unicode 与词表都会影响长度；预算应以实际编码结果为准。
- 详见 [Tokenizer 与分词](/basics/tokenizer)。

## 三、它怎么「学会」说话的？两个阶段

### 阶段一：预训练（读遍互联网）

把海量文本（网页、书籍、代码……）喂给模型，让它反复做「完形填空 / 文字接龙」练习。为了把下一个词预测得更准，模型被迫学会了语法、事实、推理模式、写作风格——**知识是「压缩」进参数里的副产品**。

训练成本随模型、数据量与硬件而变，并不是所有模型都需要同一规模集群。得到的**基座模型**更擅长延续训练分布，不保证按助手的方式回应。

### 阶段二：后训练（学会当助手）

基座模型也可能通过提示和示例回答问题，但指令遵循未必稳定。后训练把这些行为作为明确目标：

- **指令微调（SFT）**：给它看大量「问题→好答案」的范例，学会「被提问时要回答」。
- **对齐（RLHF/DPO）**：利用偏好数据塑造行为；RLHF 可以训练奖励模型再做策略优化，DPO 可直接使用成对偏好。它们不保证回答无误。

这就是为什么 ChatGPT 比原始 GPT「懂事」。详见 [微调范式](/finetuning/finetuning) 和 [RLHF 对齐](/finetuning/rlhf)。

## 四、参数、权重是什么？

你常听到「7B」「70B」——B 是 billion（十亿），指模型的**参数**数量。参数就是模型内部的一堆数字（权重），训练就是不断微调这些数字，让预测更准。参数越多，模型「容量」通常越大、越能记住和推理，但也越贵越慢。

可以打个比方：参数是模型大脑里的「神经连接强度」，训练就是反复调整这些连接，直到它能很好地完成文字接龙。

## 五、为什么同一个问题答案会变？

因为生成下一个词时，模型是在概率分布里**采样**，带一点随机性（由 temperature 等参数控制）。所以同样的问题，多问几次答案会不同。把随机性调到最低（贪心解码）会更稳定但更死板。详见 [解码与采样策略](/basics/decoding)。

## 六、上下文窗口：模型的「短期记忆」

模型一次能「看到」的 token 总量有上限，叫**上下文窗口**（如 128K token）。对话历史、你的问题、它的回答都占用这个窗口。

- 超长请求可能报错；应用也可能截断或摘要历史。即使没有超长，模型也可能没正确利用窗口内资料。「没带进请求」和「带了但没用好」是两种问题。
- 模型**本身没有跨对话的记忆**，关掉重开就「失忆」了（除非应用层做了记忆系统，见 [Agent 记忆](/agent/agent-memory)）。

## 七、几个重要的「它其实没有」

| 你可能以为 | 实际上 |
| --- | --- |
| 流畅回答证明它有意识 | 流畅性不是主观体验的证据；生成机制也不足以单独裁定意识 |
| 它语气自信就说明正确 | token 概率和口头自信不是经过校准的事实正确率 |
| 它能「记住」你 | 默认无长期记忆，靠应用层外挂 |
| 它会「上网查」 | 默认不会，除非接了搜索工具 |
| 它的知识是最新的 | 参数知识可能陈旧且不完整；请求资料和工具可以补充，但要核对来源 |

## 高频追问（面向新手）

**Q：大模型是不是有智能/意识？**
应分开问「能否完成某类任务」与「是否有主观体验」。前者可以用可重复评测检验；后者不能从像人的语气或训练目标直接得出结论。工程上不要把情感化表达当作主体承诺，也不要用「只是接龙」否定可观察的解题能力。

**Q：它为什么会「一本正经地胡说八道」（幻觉）？**
预训练通常优化真实文本的下一 token 似然，不是执行事实验证。后训练可以鼓励诚实和拒答，但数据缺失、错误资料及不当推断仍会产生无依据答案。缓解办法见 [能力边界与误区](/beginner/llm-capabilities) 和 [RAG](/rag/rag-basics)。

**Q：它能算数 / 写代码，是真的会吗？**
是从大量例子里学到的模式。简单的它很在行；复杂多步计算容易错（因为是「续写」不是真的执行运算），所以工程上常让它调用计算器/代码执行工具来兜底。

**Q：参数多就一定更聪明吗？**
通常更强，但不绝对。数据质量、训练方法、对齐质量同样关键——一个数据好、对齐好的小模型可能比粗制滥造的大模型更好用（见 [SLM](/models/slm) 和 [缩放定律](/pretraining/scaling-law)）。

**Q：我该怎么用好它？**
把问题说清楚、给足背景、复杂任务拆成可核对的小步、对事实性回答保持核查、需要实时信息时提供可靠资料或工具。系统方法见 [Prompt 工程](/prompt/prompt-engineering)。

<summary>自测：把一份新文件放入对话，模型权重会立即改变吗？</summary>

通常不会。文件经应用处理后进入当前请求上下文，影响条件概率；训练才会通过损失和优化器更新权重。若下次对话仍能访问文件，可能是应用存储和检索，不是「聊天自动完成微调」。
