# 大模型能做什么、不能做什么（能力边界与误区）

> 用好大模型的第一步，是知道它**擅长什么、不擅长什么、容易在哪翻车**。这一页帮新手建立正确预期，避开最常见的坑。工作原理见 [大模型是怎么工作的](/beginner/how-llm-works)。

## 一、它擅长的事

| 能力 | 例子 |
| --- | --- |
| 文本生成 | 写邮件、文案、报告、润色、改写风格 |
| 总结提炼 | 长文档/会议纪要浓缩成要点 |
| 翻译 | 多语言草稿；术语、语域和低资源语言需单独验证 |
| 改写转换 | 改语气、转格式、提取结构化信息 |
| 代码 | 写函数、解释代码、找 bug、写测试 |
| 问答与解释 | 解释概念、头脑风暴、当学习助手 |
| 分类与抽取 | 情感分析、意图识别、从文本抽字段 |

这些任务都有语言输入输出，但不能据此推断风险低。医疗报告翻译、合同抽取与代码生成都可能要求严格正确。先定义验收条件，再判断适不适合让模型负责。

## 二、它不擅长 / 容易翻车的事

| 短板 | 为什么 |
| --- | --- |
| **精确计算** | 它是「续写」不是「运算」，多位数乘法、复杂数学容易错 |
| **最新信息** | 参数知识可能陈旧；给出新资料可以补充，联网结果也需核查 |
| **私有/专业事实** | 未提供的内部事实不能可靠推断；可用受权限控制的检索提供证据 |
| **严格事实准确** | 会「幻觉」——自信地编造不存在的事实、引用、数据 |
| **长链严密推理** | 多步逻辑/规划容易中途出错（推理模型有改善） |
| **真正的「记忆」** | 默认不记得你之前说过什么（跨会话） |
| **可控性/确定性** | 同样输入可能给不同输出，难 100% 复现 |

## 三、最该警惕的：幻觉

**幻觉**指模型生成看似合理、实则错误或虚构的内容。这是新手最容易踩的坑，因为它**错得很自信**。

典型场景：

- 编造不存在的论文、书籍、链接、法条、API；
- 把人物、时间、数据张冠李戴；
- 你诱导它（「请引用三篇支持的研究」），它就编三篇出来。

**为什么会这样**：下一 token 似然并不等于事实验证；训练资料、上下文和后训练也可能有缺口。模型可以表现出拒答或自我纠错，但不能用其自信语气判断真假。**凡是事实性、后果严重的内容，必须核查**，别把 LLM 当权威信源。

## 四、新手十大误区

1. **以为它什么都知道** → 它有知识截止日期，且会编不知道的内容。
2. **以为它说的都是真的** → 幻觉普遍，事实要核查。
3. **以为它会算数** → 复杂计算让它调工具，别信口算。
4. **以为它记得你** → 默认无长期记忆，重要背景每次要给。
5. **以为它能上网** → 默认不能，除非应用接了搜索。
6. **指令太模糊还怪它笨** → 它没有读心术，说清楚要什么（见 [Prompt 工程](/prompt/prompt-engineering)）。
7. **把敏感数据随便贴进去** → 注意隐私与合规，公司机密别乱传。
8. **一次让它干太复杂的事** → 拆成小步，分步引导更可靠。
9. **完全照搬它的代码/建议** → 当草稿和助手，不当最终决策者。
10. **把拟人表达当承诺** → 语气会随提示变化；情感化回答不是主观体验的证据，更不是可承担责任的主体。

## 五、怎么扬长避短（实用建议）

- **给足上下文**：背景、目标、格式、约束都说清楚，输出质量天差地别。
- **复杂任务拆步**：先让它列提纲，再逐段展开，比一步到位更稳。
- **给事实提供证据**：RAG 能补充资料，但会检索错、漏检或被模型误用。要求关键结论能追溯原句，并在缺证据时拒答（见 [RAG 基础](/rag/rag-basics)）。
- **算数/查实时用工具**：接计算器、搜索、数据库，让模型「会调工具」而不是「硬扛」。
- **保持人在回路**：高风险决策（医疗、法律、财务、上线代码）必须人工复核。
- **核对依据，而非只索要依据**：检查链接真实存在、原文支持结论、日期适用。流畅的推理过程与引用都可能是生成的。

**一个可复做的边界测试。** 用构造资料「差旅餐补 60 元/天；住宿上限 300 元/晚」问「两晚住宿加三天餐补的最高总额」。先算核对值：`2 × 300 + 3 × 60 = 780 元`。再问资料未提供的「交通报销上限」：应说明未知，而不是补一个看似合理的数。最后把住宿上限改为 350 元，检查它是否跟随新证据更新为 880 元。这个小练习分别检查计算、拒答和证据更新，不代表生产准确率。

## 六、什么任务适合交给大模型？一个判断口诀

```
任务以语言为核心？     ── 否 ──► 大模型不是最佳选择
   │是
容错性高 / 有人复核？  ── 否 ──► 谨慎，加核查或工具兜底
   │是
不依赖私有/实时事实？  ── 否 ──► 配 RAG / 联网 / 工具
   │是
      可以先做小样本试用，按验收条件决定是否上线
```

## 高频追问（面向新手）

**Q：大模型会取代我的工作吗？**
不能从模型能力表预测某个岗位的去留。可以先拆分实际工作：哪些输出能自动核验、哪些需要专业判断、哪些错误不可逆。能展示节省时间且保持质量的工作流，比背诵就业口号更有用。

**Q：怎么减少幻觉？**
提供可追溯资料、允许拒答、核对引用、把计算交给工具，并用缺证据和冲突证据样本测试。低 temperature 可能让措辞稳定，却不会把错误变成事实；应分别测事实支持率和拒答是否适当。

**Q：免费版和付费版差别大吗？**
套餐和模型经常变化，不能只凭「付费」判断质量。用同一组真实任务比较输出、延迟、用量、数据条款与限额；选择满足需求的方案（见 [SLM](/models/slm)）。

**Q：我应该信任它的医疗/法律/投资建议吗？**
当作信息参考和思路启发，绝不当专业决策依据。这些领域错误代价高、且模型可能过时或幻觉，务必咨询持牌专业人士。

**Q：为什么有时它会「拒绝」回答？**
可能是模型安全策略、平台审核、权限限制，也可能是错误拒答。正当任务可补充范围和背景，先确认原因；不应尝试绕过安全和权限限制。详见 [大模型安全](/advanced/safety)。

风险说明参考：[GPT-2 历史模型卡](https://github.com/openai/gpt-2/blob/master/model_card.md)。它展示为何要明确预期用途与禁用场景，不应外推为当前模型的统一成绩。
