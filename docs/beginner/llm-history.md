# 大模型发展简史

> 知道「技术从哪来」才能理解「它为什么长这样」。本文用一条时间线串起 NLP 到大模型的关键转折，每个节点只回答一个问题：**它解决了前一代的什么痛点？** 适合新手建立全局感，也适合面试中展示技术视野。

## 一条时间线

| 时间 | 里程碑 | 解决了什么 |
| --- | --- | --- |
| ~2012 前 | 规则系统 / 统计 NLP | 人写规则到统计学习，但特征靠人工 |
| 2013 | word2vec | 词变成向量，「语义可以计算」 |
| 2014-16 | seq2seq + Attention | 序列到序列任务（翻译）可端到端学习 |
| 2017 | **Transformer** | 抛弃循环结构，并行训练 + 长程依赖 |
| 2018 | GPT-1 / **BERT** | 「预训练 + 微调」范式确立 |
| 2019 | GPT-2 | 纯语言模型能 zero-shot 干多种任务 |
| 2020 | **GPT-3** + Scaling Laws | 系统评测大模型的无梯度 few-shot 能力；拟合规模与损失关系 |
| 2022 | InstructGPT / **ChatGPT** | RLHF 对齐让能力「可用」，产品引爆全球 |
| 2023 | GPT-4 / **LLaMA 开放权重** | 多模态模型与可本地运行的权重扩大应用探索 |
| 2023–2024 | Mixtral / DeepSeek 等 MoE 模型 | 稀疏专家与长上下文工程进入更多公开实现；MoE 并非此时才发明 |
| 2024.09 | **o1** | 推理时计算（test-time scaling）开辟新增长轴 |
| 2025 | **DeepSeek-R1** | 公开可验证任务上的 RL 推理训练探索与蒸馏模型 |

本表止于 2025 年的选定转折，不是截至今天的模型榜单。论文年份、发布年份和产品普及时间不一定相同。

## 五个关键转折点详解

### 1. word2vec（2013）：语义进入向量空间

word2vec 用上下文预测高效学习稠密词向量，但不是分布式语义表示的首次出现。「国王 − 男 + 女 ≈ 女王」是特定词表和训练条件下的类比现象，不是所有语义都能做精确代数。今天的 [Embedding 检索](/rag/embedding-vectordb) 延续向量表示思想，但句向量还需要不同的训练与池化设计。[论文](https://arxiv.org/abs/1301.3781)报告的是词相似与类比测试，不是企业检索质量。

### 2. Transformer（2017）：架构分水岭

RNN 的时间步之间有依赖；Transformer 移除了循环，让一层内的多个位置可并行计算。是否能交互仍取决于 mask：自回归解码器不能看到未来位置，生成依旧逐步进行。[原论文](https://arxiv.org/abs/1706.03762)首先验证了机器翻译任务上的质量与训练效率，不等于证明所有序列模型都应替换成 Transformer。详见 [Transformer 架构详解](/basics/transformer)。

### 3. GPT-3 与缩放定律（2020）：「大力出奇迹」被定量化

[GPT-3 论文](https://arxiv.org/abs/2005.14165)评测了 175B 自回归模型：任务说明和示例放在文本中，不做梯度更新。few-shot 在多种任务上有收益，也有失败和训练污染问题。它扩大了「先试提示，再决定是否微调」的选择空间，而不是宣布微调被取代。缩放定律拟合的主要是损失，不能直接当作任意能力保证。详见 [缩放定律](/pretraining/scaling-law)。

### 4. ChatGPT 与 RLHF（2022）：能力变得「可用」

[InstructGPT](https://arxiv.org/abs/2203.02155)先做示范数据的 SFT，再用输出排序和 RLHF 改善指令遵循。论文在其提示分布上报告：评审更偏好 1.3B InstructGPT 的输出而非 175B GPT-3。这个结果区分了「预训练规模」和「满足用户意图」，却不能外推为小模型全面胜过大模型或对齐必然更便宜；模型仍会犯错。ChatGPT 的对话产品形态进一步降低了使用门槛。详见 [RLHF / DPO 对齐](/finetuning/rlhf)。

### 5. o1 与 R1（2024-25）：从「快答」到「慢想」

推理时计算成为被系统探索的预算轴，但不能据此断言预训练数据「见顶」。[DeepSeek-R1 官方说明](https://github.com/deepseek-ai/DeepSeek-R1)明确区分：R1-Zero 从基座直接进行 RL，观察到反思等行为，也存在重复、可读性和混合语言问题；R1 则加入冷启动数据及多阶段训练。不能把「纯 RL」结果误写成完整 R1 流程。更长生成也不是无条件更准。详见 [推理模型与慢思考](/advanced/reasoning-models) 与 [DeepSeek 专题](/models/deepseek)。

## 用三条主线记住这段历史

1. **规模主线**：word2vec → Transformer（可并行）→ GPT-3（缩放定律）→ MoE（更省地变大）——「怎么变大」。
2. **对齐主线**：GPT-3（强但野）→ InstructGPT/RLHF → DPO/GRPO ——「怎么变得好用」。
3. **推理主线**：CoT 提示 → o1/R1（RL 训练慢思考）→ Agent（推理 + 行动）——「怎么变聪明」。

> 面试被问「谈谈大模型发展历程」，按这三条主线组织，比按年份背模型名高一个档次。

## 中国大模型的平行时间线

- 2023「百模大战」：文心、通义、GLM、Baichuan 等密集发布；
- 2024：Qwen、DeepSeek、Kimi 等从模型权重、训练效率和上下文能力等不同方向探索；发布宣传不能直接比较实际成本与质量。
- 2025：R1 提供公开的推理训练探索；其他模型系列继续迭代。许可证、权重可用性与源码公开程度需逐模型检查。生态详见 [经典模型盘点](/models/classic-models) 与 [LLaMA 与 Qwen](/models/llama-qwen)。

## 高频追问

**Q：为什么说 Transformer 是分水岭？**
它减少了层内时间步串行依赖，使大规模训练更容易，但训练仍有层间依赖、生成仍自回归，规模化也依赖数据、优化器与硬件。不要说「没有 Transformer 就没有大模型」。

**Q：BERT 当年比 GPT-1 更火，为什么最后是 GPT 路线赢了？**
不是一方淘汰另一方。双向编码器适合分类、表示与重排；因果解码器更自然地提供开放生成接口。任务是否需要生成、训练数据和成本决定取舍，不能用产品热度证明架构优劣。详见 [经典模型盘点](/models/classic-models)。

**Q：ChatGPT 技术上有什么新东西吗？**
单点技术（GPT-3.5 + RLHF）此前都已发表，它的突破是**工程整合 + 产品形态**：把对齐做到「普通人可用」并用对话界面交付。技术史的教训：临界点常由「可用性」而非「新算法」触发。

**Q：开源模型是怎么追上来的？**
开放权重、适配工具链与公开训练方法降低了实验和私有化门槛。但「开源」要区分权重、代码、数据和许可证；能力差距需要按任务与时间点评测，不能用「只差几个月」概括。

**Q：下一个增长轴可能是什么？**
可以讨论推理时搜索与验证、[Agentic RL](/advanced/agentic-rl)、[多模态与视频](/multimodal/video-generation)及[数据工程](/pretraining/data-engineering)，但这是研究方向而非增长保证。对每个方向追问：预算增加在哪里、收益怎样测、失败与安全代价是什么。
