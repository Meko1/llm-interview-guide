# 大模型零基础入门

> 完全没接触过 AI，也想搞懂大模型、甚至转行进入这个领域？这篇就是为你准备的。我们用最少的术语，帮你建立正确的认知和清晰的起点。

## 先理清几个名词的关系

刚入门最容易被一堆缩写绕晕。先分清「方法的家族」和「系统能做的事情」：

```
人工智能 AI（让机器变聪明的所有方法）
  └── 机器学习 ML（让机器从数据中自己学规律）
        └── 深度学习 DL（用「神经网络」来学，是当前主流）
              └── 大语言模型 LLM（专门处理语言的超大神经网络，如 GPT）

生成式 AI：按能力划分的另一条轴，包括文本、图像、音频生成等。
LLM 与生成式 AI 有交集，但图像生成模型不一定是 LLM。
```

- **AI**：宽泛概念，让机器表现出智能。
- **机器学习**：从数据中学习参数或规则；数据、目标和约束仍需人设计，不是完全自动。
- **深度学习**：机器学习的一种，用多层「神经网络」，是现在大模型的基础。
- **大语言模型（LLM）**：本页主要讨论以「预测下一个 token」为训练目标的生成式语言模型。「大模型」也可指视觉等模型。

## 大模型到底在做什么？

一句话：**大模型本质是一个「超级文字接龙」机器。**

你给它一段话，它先把文字转为 token ID，再计算下一个 token 的概率分布，选择一个、接回输入、继续生成。比如「中国的首都是」可能接上「北京」；究竟一步输出一个字还是一个词，取决于分词器，而不是汉字边界。

为预测复杂文本，模型会学习语法、知识关联和解题模式；后训练再塑造指令遵循与对话行为。但训练目标不保证每次回答真实，也不能仅凭规模断言能力会突然出现。想深入可看 [核心概念总览](/basics/overview)。

## 入门最少必要概念（看这 5 个就够开始）

| 概念 | 一句话理解 |
| --- | --- |
| **Token** | 分词器输出的离散单位，可能是字、词片段或字节；不是固定字数 |
| **参数（如 7B）** | 模型内部的可学习数值，7B = 70 亿个；数量不是质量排名 |
| **上下文窗口** | 请求可处理的 token 预算；应用可能截断、摘要，也可能拒绝超长输入 |
| **Prompt（提示词）** | 输入中的指令、资料与示例；效果还取决于模型能力和资料质量 |
| **幻觉** | 模型会一本正经地胡说八道、编造事实 |

> 更多名词见 [大模型术语速查表](/beginner/glossary)。

## 怎么开始？（务实路径）

你**不需要**先啃完高数和论文才能上手。推荐顺序：

1. **先用起来**：选择一个可访问的对话产品，用不含敏感信息的小任务体验能力；入口、模型和免费额度以产品当前说明为准。
2. **学会提问（Prompt）**：这是性价比最高的技能，见 [Prompt 工程](/prompt/prompt-engineering)。
3. **调通一次 API**：先了解密钥、计费和数据使用条款，再用 Python 发一次请求，保存输入、输出与用量；具体步骤见 [新手实战手册](/beginner/llm-first-practice-handbook)。
4. **理解基本原理**：回头看 [核心概念总览](/basics/overview) 和 [Transformer](/basics/transformer)，把 token、上下文、参数和工具调用区分开。
5. **按方向深入**：想做应用走 [RAG](/rag/rag-basics)/[Agent](/agent/agent-basics)；想做算法补 [数学基础](/beginner/math-basics) 和训练原理。

完整规划见 [大模型学习路线](/interview/learning-path)。

## 三种主要「岗位方向」

了解方向有助于你选择学什么：

- **大模型算法 / 研究**：偏训练、微调、模型结构、论文。需要较强数学和 PyTorch 功底。
- **大模型应用开发**：用 API + RAG + Agent 把模型做成产品。工程能力为主，门槛相对友好。
- **大模型工程 / 推理部署**：把模型高效、稳定地跑起来对外服务（量化、vLLM、显卡）。

> 后端经验能复用于接口、权限、日志和稳定性；但能调通 API 不等于能交付可靠的 AI 系统。岗位边界以实际职责为准。

**第一次练习：总结一段你能核对的资料。** 给出三条构造事实：「A 店周一闭店；B 店每天营业；C 店营业时间未提供」，要求只列周一确定营业的店，并标注依据。检查它是否把「未提供」误当成「营业」。再去掉资料问同一问题：答案更流畅不代表证据更多。

## 新手常见误区

- **「必须先精通数学才能学」**：不对。应用方向用 API 就能做很多事，数学边用边补即可。
- **「大模型什么都对」**：错。它会幻觉、会过时。RAG 提供资料，计算器执行运算，两者都仍需检查输入和结果。
- **「参数越大越好」**：不一定。小模型 + 好数据 + 合适方法常常更实用、更便宜。
- **「Prompt 能解决一切」**：清晰输入很重要，但不能补出不存在的资料，也不能代替权限控制和测试。
- **「学完一个框架就够了」**：技术迭代极快，重要的是理解原理，工具会变。
