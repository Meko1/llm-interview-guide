# 推理类提示工程（CoT 全家桶）

> 步骤提示、多候选投票、可回溯搜索、反馈修订，是四种不同干预。它们的成本与可靠性来源不同，不能统称为“多想想”。本文重点回答：什么时候值得用、怎样判断真的改善、失败时退回哪一层。

## 为什么「思考」能提升正确率？

对固定层数的自回归 Transformer，生成中间 token 增加解码步数，并把中间表示放入后续上下文。这是“把计算摊开在时间维度”的直觉，不是增加网络层数或证明文字越长越有效。直接回答也包含 prefill 和多个输出 token 的计算；推理服务还可能包含不可见的 reasoning token。

> CoT 提供可复用中间表示，同时付出串行解码成本。[Wei 等原论文](https://arxiv.org/abs/2201.11903) 在所测算术、常识与符号任务上报告收益，不证明所有模型、事实题或更长解释都有收益。缺事实资料时，更多步骤可能只是更完整地编造。

区分**可见说明、内部推理、外部验算**：说明供读者复核，不是内部计算日志；验算由计算器、测试或规则完成。背景见 [推理模型与慢思考](/advanced/reasoning-models)，选择器与算力账本见 [推理时算力扩展](/inference/test-time-scaling)。

## 一、Chain-of-Thought 家族

### Zero-shot CoT

最简单：在问题后加一句触发语。

```
问题：食堂有 23 个苹果，午餐用了 20 个，又买了 6 个，现在有几个？
让我们一步步思考。
```

- [Zero-shot CoT](https://arxiv.org/abs/2205.11916) 测试英文步骤触发语，中文措辞需单独测试。
- 上例为教学构造，正确答案是 $23-20+6=9$；可要求简短算式和答案，不要求披露私有思维链。
- **失效场景**：多写步骤可能引入错误；不同规模、训练与任务上的收益不同。原论文特定模型的规模效应不能外推为「小模型必无效」。

### Few-shot CoT

在示例里**展示完整推理过程**，而非只给「输入→答案」：

```
Q：罗杰有 5 个网球，又买了 2 筒，每筒 3 个，共几个？
A：罗杰原有 5 个。2 筒 × 3 个 = 6 个。5 + 6 = 11。答案是 11。

Q：（你的真实问题）
A：
```

- 示例能表达格式与任务约定，不保证胜过 Zero-shot；代价是上下文长度、维护与模式偏置。
- **示例质量 > 数量**：错误或风格混乱的示例会把模型带偏。

### Auto-CoT

[Auto-CoT](https://arxiv.org/abs/2210.03493) 用多样问题生成示范，试图降低自动错误链的影响；聚类选代表问题不等于获得正确标签。工程上分开生成、验算、去重和冻结：不能把测试题答案写入示例池，也不能只靠模型自评验收。

## 二、提升可靠性：采样与搜索

### 自洽性（Self-Consistency）

对同一问题用**带温度的采样**生成多条 CoT 路径，对**最终答案**投票取多数：

```
同一问题采样 N=20 条推理 ──► 提取各自的最终答案 ──► 多数投票
```

- [Self-Consistency](https://arxiv.org/abs/2203.11171) 按终点答案聚合路径，其直觉是正确路径能汇聚；错误也可能集中到同一答案，投票比例不是校准过的正确概率。
- 增加样本可探索更多候选，但共享偏差可能使多数票仍错，N 越大不保证越准；调用、提取和验证成本都要计入。
- 要求答案**可归一化比较**（数学答案、选项）；开放式生成无法直接投票，需配评分。
- 开放式答案可另设评分器或语义聚合，但需测试选择误差；表述相似不等于事实正确。

**复算理想模型。** 假设二元答案、各次独立、单次正确率 $p=0.7$，五次严格多数正确的概率为：

$$P=\binom{5}{3}0.7^3 0.3^2+\binom{5}{4}0.7^4 0.3+0.7^5=0.83692$$

这是分布假设下的计算，不是实测。五次若共享同一系统性错误，独立性失效；多类相对多数也不等于上述二元严格多数。

**提取规则必须显式。** 构造 20 个候选：12 个答案 `9`、5 个 `8`、3 个不可解析。预先排除无效项时，有效票占比 $12/17\approx70.6\%$，不能与全样本占比 $12/20=60\%$ 混用；另报 $3/20=15\%$ 提取失败率。平票、缺单位和低支持度需追问/弃权。

预算构造：每次输入 500、输出 300 token，20 次合计输入 10,000、输出 6,000 token（无缓存折扣，未计裁判）。并发可能减墙钟时间，不消除费用和限流；尾延迟还受最慢候选影响。

### 思维树（Tree of Thoughts, ToT）

把推理建成**树**：每个节点是一个「想法（thought）」，模型生成多个候选分支、对每个分支**自评打分**、用 BFS/DFS 搜索 + 剪枝，支持**回溯**。

```
        问题
       /  |  \
    想法A 想法B 想法C   ← 生成候选
     |    ✗    |       ← 评估剪枝（B 被淘汰）
   A1 A2     C1 C2
```

- 适合需要探索和试错的任务：24 点游戏、填字、规划。
- [ToT](https://arxiv.org/abs/2305.10601) 在 24 点、创意写作和小型填字上测试搜索，不是一般规划能力认证。控制器需显式保存状态、生成、评分与回溯；一条 prompt 写“建立思维树”不等于实现搜索。评分器错判会剪掉正确路径。

完整树分支数 $b=3$、深度 $d=4$，非根节点为 $3+9+27+81=120$，有子节点的父状态为 $1+3+9+27=40$。**节点数不等于调用数**：每父状态一次批量生成、一次批量评分，共 80 次；逐子评分则为 $40+120=160$ 次，均未计终点验证。剪枝、缓存会改变账本，应报实际展开数。

### 思维图（Graph of Thoughts, GoT）

[GoT](https://arxiv.org/abs/2308.09687) 允许聚合、反馈和复用想法依赖。结构更一般，不代表每个任务更好或更贵。用“多份分析汇总到决策节点”说明聚合后，还要解释去重、依赖版本和循环终止；合并丢失证据时，图结构也救不了答案。

## 三、问题分解类

### Least-to-Most（由简至繁）

[Least-to-Most](https://arxiv.org/abs/2205.10625) 先拆子问题再顺序求解，后题使用前题答案。easy-to-hard 收益限所测任务，不等于消除误差传播。例如先算原价、税额、总价，前一步错仍会污染后面；每步保留单位、依赖和验算。

### Plan-and-Solve

[Plan-and-Solve](https://arxiv.org/abs/2305.04091) 先计划后执行应对漏步骤，PS+ 增加细化指令处理计算等问题。计划列出输入、子目标和终止条件，不是“认真分析”。错误计划执行得完整，也会得到错误结果。

### Step-Back Prompting（退一步）

先让模型**抽象出更高层的原理/概念**，再用原理解答具体问题：

```
原问题：理想气体在温度变为 2 倍、体积变为 8 倍时压强如何变化？
退一步：这道题背后的物理原理是什么？ → 理想气体定律 PV=nRT
再解答：用该定律推导……
```

[Step-Back](https://arxiv.org/abs/2310.06117) 先抽象原理再解实例。此题还需假设 $n$ 不变、温度使用 Kelvin，才有 $P_2/P_1=(n_2/n_1)(T_2/T_1)(V_1/V_2)=1\times2/8=1/4$。摄氏温度翻倍不满足该比例；原理错或条件缺失时，只会把错误包装得更整齐。

## 四、自我改进类

### Self-Refine（自我精炼）

同一个模型扮演三角色循环：**生成 → 自我反馈 → 按反馈修订**，直到满意或到轮数上限。无需额外训练，靠模型自己挑自己的错。

- 原 [Self-Refine](https://arxiv.org/abs/2303.17651) 使用同一模型反馈，在七类任务上报告改善；外部验证不是原方法定义。
- [无外部反馈自纠错研究](https://arxiv.org/abs/2310.01798) 在其推理实验中发现修订可无效或变差。任务/指标不同，不可推广为“纯自评一律无效”或“数学代码必然有效”。
- 引入外部测试/规则时注明是增强流程。保留原答案，只按预定义验收选择修订；设轮数/预算上限，记录“对改错”和“错改对”，不只以模型自称满意停止。

### Reflexion

[Reflexion](https://arxiv.org/abs/2303.11366) 保存任务反馈形成的反思文本，供后续试次使用；不更新权重，反馈可外部或内部模拟。区别在跨试次经验，不只是更名。记忆绑定任务、证据和过期条件，不能让网页载荷变成永久系统规则。见 [记忆系统](/agent/agent-memory) 与 [Agent 基础](/agent/agent-basics)。

## 五、推理模型时代：范式转变（最新）

本节“最新”保留用于旧标题锚点兼容，不代表实时榜单。训练与接口依模型而异，不能把 R1 的 RL 路线当所有模型的训练说明；见 [DeepSeek 专题](/models/deepseek)。先查版本指南，再做任务对照。

| 传统模型 | 推理模型 |
| --- | --- |
| 可测试简短步骤提示 | 先查所选模型指南，不强制暴露或复写私有思维链 |
| few-shot 可表达解题格式 | 示例可能有益或干扰，按任务比较零/少样本 |
| 可拆子问题并验算 | 给目标与可验证结果，粒度按测试决定 |
| 参数按任务/API 测试 | 官方建议针对具体模型，不是跨模型定律 |

**给推理模型写提示的要点**：

- 说清**目标、约束、评判标准**，把「想」的过程交给模型；
- 不默认堆入大量示例；是否需要步骤引导要查指南，不能一刀切；
- 复杂任务可以明确「先分析需求，再给方案」，但不必规定具体推理步骤；
- 答案可归一化时可测试投票，同时计入内部推理预算和选择器误差。

**反例：** [R1 官方 README](https://github.com/deepseek-ai/DeepSeek-R1#usage-recommendations) 建议温度 0.5–0.7（推荐 0.6），且建议数学题包含逐步推理与答案格式指令。因此“所有推理模型都别写 step by step”不成立。其无 system prompt 等使用建议不能替代执行器安全策略，也不能直接套其他厂商 API。

## 方法选型速查

| 任务特征 | 推荐方法 |
| --- | --- |
| 简单事实/分类 | 从直接回答起步；缺资料先补证据 |
| 数学/逻辑/多步 | Zero/Few-shot CoT |
| 要更高准确率、可投票 | Self-Consistency |
| 比示例更难的组合问题 | Least-to-Most |
| 知识密集易翻车 | Step-Back |
| 有外部验证（代码/数学） | Self-Refine / Reflexion |
| 需大量探索试错 | ToT（成本允许时） |
| 用的是推理模型 | 查版本指南，固定预算比较有/无步骤引导 |

## 验证方法，而不只验证话术

假设用文中的苹果问题，正确结果是 $23-20+6=9$；Step-Back 的气体例子还需要假设物质的量不变，才有 $P_2/P_1=2/8=1/4$。若条件不全，先澄清，不能因为写出长推导就判正确。

在同一模型和任务集上比较直接答案、简短步骤提示、few-shot 和多候选方案，冻结示例与验收划分，统计答案正确、格式、拒答、token 和时延。只用可见解释检查中间算式，不把解释当真实内部计算记录；合理解释也可能只是事后合理化。

自评与外部反馈要分开：测试通过仅覆盖测试定义，检索来源也可能错，换一个同样的模型投票不是独立事实认证。涉及工具行动时，模型生成计划只作建议，授权、状态机、幂等与恢复仍在执行器；Prompt 不能把不可靠模型变为安全边界。

最终选中答案正确率与“候选中存在正确答案”要分开；后者假设一个完美选择器。多候选/迭代方案补同 token 或调用预算对照，避免把多花钱误归因为更好的提示。

### 分层口述：同一道题，深度不同

<summary>L1：苹果题怎样变为可验证任务？</summary>

定义算式、数值、单位的输出契约，用规则验算 $23-20+6=9$。条件缺失先追问，不以解释长度判正确；说清输入、输出和失败例，不必背所有变体。
</details>

<details>
<summary>L2：五次投票为何仍可能不值得上线？</summary>

理想独立模型的 0.83692 不是实测承诺。检查相关错误、提取失败、限流、尾延迟和费用；低支持度弃权，最终选中结果与同预算基线比较，不能只报候选上限。
</details>

<details>
<summary>L3：如何区分步骤、搜索与反馈贡献？</summary>

固定模型/数据与预算，分别消融步骤提示、采样数、评分器和反馈来源。保留逐题配对、多次试验与不确定性，报对改错率；可见解释只作行为证据，不声称测到了内部真实推理。
</details>

## 高频追问

**Q：CoT 一定能提升效果吗？**
不是。收益取决于模型训练、任务、示例和预算，不能仅按参数量或「是否推理模型」判断。用直接回答基线与保留测试集比较，检查多写步骤是否只是增加成本或错误。

**Q：Self-Consistency 和 ToT 的区别？**
候选不共享搜索状态不代表错误统计独立；ToT 维护父子状态、评估与回溯。区别在控制流程，不是“谁必然更强”；费用按实际生成与评分调用计算。

**Q：模型能可靠地自我纠错吗？**
先区分自评、外部反馈与跨试次记忆，再测修订收益。测试不全、检索错误、评分器误判也会把正确答案改错；保留原候选与验收记录，设置停止和回退。

**Q：为什么对 o1/R1 不该写「让我们一步步思考」？**
先查具体模型指南，再做任务对照。有些推理模型不需要额外步骤提示，但不能把某供应商建议推广到所有版本；给清晰目标、约束与可验证输出，不要求泄露私有思维链。

**Q：Step-Back 为什么有效？**
它先抽象原理再应用，不必包含外部检索。气体题检查 $n$ 不变与 Kelvin 比例；原理错或条件缺失仍会失败。论文收益与自己的验证集结果分开报告。

**Q：这么多变体，工程上实际常用哪些？**
先建立直接回答基线；确有分解需求再加步骤；可比较答案且预算允许再采样；有可用反馈再修订；需要回溯状态空间才考虑搜索。这是诊断顺序，不是免评测配方。
