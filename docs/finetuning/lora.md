# LoRA / QLoRA 详解

> **LoRA 减少的是可训练参数与其训练状态，不是把整个训练过程变成小模型。** 本页主阅读级别 L2；L1 先读选型与配方，L3 再读公式、初始化和对照实验。微调全貌见 [微调范式](/finetuning/finetuning)。

<LessonLab kind="lora" />

## 一、为什么需要 LoRA？

全参数微调更新所有目标参数；LoRA 冻结基座，在指定权重上学习低秩增量。基座可以共享，任务变化主要保存在适配器中。

全参微调显存不仅是权重，还包括梯度、优化器状态、可能存在的主权重副本、激活和临时工作区。例如**假设** BF16 权重与梯度各 2 字节、FP32 主权重 4 字节、Adam 两个 FP32 状态共 8 字节，则状态合计 16 字节/参数，7B 为 112 GB，约 104.3 GiB。这个教学配置不含激活、分片与额外缓冲，也不是所有优化器实现都如此。

LoRA 省去了冻结权重对应的梯度与优化器状态，但仍要执行基座前向，并通过网络传播梯度以训练较早层的适配器。长序列、batch 与激活仍可能主导峰值显存；可训练参数少不等于训练 FLOPs 按相同比例减少。

## 二、LoRA 原理

### 2.1 低秩假设

对线性层 `W（d_out × d_in 的实数矩阵）`，采用：

```text
h = W x + s B A x
W: d_out × d_in    A: r × d_in    B: d_out × r
s = α / r
```

冻结 `W`，训练 `A、B`。单层适配器参数量为 `r(d_in + d_out)`，相对该层全参更新的比例为 `r(d_in + d_out) / (d_in · d_out)`。方阵时才简化为 `2dr`。

这是**普通线性 LoRA 且不另训 bias**的账本，不是 PEFT 整个模型的训练清单。配置 `bias`、`modules_to_save`、可训练 embedding 或 DoRA 幅度后，还会有额外参数；应用前后分别列出 `requires_grad=True` 的名称、形状和优化器参数组。`model.eval()` 关闭训练态行为，`requires_grad=False` 才冻结参数，二者不能互换。

“低秩”是对更新的结构约束与经验假设，不是证明所有任务的最优更新都低秩。秩限制的是单个增量矩阵，不意味着整个模型只能表达秩为 r 的函数；原始 `W` 与非线性仍然存在。

```text
输入 → 冻结的 W ───────────────┐
     → 可训练 A → 可训练 B → ×s ├→ 相加 → 输出
                               ┘
```

### 2.2 初始化与缩放

原始 LoRA 采用随机初始化 `A`、零初始化 `B`，使开始时 `BA = 0`。不同实现和初始化变体不一定相同：PEFT 普通线性 LoRA 默认使用 Kaiming uniform 初始化 A，显式选择 gaussian 时才使用相应高斯初始化。不能把“随机高斯”写成所有实现的统一默认。

对一个输入 `x`，上游梯度 `g = ∂L/∂h`：

```text
∂L/∂B = s · g · (A x)ᵀ
∂L/∂A = s · Bᵀ · g · xᵀ
```

因此 B 为零时，第一步 A 的梯度为零，B 通常仍有梯度；B 更新后 A 才获得梯度。若 A 与 B 都为零，在这个普通参数化下两者都没有学习信号。

本轮核对的 PEFT `reset_lora_parameters` 对普通线性层采用 A 随机、B 为零；embedding 分支却采用 A 为零、B 随机。所以上述梯度结论必须绑定到这里定义的线性矩阵方向，不能把「A 总是随机」推广到所有适配器。初始化模式为 `False` 或分解式变体时也需另读路径。

`s = α/r` 控制旁路尺度，**不保证改变 r 后无需调学习率**。rsLoRA 使用 `α/√r`，比较不同秩时应记录缩放方式、学习率与目标层，不只报告 r。

## 三、LoRA 的三大优点

| 优点 | 成立条件 | 不应误解为 |
| --- | --- | --- |
| 减少训练状态 | 基座被冻结，只给适配器等训练参数建梯度与优化器状态 | 任意大模型都能在任意单卡训练 |
| 可以合并权重 | 适配器兼容同一基座，部署实现支持合并 | 动态多 LoRA 服务没有额外成本 |
| 易于管理多任务版本 | 记录基座、适配器与任务的绑定 | 适配器一定只有几 MB，随便换基座也能用 |

不带训练 dropout 的线性推理可在实数运算下合并为 `W′ = W + sBA`。浮点计算顺序与量化可能带来差异，不能承诺逐位一致；量化基座的反量化、合并与再量化也需重新验证。

合并后的结构可不增加 LoRA 分支计算，但未合并适配器、热加载与多适配器 batch 会有服务代价。“零额外推理延迟”需要说明比较的是哪种部署形态。

## 四、关键超参数

| 参数 | 改变什么 | 如何选择与验证 |
| --- | --- | --- |
| r | 增量容量、参数量与适配器大小 | 在固定数据和目标层下做小范围对照 |
| alpha / scaling | 旁路尺度 | 记录标准 LoRA 或 rsLoRA；联动验证学习率 |
| target_modules | 哪些矩阵可适配 | 核对模型模块名、矩阵形状与任务瓶颈 |
| dropout | 训练时的正则化 | 按验证集看过拟合，不把 0.05 当定律 |
| 学习率 / epoch | 更新幅度与训练时长 | 观察验证指标、遗忘与不稳定，不只看训练 loss |
| 长度 / batch / 累积 | 数据覆盖、激活与有效 batch | 以真实长度分布和峰值测量决定 |

扩展到 attention 与 FFN 可能改善某些任务，也会增加参数和算力；不保证比增大 r 总是更有效。GQA 下 K/V 投影宽度与 Q 不同，应按实际矩阵计数。

### 可复算：参数量、存储与线性合并

构造一个 32 层模型，每层只在两个 **4096 × 4096 方阵**上加 r=16 的 LoRA，适配器权重按 2 字节存储。不是某个实际 GQA 模型配置；7B 仅作为全模型参数分母。以下 Python 标准库代码不下载模型、不训练、不测试 GPU。

```python
layer_count = 32
module_count = 2
input_dim = output_dim = 4096
rank = 16
adapter_parameters = layer_count * module_count * rank * (input_dim + output_dim)
print(f"Adapter parameters: {adapter_parameters:,}")
print(f"BF16 adapter weights: {adapter_parameters * 2 / 2**20:.1f} MiB")
print(f"Fraction of 7B: {adapter_parameters / 7_000_000_000:.3%}")

base_weight = [[1.0, 2.0], [3.0, 4.0]]
adapter_down = [1.0, -1.0]
adapter_up = [0.5, 0.25]
input_vector = [2.0, 1.0]
scale = 2.0

def matvec(matrix, vector):
    return [sum(value * element for value, element in zip(row, vector))
            for row in matrix]

base_output = matvec(base_weight, input_vector)
down_output = sum(value * element for value, element in zip(adapter_down, input_vector))
unmerged = [value + scale * up * down_output
            for value, up in zip(base_output, adapter_up)]
merged_weight = [[value + scale * up * down
                  for value, down in zip(row, adapter_down)]
                 for row, up in zip(base_weight, adapter_up)]
merged = matvec(merged_weight, input_vector)
print(f"Unmerged: {unmerged}")
print(f"Merged: {merged}")
assert unmerged == merged
```

预期输出：

```text
Adapter parameters: 8,388,608
BF16 adapter weights: 16.0 MiB
Fraction of 7B: 0.120%
Unmerged: [5.0, 10.5]
Merged: [5.0, 10.5]
```

这个适配器仅权重就有 16 MiB，训练还需其梯度、优化器状态与激活。小矩阵示例使用易于表示的数值，不能据此保证真实 GPU 或量化合并逐位一致。

## 五、QLoRA：单卡微调超大模型

QLoRA 将冻结基座的低比特存储与 LoRA 训练结合。原论文报告了特定配置下在单张 48 GB GPU 上微调 65B 模型；这是论文实验，不是本页复现，也不是任意长度、batch 或设备都能达到的保证。

| 技术 | 作用 | 边界 |
| --- | --- | --- |
| NF4 | 面向近似正态权重分布设计的 4-bit 表示 | 不是所有张量都保证同样误差 |
| Double Quantization | 进一步量化量化常数，降低存储开销 | 仍有元数据与非量化模块 |
| Paged Optimizers | 利用统一内存处理部分显存峰值 | 不能保证永不 OOM，迁移可能有代价 |

基座低比特存储，在计算路径上按实现反量化到配置的计算精度；LoRA 与其他张量的存储和计算 dtype 由具体实现决定，不能简单说“所有计算都是 4-bit”。基座不更新，但梯度仍需通过它传播到上游适配器。

7B × 4 bit 的原始编码量约 3.5 GB，仅是权重载荷；实际训练显存还包括量化元数据、未量化模块、适配器状态、激活和工作区。是否比 BF16 LoRA 更快，取决于内核、硬件、长度和内存迁移，不能只由比特数判断。

## 六、主流变体

| 方法 | 主要改变 | 应追问什么 |
| --- | --- | --- |
| QLoRA | 冻结基座的低比特存储与训练机制 | 计算 dtype、量化误差与峰值 |
| rsLoRA | alpha / sqrt(r) 缩放 | 不同 r 下学习率与稳定性 |
| DoRA | 将权重幅度与方向分开适配 | 额外训练与部署开销 |
| LoRA+ | A、B 使用不同学习率 | 比较是否控制其他超参数 |
| AdaLoRA | 动态分配秩预算 | 总参数预算与调度策略 |
| PiSSA | 主奇异分量相关初始化 | 初始权重分解与基座绑定 |
| VeRA | 共享冻结矩阵，训练缩放向量 | 参数共享与任务迁移边界 |

名称不同不代表存在统一质量排序。上述是机制索引，不是最新排行榜；具体效果需核对原论文的模型、数据和预算。L1/L2 面试先讲清 LoRA 与 QLoRA，再按真实项目讨论变体。

## 七、多 LoRA 服务

为每个适配器记录基座版本或哈希、tokenizer、聊天模板、目标模块、r、缩放与权重 dtype。基座“名字相同”不够，错误版本可能可加载却产生错误输出。

- **单任务合并**：减少运行时分支，换任务需重新管理合并产物；保留基座与原始适配器以便回滚。
- **按请求加载**：适合多任务，但需控制加载延迟、适配器缓存、并发与权限。
- **多 LoRA batch**：由具体推理引擎提供支持；对 rank、模块和数量有限制，按实际负载测量。
- **加权融合**：增量权重可以相加，但任务效果不保证相加；拼接后的表示可能增加秩，重新压缩会引入误差。

QLoRA 训练产物部署到不同精度基座时，应分别评测未合并、合并与量化后的版本。不要把“数学上能合并”当作“服务端任意组合都支持”。

### 不要分别平均 A 与 B

两个适配器的正确目标是 $\Delta W=s_1B_1A_1+s_2B_2A_2$。分别平均 A、B 会产生交叉项 $B_1A_2$ 与 $B_2A_1$，通常不等价。可通过拼接 `B=[s₁B₁,s₂B₂]`、纵向堆叠 `A=[A₁;A₂]` 精确表示相加，秩预算随之增加；再用 SVD 截断才是带误差的压缩。部署是否支持这种 rank 和 scaling 组合，需要单独确认。

**冻结不等于无遗忘**：基座 W 保持不变，启用后的有效权重 W+sBA 已改变。验收时同时比较原基座、挂载适配器、卸载适配器、合并产物和再量化产物；这能区分训练退化、加载错误和精度误差。

## 八、实战配方（速记）

这是一套决策流程，不是无需验证的超参数处方：

1. 先有 Prompt / RAG / SFT 基线，确认问题是任务行为而非资料缺失或权限错误。
2. 按来源、用户或时间划分数据，核对模板、EOS、截断与 loss mask，避免训练集泄漏。
3. 选择有限的目标层和秩候选；只把某个常见配置作为实验起点，记录实际可训练参数。
4. 资源紧张时评估 QLoRA，同时测量峰值显存、吞吐与质量，不只看模型加载成功。
5. 检查任务指标、格式、拒答边界和通用能力；保留合并前后对照和回滚产物。

## 九、面试专项：LoRA/QLoRA 参数怎么调

| 观察到的问题 | 优先核查 | 可尝试的改变 |
| --- | --- | --- |
| 训练 loss 降，验证差 | 数据泄漏、过拟合、模板不一致 | 更好的划分、较少训练、正则化 |
| 训练与验证都差 | 标签质量、loss mask、截断、容量 | 修数据，再对照目标层与 r |
| 长样本 OOM | 激活、batch、优化器峰值与 dtype | 缩 batch、检查点、长度策略、低比特方案 |
| 线上格式退化 | tokenizer / 模板 / 基座是否一致 | 修部署绑定和测试用例 |
| 合并后指标变差 | 精度、再量化、错误适配器或版本 | 与未合并基线逐项对照 |

### 一个可复述的调参流程

固定数据、模板、训练步数和评测，先做小规模正确性检查。再分别对照目标层、r、缩放与学习率，记录质量和资源；不同时改变一堆参数后只归功于“秩变大”。最后加入部署形态、遗忘、安全与失败样例回归。

<details>
<summary>L3 / L4 追问：怎样证明低秩约束合适？</summary>

比较相同数据与资源预算下的全参、不同秩和目标层方案；观察任务效果、泛化、训练稳定性与适配器大小。若分析增量奇异值，应说明矩阵、层与采样方式，不能凭某一层的低秩谱断言全模型所有任务都低秩。

## 十、高频追问

以下为模拟追问，不宣称企业真题出处。

**为什么两个矩阵不能都零初始化？** 普通 BA 参数化下两者第一步梯度都为零；一随机一零可保持初始增量为零并给零矩阵提供学习信号。

**r 越大一定越好吗？** 容量和存储增加，但效果受数据、目标层、缩放与优化影响；需同条件比较。

**LoRA 能学新知识吗？** 可以从训练数据改变参数知识，但不保证可靠更新大量事实；需要时效和引用的任务通常还要知识治理或 RAG。

**QLoRA 量化了什么？** 主要是冻结基座的存储表示，不等于梯度、激活和所有计算都 4-bit。

**能承诺零推理开销吗？** 说明是否合并、是否量化和是否多适配器服务；只有满足部署条件才讨论无新增分支计算。

**项目怎样讲？** 用真实数据划分、可训练参数、峰值测量、对照指标、失败样例和回滚方案回答，不编造训练成绩。
