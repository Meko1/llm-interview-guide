# 垂直领域专家模型实战

> **领域模型首先是一个可验收的系统，而不是一个行业名称。** L2 读者应能把事实缺失、任务行为、计算错误与权限问题分开，再决定哪些值得训练。本文的行业段落是设计练习，不是已复现项目，也不构成专业服务或合规保证。基础见 [微调范式（SFT / PEFT）](/finetuning/finetuning)、[LoRA / QLoRA 详解](/finetuning/lora)；选型见 [RAG vs 长上下文 vs 微调](/rag/rag-vs-long-context)。

## 面试先背这几句话

- 标准技术路线：**开源底座 →（可选）领域继续预训练 CPT → 领域 SFT →（可选）偏好对齐 → RAG 外挂时效知识**——每一步都要能说清「做不做的判断依据」。
- 训练可以改变术语理解、任务行为和参数知识；需更新、引用、权限控制的事实优先走检索或工具。二者不是知识类型的硬分界。
- CPT 没有通用的「B 级 token 起步」门槛：先证明领域分布适配能改善下游任务，再比较数据与算力成本。
- 最大风险是**灾难性遗忘**：领域能力上去了，通用能力（指令遵循/安全）掉下来——靠**混合通用数据回放（replay）**与评估双轨制防守。
- 评估必须**行业基准 + 自建业务评测集**双轨：C-Eval 高不代表会写你们医院的病历摘要。

## 一、先想清楚：要不要训模型

面试第一个加分点是**先质疑需求**。决策树：

```
业务需求
 ├─ 通用模型 + 好 prompt 能满足验收？ ──是──► 不增加训练链路
 ├─ 缺的是「事实知识」（条款/价格/文档）？ ──是──► RAG（见 RAG vs 微调）
 ├─ 缺的是「输出格式/风格/任务范式」？ ──是──► 对照 SFT/LoRA 与约束解码
 └─ 缺的是「领域语感/术语理解/推理套路」
      且有大量领域语料？ ──是──► 继续预训练 CPT + SFT
```

把真实失败按任务切片：找不到依据、找到却理解错、引用错版本、输出不合格式、算错数、越权调用。检索召回不足时训练表达通常治不了根因；事实正确但输出结构持续不稳时，SFT 才是有理由的候选。先固定未用于调参的验收样本，再投入训练。

## 二、标准四段式技术路线 ★

### 2.1 底座选择

- 同时比较能满足部署约束的候选，不从尺寸推断行业胜任力。记录底座版本、上下文长度、语言覆盖、工具/结构化输出表现和授权条件。
- 用同一检索证据和解码预算比较小模型与大模型；分开记录任务质量、尾延迟、吞吐与运行成本。预算相等不一定 token 数相等。

### 2.2 领域继续预训练（CPT，可选）★

在底座上用领域语料继续做自回归预训练：

- **假设**：已有模型对领域分布的建模不足，且这种不足确实限制目标任务。领域 held-out loss 是诊断信号，不是业务成功的替代指标。
- **数据**：去重、保留出处和使用权限，按来源/时间隔离评测。通用 replay 比例、学习率与训练步数是实验变量，不套固定配方。
- **对照**：相同 SFT 数据下比较「底座 → SFT」与「底座 → CPT → SFT」；再比较等总训练预算，防止把多训练的收益都归给 CPT。
- CPT 从 Base 或 Instruct 起步的结果不同；继续预训练可能损伤聊天行为，不能把产物自动称为已可部署的助手。

### 2.3 领域 SFT ★

- **数据来源**：真实业务问答脱敏、专家撰写、强模型合成+专家审核（见 [合成数据与自我改进](/finetuning/synthetic-data)）、领域考试题改造（执业医师/法考/CPA）。
- 用学习曲线确定样本需求：增加数据后是长尾错误减少，还是近重复样本增多？按数据源拆效果，而不把「数千条」当充分条件。
- 通用指令 replay 与 LoRA 都是待验证的防退化措施。冻结基座不保证挂载适配器后的有效模型不遗忘。
- 格式训练应与 schema 校验结合；结构正确不等于专业内容正确。聊天模板、回答 mask、EOS 和截断策略须与部署一致。

### 2.4 对齐与安全（行业强相关）

- 先由业务、专业人员和治理负责人定义辅助服务边界：哪些可回答、哪些需转人工、哪些动作不得自主执行。法律义务需按地区和实际服务确认，本页不推断具体法规。
- 拒答示范或 DPO 只能改变行为倾向。系统侧仍需授权、证据版本控制、人工批准和审计；免责声明不是安全措施的替代品。

### 2.5 RAG 补时效（永远需要）

需要依据版本回答时，检索应返回出处、版本和有效期，并做权限过滤。模型可能记住旧事实，不能仅靠「外挂 RAG」消除冲突：要测试证据与参数记忆不一致时是否遵循证据、是否拒绝无依据的补全。并非所有离线任务都必须部署检索；见 [RAG 生产化与系统设计](/rag/rag-production)。

## 三、灾难性遗忘：领域模型的头号大坑 ★

**构造情境**：摘要模板更稳定，正常通用请求却更容易被拒。此时领域平均分提升不能掩盖行为退化。

| 防守手段 | 做法 |
| --- | --- |
| **数据回放（replay）** | CPT/SFT 阶段混入通用数据（比例见上文），最重要的手段 |
| 小学习率 + 早停 | 在独立验证曲线上选择，不保证学习率越小越好 |
| LoRA 而非全参 | 可卸载适配器恢复原基座；启用适配器时仍须测通用能力 |
| 模型合并 | 领域模型与通用模型做权重合并找平衡（见 [模型融合与合并](/finetuning/model-merging)） |
| **评估双轨制** | 每个 checkpoint 同时跑领域评测和通用评测（MMLU/CMMLU+安全集），任何一边超阈值下降即报警 |

## 四、行业案例拆解（面试可直接引用的叙事）

### 4.1 医疗（HuatuoGPT / DISC-MedLLM 类路线）

本节保留原研究名称作为检索入口，不声称这些项目都执行了同一训练流程。以「脱敏记录摘要」为设计练习：训练输出结构，检索提供受控术语表，专家判断事实是否来自记录。测试遗漏重要条件、擅自补充信息和跨患者资料泄漏，考试题成绩不能替代这三项验收。

### 4.2 法律（LaWGPT / DISC-LawLLM 类路线）

以「材料整理和依据检索」为练习：检索返回指定法域、时间版本的材料；模型区分材料原文与推断。失败测试包括存在但不支持结论的引用、过期条文、事实条件缺失。检索不能保证引用准确，须逐项核查支持关系；具体专业意见交由有权限的人员审阅。

### 4.3 金融（轩辕 / DISC-FinLLM 类路线）

以「公告抽取与比率计算」为练习：模型抽字段，工具执行明确公式，输出单位、报告期和来源。测试币种错配、合并/单体口径混用、分母为零与工具超时。工具只保证所执行的计算，不保证输入字段和业务口径正确。

共同原则：每一条链路都要有独立验收。训练、检索、工具和对齐分工能减少风险，但任何一个都不是正确性保证。

## 五、评估：双轨制 + 业务金标准

1. **行业公开基准**：用于可比任务表现，先读数据和评分协议；不以考试成绩证明专业服务胜任力。
2. **自建业务评测集**：按高频任务、风险和长尾分层，由专家定义正确性。样本量由要检测的差异与可接受不确定性决定，不用固定 200~500 条作上线门槛。
3. **通用能力守门**：CMMLU/MMLU + 指令遵循 + 安全拒答，防遗忘。
4. **上线后**：专家抽检 + 用户反馈回流，构成数据飞轮（见 [LLMOps](/engineering/llmops)）。

## 六、常见坑清单

- ❌ 未定位检索错误就开训 → 训练支出增加，缺证据的根因仍在。
- ❌ 只测领域任务 → 漏掉通用行为和安全回归。
- ❌ 只用蒸馏合成数据 → 模型「说得像专家」但推理浅（合成数据同质化）。
- ❌ 只刷行业榜 → 榜单高分、业务不可用（榜题≠业务分布）。
- ❌ 用参数记忆代替版本化证据 → 无法可靠回答「依据哪一版材料」。
- ❌ 认为对齐后可越过授权和人工审核 → 模型行为倾向不是服务许可。

## 高频追问

1. **给某行业做专家模型的完整路线？** 底座选型→（语料够且分布差异大时）CPT→领域 SFT（混通用数据）→行业对齐→RAG 补时效；每步给出做/不做的判断依据。
2. **哪些知识进权重、哪些走 RAG？** 语感/术语/推理套路/输出范式进权重；时效性事实、条款、需溯源内容走 RAG；数值计算交给工具。
3. **什么时候考虑 CPT？** 先用下游对照证明领域分布适配有收益；无统一 token 门槛，必须同时测遗忘和总成本。
4. **灾难性遗忘怎么防？** 数据回放（领域:通用混合）、小学习率少 epoch、LoRA 冻结底座、模型合并、领域+通用评估双轨守门。
5. **领域 SFT 数据从哪来？** 授权日志、专家示范、经过验证的合成数据；按来源隔离评测并用学习曲线决定数量。
6. **怎么评估领域模型？** 行业基准（证明懂行）+ 自建业务金标准集（证明可用）+ 通用/安全守门（证明没退化），三者缺一不可。
7. **小模型能胜过大模型吗？** 这是具体任务、预算和评测下的实验问题；报告切片与置信区间，不由参数量预设赢家。
8. **行业边界怎样落实？** 业务定义服务范围，系统限制动作权限，专家验收风险样本；对齐不提供法律或专业资质保证。

## 交付物：一份可否证的训练立项

| 决策 | 最少应交付的证据 | 停止条件 |
| --- | --- | --- |
| 是否 CPT | 固定 SFT 后的 CPT 消融、等预算对照 | 只降低语料 loss，没有下游收益 |
| 是否 LoRA | 实际参数清单、训练与部署基座绑定 | 业务改善不足以覆盖维护成本 |
| 是否偏好优化 | 同上下文偏好标注、分歧和误拒切片 | 奖励上涨而独立正确性下降 |
| 是否上线 | 留出集、专家风险集、权限与回滚演练 | 任一不可接受风险未被控制 |

[Don't Stop Pretraining（ACL 2020）](https://arxiv.org/abs/2004.10964)在四个领域、八个分类任务中研究领域/任务适配，支持「应实验比较适配收益」，不建立生成式行业助手的通用语料量门槛。上述行业项目名称未在本轮逐一核实，不能当已验证的复现案例。
