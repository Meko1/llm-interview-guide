# 合成数据与自我改进（Synthetic Data & Self-Improvement）

> **流畅不是正确，筛选通过不是可信，条数不是覆盖。** L2 重点是数据与成本闭环；L3 应能设计教师、筛选器和比例的消融。前置：[数据工程](/pretraining/data-engineering)、[RLHF/DPO](/finetuning/rlhf)、[推理模型](/advanced/reasoning-models)。

## 面试先背这几句话

合成可扩展指令、轨迹和偏好反馈；质量仍需外部核查。监督蒸馏、拒绝采样与在线 RL 的更新机制不同。模型崩溃是递归训练的风险，不是所有合成数据必然退化，也没有通用安全混合比例。

## 一、为什么合成数据从"补充"变成"主力"？

可验证的动机是缺少授权示范、轨迹或偏好标签，而不是无法核实的「所有大厂耗尽互联网」。生成前先声明缺口：格式、解法、长尾还是偏好？然后说明真实性依据、目标分布和验证成本。

Phi-1 原论文包含筛选网页与合成教材/练习，不能说 Phi 预训练几乎全部合成。R1 蒸馏总样本数也不是纯推理轨迹数。任何规模数字都要绑定版本、阶段和单位，题目数、轨迹数、token 数不能互换。

## 二、五条技术路线全景

### 2.1 Self-Instruct（Alpaca 谱系）

从种子生成指令、输入、输出，过滤无效或相似样本后训练。Alpaca 借鉴这种方法，但原论文、ShareGPT 对话与人工开放标注不是同一条数据谱系，不能混写教师版本和 API 成本。保存种子、教师、prompt、采样设置及过滤原因。

### 2.2 Evol-Instruct（WizardLM/Math/Coder）

增加约束、推理步骤或主题来构造更复杂指令。新约束可能矛盾、不可解或与旧答案不匹配，须保存原题、进化操作、解答和验证结果。对照原指令、随机改写与复杂化，固定样本数或生成预算，不能宣布复杂度永远比数量重要。

### 2.3 强蒸馏（Strong-to-Weak Distillation）

教师生成文本经筛选后，学生用 SFT 拟合目标 token；这不一定有教师 logits 或 KL 损失。DeepSeek-R1-Distill 用教师生成数据微调小模型；学生模仿可见轨迹，不等于复制教师内部推理。是否优于同预算 RL 依赖底座、覆盖与验证器，不由「小模型不可能探索」决定。

### 2.4 拒绝采样（Rejection Sampling）

每题生成 N 条候选，按规则/RM 筛选后用于 SFT。它与推理 best-of-N 有相似筛选步骤，但用途不同，不能保证更省。

**构造账本**：100 题，每题 8 条、每条 500 token，生成约 400,000 token；每题只留一条，则目标约 50,000 token。生成、评分、执行验证都要计成本，不能只报保留条数。

独立候选、单条成功概率 p 时，至少一条成功概率为 $1-(1-p)^N$。现实候选相关，筛选器也会选错，这不是实际通过率保证。

### 2.5 自我改进（Self-Improvement）

| 研究 | 更新机制 | 外部信号 |
| --- | --- | --- |
| STaR | 失败时给正确答案重生成 rationale，筛选后 SFT | 已知答案和种子 |
| rStar-Math | MCTS、代码增强轨迹、过程偏好模型、自进化 | 题目、执行与验证条件 |
| ReST-EM | 采样、筛选、再训练 | 奖励和任务分布，细节待核 |
| R1-Zero | 基座直接在线 RL | 预训练能力、题目、规则奖励 |
| Absolute Zero | 提议任务、求解、环境反馈和课程演化 | 预训练模型与执行环境 |

Zero 不等于没有预训练或环境知识。R1-Zero 的策略梯度不是拒绝采样 SFT 的极限，自进化也不是开放任务正确性保证。

## 三、按领域看合成数据的现状

### 3.1 数学推理

MetaMathQA、NuminaMath、OpenMathReasoning、DAPO-Math-17k 保留为资料入口，本轮未核定其版本规模。原题改写可与 benchmark 同源；最终答案正确不证明步骤正确，用于过程监督时还须步骤核查。

### 3.2 代码

CodeAlpaca、WizardCoder、Magicoder/OSS-Instruct 是不同构造思路。真实代码片段可约束输入分布，但不保证题目有效、许可适用和测试充分。独立隐藏测试、超时和沙箱不可少，参考解不能泄漏到题目材料。

### 3.3 偏好数据（RLHF 用）

Constitutional AI 用原则指导批评、修订和 AI 反馈；UltraFeedback、PairRM、Nemotron 是数据/评分模型入口，不能说每个评分模型都生成训练对。记录候选、同一上下文、rubric 和配对过程。位置交换、长度匹配和专家校准可以发现偏差；同一模型生成、筛选、验收会削弱独立性。

### 3.4 中文与多语

BELLE、Firefly、MOSS 等保留为旧资料索引，不宣称全部同源。翻译扩展需核查术语、地区语境和答案有效性；英文题翻译不是独立多语评测。

## 四、数据质量控制：合成 ≠ 有效

### 4.1 数量 vs 质量：LIMA 观察

LIMA 在特定 65B LLaMA 上用 1,000 条精选样本展示适配价值，不证明任意任务千条足够，也不证明预训练只重数量。分别画新增数据量、过滤强度与业务收益/长尾覆盖曲线。

### 4.2 语义去重

字面和 embedding 匹配都是候选发现器。过严阈值会删不同边界条件，过松会让同题改写跨 train/test 泄漏。抽查命中、未命中；按源题/材料家族划分，不编造统一可删比例。

### 4.3 难度平衡（Curriculum）

只保留易验证题会损失长尾，全错组可能无相对奖励信号。DAPO 动态采样针对组内无区分奖励，不是通用 SFT 删除所有难题。按目标模型、奖励和任务类别估计难度。

### 4.4 数据配比

没有通用 `40:20:20:10:10` 配方。固定原始来源、训练 token 和验收集，逐步改变合成比例；教师、筛选器和任务类别分别消融，不能多变量一起改变后只归因于比例。

## 五、模型崩溃（Model Collapse）

Shumailov 等研究递归生成训练的分布退化，包括尾部事件消失。风险依赖是否替换数据、是否累积真实来源、采样和拟合误差，不能简化为所有模型只输出最高概率 token。

### 5.1 会不会真的发生？

在自己的递归设置中验证：固定真实留出集，按代记录罕见样本、重复度、覆盖与任务质量。不宣称大厂从不纯递归，也不由一代未下降推断长期无风险。

### 5.2 三件套对策

| 措施 | 用途 | 不足 |
| --- | --- | --- |
| 授权真实来源 | 分布锚点 | 无统一 `>30%` 安全线 |
| 独立验证/专家复核 | 降低错误标签 | 有选择偏差 |
| 长尾与多样性评测 | 监测覆盖损失 | n-gram/embedding 不保证质量 |

**验证器算例**：真实正确率 60%，正确样本保留 90%，错误样本误留 10%；保留后正确率为 `0.6×0.9/(0.6×0.9+0.4×0.1)≈93.1%`，仍有约 6.9% 错误，保留率仅 58%。这是构造假设，现实概率按类别变化。「通过验证器」不等于真实正确。

## 六、合成数据的伦理与法律

按实际条款版本、法域和用途核查教师/API、输入材料、个人信息和输出用途；开源教师不自动解除其他限制。本页不是法律意见。保留教师、时间、原材料、验证器版本、保留原因和撤回路径；修正模型自称不是来源或合规证明。

## 高频追问

**能替代真实数据吗？** 执行/形式任务可高度依赖合成，但开放分布覆盖、事实与授权仍需外部依据，不作统一判断。

**蒸馏为何可能有效？** 获得可模仿轨迹，减少搜索负担；不证明复制教师机制或必胜同预算 RL。

**STaR 与 R1-Zero？** 带答案信号的迭代监督、在线奖励驱动的策略优化，目标不同。

**怎样防污染？** 保存源题家族，字面/语义匹配与人工复核结合；私有题和时间切分是补充，不证明教师从未见过。

<details>
<summary>自测：过滤后正确率更高，学生为什么可能更差？</summary>

过滤可能删除难题和长尾，使数据偏离业务。检查覆盖、误留/误删和源题泄漏，在独立验收集比较等训练 token 的方案；筛选正确率与学生任务质量不是同一指标。
