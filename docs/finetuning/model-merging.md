# 模型融合与合并（Model Merging）

> **合并省的是再训练步骤，不是实验、内存和验收成本。** L2 读者需要解释兼容条件与失败模式；L3 可以继续研究权重空间和消融。前置：[微调范式](/finetuning/finetuning)、[LoRA](/finetuning/lora)。

## 一、什么是模型融合？

权重合并在参数空间组合多个模型，产出一个部署模型；输出 ensemble 在推理时调用多个模型再组合预测。两者的延迟与资源账本不同。常见线性合并不需要反向传播，但选系数仍需要验证数据，大模型权重读写也消耗 RAM、磁盘和时间。

```text
同源底座 θ₀ → 微调 θ₁、θ₂ → 兼容性核查 → 权重合并 θ_merge
                                      → 任务/安全/成本评估
```

对于逐元素线性合并，必须先对齐架构、张量形状、词表和参数语义。同源底座能降低不对齐风险，但不是成功保证。结构相同却独立训练的模型可能存在神经元排列差异，直接平均通常缺乏依据。

## 二、为什么能 work？任务向量（Task Vector）

$$\tau_i=\theta_i-\theta_0,\qquad \theta_{merge}=\theta_0+\sum_i\lambda_i\tau_i.$$

任务向量是一次微调的**参数增量**，不是可独立搬运的语义能力。加、减、缩放可能改变任务行为；减去某个向量不证明已经删除知识或消除危险能力。

部分同源微调模型之间存在低损失连接，是合并可行的经验依据；不能断言所有任务都在同一个盆地。最直接的检查是在多个插值系数处测任务 loss 和业务指标，观察是否出现高损失障碍。

**构造冲突例子**：基座两个参数 `[0,0]`，两个增量 `[2,1]`、`[-2,1]`。等权平均为 `[0,1]`，第一维更新抵消，第二维保留。我们能证明数值抵消，但不能据此称第一维代表数学能力、第二维代表代码能力。

## 三、主流合并算法

| 算法 | 机制 | 应验证的假设 |
| --- | --- | --- |
| Linear / Model Soup | 对兼容权重加权平均 | 候选之间是否有可用的低损失区域 |
| SLERP | 在向量化权重间按角度插值 | 哪些张量参与、近共线/零范数如何处理 |
| Task Arithmetic | 加权组合相对同一底座的增量 | 更新冲突和系数敏感性 |
| TIES | 裁剪小增量、选择符号、同符号合并 | 小值不一定不重要，符号规则需明确 |
| DARE | 随机丢弃增量并重缩放 | 稀疏率、随机种子及增量幅度适用范围 |

TIES 的 elect sign 不能简单写成「按任务个数多数投票」：原方法考虑增量幅度来选择聚合方向，然后合并与选定符号一致的值。裁剪和符号消融应分别比较，避免把所有收益归给一个步骤。

DARE 令丢弃率为 $p<1$，保留掩码 $m_j\sim\mathrm{Bernoulli}(1-p)$，$\tilde\tau_j=m_j\tau_j/(1-p)$。因此 $E[\tilde\tau_j]=\tau_j$。**无偏的是参数增量的期望，不是模型输出或任务分数**；非线性网络不满足一般的 $E[f(\theta+\tilde\tau)]=f(\theta+\tau)$。论文中的高稀疏率实验不构成「丢掉 90% 永远无损」的保证。

MergeKit 可作为实现入口，但具体支持的算法和配置应锁定版本，不以工具名称替代实验。

## 四、特殊形态

- **Frankenmerge / Passthrough**：拼接或复用层，改变深度和中间激活分布；不是普通逐元素平均，必须检查结构和推理配置。
- **MoE 化合并**：引入专家与路由，改变激活参数、路由质量和部署成本，见 [MoE](/basics/moe)。
- **LoRA 合并**：先理解 $\sum_i s_iB_iA_i$；分别平均 A 与 B 会产生交叉项，通常不等价。精确拼接可能增秩，再压缩会有误差。

## 五、适用场景与边界

适合作为已有兼容 checkpoint 的低训练成本候选：多任务折中、同任务不同训练配方组合，或领域适配与通用能力平衡。它不是不需要评测的「免费升级」。

| 失败表现 | 可能机制 | 应做的检查 |
| --- | --- | --- |
| 无法加载或词表错乱 | 张量/词表/配置不兼容 | 名称、形状、tokenizer 与特殊 token |
| 某任务明显退化 | 增量冲突、缩放不合适 | 单任务切片、系数消融、插值曲线 |
| 安全行为变弱 | 合入分支改变拒答/权限行为 | 危险与正常请求分别评估 |
| 公开榜高、业务差 | 多次用榜单挑配方 | 开发集选配方，冻结验收集一次确认 |
| 再量化后退化 | 合并改变权重分布 | 合并前后、量化前后分别对照 |

数据集授权、模型许可证和输出用途都要核查；合并不会自动消除源模型的使用限制。

## 高频追问

**为什么合并可能有效？** 同源微调在参数空间中可能存在可组合区域，但必须用任务指标验证，不假定能力可线性相加。

**任务向量能删除某种知识吗？** 可作为行为干预候选，不能证明知识擦除；应独立测试记忆、泛化与安全。

**TIES 和 DARE 的区别？** 前者处理小增量与符号冲突；后者随机稀疏化并保持增量期望。没有统一胜负关系。

**不同底座一定不能合吗？** 普通同坐标线性合并需要严格兼容；跨底座对齐或结构拼接是另外的研究问题，不能冒充直接平均。

**Model Soup 的数据是什么？** 常比较同一预训练初始化、同一下游任务的不同微调配方；它不是只平均同一训练过程相邻 checkpoint 的同义词。

## 一手来源与验证边界

- [TIES-Merging](https://arxiv.org/abs/2306.01708)：已读取干扰与三步骤描述；效果不外推到所有模型。
- [DARE / Language Models are Super Mario](https://arxiv.org/abs/2311.03099)：随机丢弃与 `1/(1-p)` 重缩放。
- [Model Soups](https://arxiv.org/abs/2203.05482)：作为低损失连接与同任务权重平均的研究入口，本轮不声称完整复现。

本文算例为参数代数，不执行真实权重合并，也不验证生产质量或硬件耗时。
