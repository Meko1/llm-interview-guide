# 多模态大模型

“能看图”可以指图文检索、OCR、看图问答或生成图像，任务并不相同。本文先建立**表示 → 对齐 → 生成 → 验证**的地图；连接器和推理张量细节见 [VLM 架构](/multimodal/vlm-architecture)。图像生成见 [扩散模型](/multimodal/diffusion)，音频见 [语音大模型](/multimodal/speech)。

## 一、什么是多模态大模型？

多模态模型处理不止一种输入或输出模态。这里重点讨论图像与文本：

| 任务 | 模型输出 | 能力边界 |
| --- | --- | --- |
| 图文检索/零样本分类 | 相似度或类别 | 匹配不是自由文本生成 |
| OCR/文档理解 | 文字、结构、引用 | 转录正确不等于跨表关系正确 |
| 视觉问答/图表分析 | 自然语言或结构化答案 | 答案流畅不等于有图中证据 |
| 图像/视频生成 | 像素或潜变量再解码 | 理解视觉输入不自动拥有此输出接口 |

“VLM”在不同文献中可指较宽的视觉语言模型；本文的生成式 VLM 特指能基于视觉输入生成语言答案的模型。产品支持哪些模态，要查具体版本和接口，不能从系列名推断 any-to-any。

## 二、CLIP：图文对比学习的基石

[CLIP（2021）](https://arxiv.org/abs/2103.00020) 用图文配对训练两塔编码器。给 batch 中的图像表示 $u_i$、文本表示 $v_j$，相似度 $s_{ij}=u_i^\top v_j/\tau$，单向损失可写为：

$$\mathcal L_{I\to T}=-\frac1N\sum_i\log\frac{\exp(s_{ii})}{\sum_j\exp(s_{ij})}.$$

再与文本到图像方向组合。对角线是配对正例；非配对样本作为对比候选，但其中也可能语义相关，不能都视为真实错误。

训练得到的是**可比较的联合表示**，不是把每个视觉 patch 直接变成某个 LLM 词向量。CLIP 可以用文本类别提示做分类或检索，不直接自回归生成答案；全局相似度也可能忽略小字、计数或位置关系。

## 三、ViT：把图像变成 token

[ViT（2020）](https://arxiv.org/abs/2010.11929) 把图像分成 patch，再映射为连续向量序列。视觉 token 通常不是 tokenizer 词表里的离散 ID；使用 Transformer 也不等于使用与文本相同的训练目标。

构造例：$224\times224$ 图片、$16\times16$ patch，共 $(224/16)^2=196$ 个 patch。额外 token、缩放、裁剪与 connector 压缩要单算。把分辨率放大一倍会使 patch 数约四倍，不是两倍；小字是否可读，还取决于原图质量与预处理。

## 四、主流架构：以 LLaVA 为例

```text
像素 → 视觉编码器 → 特征序列 → 连接器 → 视觉嵌入
文本 → tokenizer → 文本嵌入                 ↓
                         混合输入 / 交叉读取 → LLM → 文本答案
```

[LLaVA 原论文 v2（2023）](https://arxiv.org/html/2304.08485v2) 使用 CLIP ViT 与**线性投影**连接 LLM。第一阶段冻结视觉编码器与 LLM，训练投影；第二阶段保持视觉编码器冻结，更新投影与 LLM。不能把后续 LLaVA 变体的 MLP 写成原版唯一结构。

[BLIP-2（2023）](https://arxiv.org/abs/2301.12597) 使用 Q-Former 桥接冻结的视觉编码器与语言模型，其两阶段预训练目标不是 LLaVA 两阶段的同义表述。连接器选择决定保留多少视觉细节、训练哪些参数和语言侧 token 成本。

## 五、原生多模态 vs 适配器式

这不是严格互斥的架构分类。至少分三个轴：

- **初始化**：复用已预训练模块，还是重新训练某些模块。
- **数据/训练**：何时混合模态、哪些参数冻结、用什么损失。
- **融合/接口**：拼接嵌入、交叉注意力、输入与输出支持哪些模态。

“原生”可以是厂商训练描述，不足以证明没有编码器或连接器，更不能推出能力必然比复用模块强。[Qwen2-VL 报告 v1（2024）](https://arxiv.org/html/2409.12191v1) 就展示复用初始化、分阶段联合训练、动态分辨率等设计，不能简单归为“外挂所以浅”。

**早期融合**描述信息何时交互，**后期适配**描述训练/开发时间，两者不是同一个轴。闭源模型未披露的融合结构应标为未知，不从实时音视频体验反推统一 token 结构。

## 六、工程挑战：高分辨率与 token 爆炸

| 处理方式 | 收益 | 可能丢失什么 |
| --- | --- | --- |
| 全图缩放 | 视觉预算低 | 小字、细线、低对比度区域 |
| 高分辨率/动态尺寸 | 保留更多细节 | token、prefill 与 KV 成本上升 |
| 全局图 + 局部裁剪 | 兼顾布局与局部识别 | 裁剪坐标和跨块关系需保留 |
| Query/局部合并压缩 | 限制语言侧 token | 压缩可能丢掉细粒度事实 |

Qwen2-VL 报告描述动态视觉 token 与邻近 token 合并，实际输入预算还受 processor 设置约束。视觉编码器开销、connector 开销、LLM prefill 与文本 decode 应分别测；降低输出 token 不能抵消所有高分辨率成本。

视频理解增加帧采样与时间信息，短暂动作可能被采样漏掉；不要用图像问答分数证明视频事件理解可靠。

## 七、多模态幻觉

[POPE（2023）](https://arxiv.org/abs/2305.10355) 用询问物体是否存在的方式分析物体幻觉。它能检查特定对象存在性，不覆盖 OCR 数字、关系、时间顺序或图表计算的全部错误。

**失败例**：问“图中停车场有几辆车”，模型因场景先验补出被遮挡或根本不存在的车。另一种错误是读出表格数字，却把列标题对应错。两者的修复方向不同，不能都叫“多加分辨率”。

可验证流程：保存原始输入和预处理版本；要求证据区域或坐标；用人工/工具核对关键字段；加入无目标、遮挡、低清、否定和图文冲突样本。高风险结论无证据时拒答或升级，图内文字也应当作不可信输入处理。
