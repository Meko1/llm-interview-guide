# 多模态大模型架构深挖（VLM）

本页回答“图片到底怎样进入 LLM”，重点是**张量形状、参数训练范围、位置/掩码与成本**。概念总览见 [多模态大模型](/multimodal/multimodal)，检索场景见 [多模态 RAG](/rag/multimodal-rag)。示例限公开报告，不反推闭源模型内部结构。

## 一、核心问题：模态鸿沟

LLM 计算的是嵌入向量序列，不是只接受离散文本 ID。视觉模块可以提供连续向量，但**维度相同不代表语义已兼容**：模型必须学会如何用视觉信息生成答案。

```text
像素 → 预处理 → 视觉特征 [B, Nv, dv]
                      ↓ 连接器
                视觉嵌入 [B, Nc, dL]
文本 ID → 文本嵌入 [B, Nt, dL]
                      ↓ 拼接或交叉读取、位置与掩码
                    LLM → 文本 logits
```

$N_v$ 是视觉编码器输出长度，$N_c$ 是连接后长度，$d_v$ 与 $d_L$ 是视觉/语言隐藏维度。它们不一定相等。连续视觉嵌入通常不需要量化成文本词表中的 ID。

图中链路只是常见实现。推理还要处理模板里的图像占位符、图像数量、patch 顺序、位置编码、padding 与 attention mask；任何一项不匹配都可能“能跑但答错”。

## 二、三大组件

### 1. 视觉编码器（Vision Encoder）

[ViT（2020）](https://arxiv.org/abs/2010.11929) 把 patch 映射成表示，再经 Transformer 建模。[CLIP（2021）](https://arxiv.org/abs/2103.00020) 提供图文对比训练路线；其全局联合表示不能等同于所有 patch 已对齐 LLM。

[LLaVA 原论文 v2（2023）](https://arxiv.org/html/2304.08485v2) 使用 CLIP ViT-L/14。[Qwen2-VL v1（2024）](https://arxiv.org/html/2409.12191v1) 则描述来自 DFN 的 ViT 初始化与后续修改。不能把所有模型的视觉编码器都写成 CLIP，也不能从初始化来源推断最终冻结状态。

视觉编码器用哪一层特征、是否保留特殊 token、如何缩放/切图都影响后续输入；更深层不必然更适合 OCR 细节。

### 2. 连接器 / 投影器（Connector / Projector）

| 结构 | 长度变化与计算 | 取舍 |
| --- | --- | --- |
| 线性/MLP 投影 | 通常 $N_c=N_v$，变换隐藏维度 | 保留 patch 序列，但语言侧成本随长度增长 |
| 可学习 query 的 Q-Former/Resampler | 用固定/受控 query 读取视觉特征 | 限制语言输入长度，但可能丢细粒度信息 |
| 邻近特征合并/空间重排 | 相邻位置合并为更少 token | 降语言侧长度，需保持布局和位置一致 |
| LLM 中的交叉注意力 | 语言状态读取外部视觉状态 | 不必把全部图像嵌入拼到自注意力序列，仍有读图计算 |

原版 LLaVA 是线性投影；后续 MLP 变体不能追溯成原论文结构。[BLIP-2（2023）](https://arxiv.org/abs/2301.12597) 用 Q-Former 连接冻结模块，并有自己的两阶段预训练目标，不能将它视为“几层 MLP 的压缩版”。

Qwen2-VL 报告具体使用 MLP 将邻近 $2\times2$ token 合并为一个；不要把任何 token 合并笼统称为相同的 pixel shuffle 实现。连接器类型也不能单独决定谁的质量“最高”或训练“最便宜”。

### 3. LLM 主干

嵌入拼接路径通常令视觉和文本共同进入语言 Transformer，但位置、掩码和训练损失可以不同，不能说被“一视同仁”。文本生成用输出词表，不意味着视觉 token 都接受下一文本 ID 的监督。

推理分两个阶段：prefill 编码视觉/文本上下文并建立缓存；decode 逐步生成文字。多轮中是否重算图像取决于接口与缓存设计，不能默认永远只算一次。

## 三、两种融合方式

沿用原标题，但更准确的比较不是“适配器浅、原生深”。区分：

| 轴 | 要查的问题 |
| --- | --- |
| 信息融合 | 自注意力拼接、层间交叉读取，还是其他结构？ |
| 模块初始化 | 视觉、语言、连接器从何初始化？ |
| 训练时点 | 在哪些阶段混合图文/视频数据？ |
| 可训练参数 | 哪些阶段冻结或解冻哪些模块？ |
| 输出接口 | 只输出文本还是也能生成图像/音频？ |

“早期融合”是计算位置，“后期适配”是训练/开发时点，二者不是同义词。复用模块后再联合训练也可以形成强交互；厂商称“原生”不自动证明单一网络、统一离散词表或 any-to-any 能力。

对于未公开内部结构的产品，只能说接口/发布材料提供什么证据，不推断参数或融合深度。

## 四、训练流程（适配器路线）

以 LLaVA 原论文 v2 为具体例子：

```text
阶段一：图文配对 → 冻结视觉编码器与 LLM → 训练投影层
阶段二：多模态指令 → 视觉编码器仍冻结 → 更新投影与 LLM
```

冻结省去相应反向与优化器成本，也防止小数据改变已有表示；同时限制了视觉端适配。解冻可能改善领域视觉，但需要数据、优化与遗忘控制，不是“编码器已完全对齐，所以没必要训练”。

BLIP-2 的两阶段分别引导视觉语言表示学习与视觉到语言生成学习，不能仅按阶段数与 LLaVA 合并。Qwen2-VL 报告则描述：先训练视觉部分，再全参数训练，最后冻结 ViT 并做语言侧指令适配。**两阶段、三阶段是版本配方，不是通用定律。**

训练时要核对标签 mask：图像位置、提示位置和回答位置是否接受监督，以及多轮模板、EOS 和图像占位符是否正确。模型能输出答案并不能排除它只凭文本先验；需要去图、错图、图文冲突等对照验证视觉使用情况。

## 五、高分辨率与视频的难题

### Qwen2-VL 的版本化 token 例子

报告给出 $224\times224$ 图片、patch size 14，原始网格有 $16\times16=256$ 个 patch；邻近 $2\times2$ 合并后为 64 个视觉内容 token，再加两个视觉边界标记为 66。这个数字限定报告的输入路径，不是任意尺寸图片的固定 token 价格。

动态分辨率仍有 processor 的像素/长度限制；“支持不同长宽比”不等于原图不缩放、无限分辨率或 OCR 必然准确。视觉编码器仍要先处理原始 patch，连接后长度更少不表示前面计算全部省掉。

### 把成本拆到模块

| 成本项 | 与什么相关 | 常见误判 |
| --- | --- | --- |
| 视觉编码 | 分辨率、切图数、原始 patch | 只看连接器输出 token |
| 连接器 | 合并/query 数、隐藏维度 | 以为压缩是无损且免费 |
| LLM prefill/KV | 视觉 + 文本长度、结构与精度 | 只统计用户文本 token |
| 文本 decode | 输出长度、缓存、batch | 误把短答案当成低总成本 |

视频理解还涉及采样时刻、帧顺序和时间编码。Qwen2-VL 报告的 M-RoPE 分开表达时间与空间位置；它不是自动保证对任意长视频的完整记忆。密集抽帧提高成本，稀疏抽帧可能漏掉短暂动作，需要按任务比较。

理解视频的视觉编码与生成视频的时空 latent 不是同一个链路，见 [视频生成](/multimodal/video-generation)。文档检索中的直接截图表示也有预算取舍，见 [多模态 RAG](/rag/multimodal-rag)。

### 失败定位：小字错误不一定来自 LLM

先检查原图是否清晰、缩放是否抹掉文字、局部裁剪坐标是否正确；再看视觉编码/合并是否保留信息、模板是否匹配图像；最后比较语言生成与工具抽取。固定失败页集，用全图、局部裁剪、OCR+结构工具和 VLM 对照质量、证据定位与成本。本文未执行这些实验。

## 高频追问

<details>
<summary>连接器输出维度等于 LLM hidden size，为什么仍要训练？</summary>

形状兼容只保证计算可执行，语义与生成条件并未对齐。需要合适的图文/指令监督和参数训练，让语言模型使用视觉证据；还要做错图或去图对照，防止纯文本先验“猜对”。

</details>

<details>
<summary>MLP 保留所有 patch，是否必然比固定 query 更准确？</summary>

不必然。信息保留、数据质量、训练目标和语言侧处理能力共同决定结果。固定 query 可降长度但可能损失细节；MLP 不压长度则更贵。按 OCR、关系、视频等任务单独比较，不能从结构名排名。

</details>
