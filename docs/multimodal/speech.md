# 语音大模型（ASR / TTS / 实时语音对话）

语音系统不只是把文字换成声音。它还涉及音色、停顿、噪声、轮次、并发与打断。先判断业务需要**识别、合成还是对话**，再讨论表示和模型；端到端标签不自动保证更快、更可靠。

## 一、语音的三类核心任务

| 任务 | 输入与输出 | 关键验收 |
| --- | --- | --- |
| ASR | 波形/声学特征 → 文字 | 字词错误、术语、数字、噪声、时间戳 |
| TTS | 文字与可选参考音频 → 波形 | 可懂度、漏字/复读、音色、首包与持续速度 |
| 语音对话 | 用户音频与上下文 → 回复音频/文字 | 任务完成、轮次、打断、副语言与安全 |

说话人分离、情感识别、克隆音色和歌声合成是额外任务，不应默认任何 ASR/TTS 型号都支持。

## 二、语音怎么被模型处理？（核心考点）

波形是采样点序列；例如 16 kHz 表示每秒 16,000 个样本，不是每秒 16,000 个模型 token。常见表示有：

| 表示 | 构造 | 能保留什么、会丢什么 |
| --- | --- | --- |
| Mel 频谱等连续特征 | 分窗、频谱变换与滤波 | 时频信息；并非所有相位/波形细节 |
| 语义 token | 自监督或监督编码器的表示与离散化 | 倾向语言内容，但可能仍含说话人/韵律信息 |
| 声学 codec token | 神经编解码器与量化码本 | 保留可重建声学信息，但通常有损 |

RVQ 用多个码本逐层编码前一层的残差；它不是“保留全部细节、精确还原”的保证。码率、token 帧率、码本数和音质/延迟要一起讨论。语义与声学是设计倾向，不是完全隔离的两个空间。

对音频自回归建模时，codec 帧率和多码本串行/并行方式决定序列开销；连续频谱也可以由非自回归模型生成，语音不必全部变成离散 token。

## 三、代表模型拆解

### Whisper：弱监督的序列到序列识别

[Whisper 报告（2022）](https://arxiv.org/abs/2212.04356) 描述 680,000 小时多语言、多任务监督，使用音频到文本的训练路线。这个数字属于该报告，不是当前所有 Whisper 变体的数据规模。

```text
训练：音频 → 特征/编码器 → 文本解码器 → 转录等任务损失
推理：音频预处理 → 编码 → 文本生成 → 分段/时间戳与后处理
```

规模和多样性支持报告中的泛化结果，但不能保证业务口音、罕见术语、静音或环境噪声都可靠。非语音段的错误转录也应进测试集。

### VALL-E：codec 条件语言建模

[VALL-E（2023）](https://arxiv.org/abs/2301.02111) 使用离散音频 codec，把 TTS 建模为条件语言建模，报告研究了短参考录音的声音适配。原文把它简化成“全部码本逐 token 自回归续写”并不充分，具体声学码本生成应看其架构。

报告里的 3 秒参考音频是实验设置，不是任意噪声、任意说话人都能成功克隆的产品保证。

### CosyVoice 与 F5-TTS：不要合并成一条生成路线

[CosyVoice（2024）](https://arxiv.org/abs/2407.05407) 使用监督语义 token：LLM 做文本到 token，再用条件 Flow Matching 做 token 到语音合成。它有自回归与非自回归模块的分工。

[F5-TTS（2024）](https://arxiv.org/abs/2410.06885) 则描述基于 Flow Matching/DiT 的完全非自回归 TTS。两者都涉及流匹配，但不能据此写成“同一种架构、统一情感能力”。采样次数、时长估计、声码器和流式支持应逐版本核对。

## 四、级联 vs 端到端语音对话

```text
级联：音频 → ASR → 文本 → LLM → 文本 → TTS → 音频
端到端示例：输入音频流 + 文本/音频状态 → 联合模型 → 输出音频流
```

| 维度 | 级联 | 联合/端到端 |
| --- | --- | --- |
| 调试 | 可单独检查转录、回复和合成 | 需要跨流对齐与内部/外部观测 |
| 副语言 | 只传转录文本会丢信息；也可增加辅助信号 | 有机会保留语气/非语音，但非保证 |
| 延迟 | 可以分段流式与重叠，不必完全串行 | 可联合生成，但仍受缓冲、计算、网络限制 |
| 可控性 | 组件替换、规则与审计方便 | 文本侧可控性和音频侧行为需分别验证 |

[Moshi（2024）](https://arxiv.org/abs/2410.00037) 是全双工语音文本联合建模的公开例子，处理用户和系统语音流，并结合文本生成。它不是“所有音频与文本只能塞到一个扁平自回归序列”的证明。

对文本知识的保留、音频任务适配和生成延迟存在训练取舍；不能把“纯音频一定变笨”当定律。比较应控制任务、文本/音频训练配比、模型容量与输出预算。

## 五、实时语音的工程挑战

**首包延迟要定义起止点。** 用户停止说话到第一段可播放音频，与开始录音到完整答复是不同指标。保守串行预算可拆为：

$$T_{first}=T_{endpoint}+T_{ASR}+T_{LLM}+T_{TTS}+T_{transport}.$$

构造例：终点检测 120 ms、转录收尾 80 ms、首文本 200 ms、首音频 150 ms、传输/缓冲 50 ms，合计 600 ms；这不是实测或人类对话阈值。流式重叠后应测关键路径，而不是把每段完整耗时机械相加。

- **VAD/终点检测**：停顿不一定是说完；噪声、咳嗽与短确认词会误判。
- **打断**：不仅停止生成，还要取消待发送音频、清播放缓冲，避免已经说出/未说出的内容在上下文混淆。
- **全双工**：同时听说需要回声处理、轮次策略和流状态；支持流式不等于支持全双工。
- **流式合成**：分块影响韵律与边界衔接，过小块可能损失上下文，过大块增加等待。

成本需包括音频编码、生成 token/采样次数、声码器、缓存、网络与并发。TTS 实时因子 $RTF=\text{计算耗时}/\text{音频时长}$，小于 1 只说明平均生成速度快于播放，不保证首包延迟低。

## 六、安全与伦理

声音适配可能被用于冒充。应以授权、最小留存、用途限制和人工/业务身份验证为边界，不用声纹相似度直接证明身份。水印与检测是辅助措施，不是防伪保证；这里不评价未经核查的具体法律合规要求。

测试还应覆盖误唤醒、环境泄露、静音幻觉、危险指令和未授权克隆。系统需要能取消生成、删除留存并回溯错误，见 [安全治理](/advanced/governance)。

## 高频追问

<details>
<summary>端到端模型为什么不一定比级联快？</summary>

比较要固定终点定义、首包、采样与网络。级联可以流式重叠；联合模型也可能等待长缓冲或生成多级 codec。除首包外还要测连续播放、p95、打断响应和真实任务成功率。

</details>

<details>
<summary>语音模型“字都对但意思错”如何排查？</summary>

保留音频、转录和回复的时间对齐，检查否定、停顿、强调、说话人和上下文是否在文本中丢失；再定位 LLM 推理或合成重音错误。采用音频与文本对照样本，不只算整体 WER。

</details>
